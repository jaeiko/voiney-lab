## 분석 0 — STT 키워드 힌트 현황

### 0-1. xAI STT 호출부와 전송 파라미터

**① 사실**

Single call site: `src/voice_workflow_agent/server.py:1219` `transcribe()`.
It builds its body in `_stt_multipart()` (`server.py:1143`) and posts to
`api_url("stt")` → `https://api.x.ai/v1/stt` (`api_url`, `server.py:1043`;
base overridable via `XAI_BASE_URL`), `timeout=120`,
`Authorization: Bearer $XAI_API_KEY`.

The multipart body is emitted in this exact order (`server.py:1164-1171`):

| # | field | value | bound |
|---|---|---|---|
| 1 | `format` | `"true"` | always sent |
| 2 | `language` | `ko` \| `en` \| `vi` | omitted when `None`; any other value raises |
| 3 | `vad_threshold` | float `%g` | `0.0–1.0`, default `0.5` |
| 4 | `filler_words` | `"true"`/`"false"` | default `false` |
| 5 | `keyterm` | repeated, one part per term | each 1–50 chars after strip, de-duplicated, **max 100** |
| 6 | `file` | `("utterance.wav", wav, "audio/wav")` | last, per the documented xAI order |

Response fields read back: `text`, `duration`, `language`,
`words` (capped at 500, keys narrowed to `word/start/end/speaker`).
`confidence` and `no_speech_probability` are consumed by
`transcription_quality_issue()` (`language.py:396`) but are not visible in the
parse above — they are `Transcription` fields populated elsewhere.

**② 판정** The request contract is fully server-owned, ordered, and bounded.
Nothing client-supplied reaches it.

**③ 확신도** 높음.

### 0-2. keyterm / keyterms / language / language_hint

**① 사실**

- `keyterm` — **사용 중.** Repeated multipart field, sourced from
  `CuratedProtocolSession.stt_keyterms()` (`curated_protocol.py:4673`) via
  `cascade_transcription_context()` (`server.py:5124`).
- `language` — **사용 중.** Resolved from
  `session.accepted_input_language`; `InputLanguagePreference.AUTO` sends
  nothing at all (`server.py:5151-5155`).
- `keyterms` (plural field name) — not sent to the provider. It is the internal
  tuple name only; the wire field is singular and repeated.
- `language_hint` — **존재하지 않음.** Zero occurrences in `src/`.

**② 판정** Keyterm biasing is already implemented and already per-session. The
missing capability is not "keyterms" but "keyterms that change as the step
changes" — see 0-5.

**③ 확신도** 높음.

### 0-3. 배치 vs 실시간 스트리밍

**① 사실** `transcribe()` uses `requests.post` — a synchronous, whole-utterance
HTTP POST of one WAV. There is no provider-side WebSocket anywhere in `src/`:
the only WebSocket is `@app.websocket("/ws")` (`server.py:8338`), which is
browser↔server. `grep` for `session.update`, `ws_connect`, `realtime` in `src/`
returns nothing outside that browser socket.

The utterance is cut by local endpointing first (`FrameBuffer` + `webrtcvad`),
then posted once. `.agent/architecture.md` and `AGENTS.md` rule 8 both state the
product is Cascade-only, with no Native/Realtime transport — this matches.

**② 판정 배치(/v1/stt)다.** Not streaming.

**③ 확신도** 높음.

### 0-4. "keyterm echo" 로직

**① 사실** `_is_keyterm_echo()` (`language.py:293`), reached from
`classify_input_event()` (`language.py:371`); a positive result returns
`InputEventDecision(False, "keyterm_echo")` — the turn is **rejected before a
user Turn is committed**.

What it defends against, in the module's own words: an STT model that
"regurgitate[s] the prompt / keyterm catalog" instead of transcribing. Because
the request injects up to 100 biasing terms, a low-signal utterance can come
back as a concatenation of those very terms. Three independent triggers
(`language.py:351-359`):

1. ≥4 distinct keyterm phrases with high coverage — an obvious vocabulary dump;
2. ≥3 enumerated keyterm commands with list punctuation;
3. coverage ≥0.85 with no natural syntax at length ≥4 tokens.

The term pool it matches against is the injected `keyterms` **plus**
`_CANONICAL_COMMAND_TERMS`.

**② 판정** This is the direct cost of keyterm injection, not an unrelated
filter. Any change that enlarges or churns the keyterm list changes this
gate's false-positive surface — a real user utterance made mostly of reagent
names can be rejected. That coupling must be held in view before 0-5 is acted
on.

**③ 확신도** 높음.

### 0-5. 단계마다 keyterms 를 갱신할 구조

**① 사실** The question presupposes a realtime session; 0-3 establishes there
is none, so there is no `session.update` to carry an update. The relevant fact
is different and better: **keyterms are already rebuilt on every turn.**

`cascade_transcription_context(session, audio_origin=...)` is called per
utterance and calls `stt_keyterms()` afresh each time (`server.py:5137-5139`).
`stt_keyterms()` already reads `self.current_index` and appends the current
step's label tokens (`curated_protocol.py:4693-4697`):
`f"{lbl}단계"`, `f"{lbl} 단계"`, `f"현재 {lbl}단계"`, `f"이번 {lbl}단계"`.

So per-step variation exists — but it is **only the step number**. The
scientific vocabulary in the same function is one fixed 20-item tuple
(`curated_protocol.py:4680-4690`) that does not consult the step, the protocol,
or the fixture at all:

```
AMBIC, ammonium bicarbonate, HPLC water, acetonitrile, Solution A, Solution B,
DTT, iodoacetamide, trypsin, formic acid, LC-MS, SDS-PAGE, gel plug,
stained protein band, Thermomixer, rpm, incubation, keratin, contamination, Evotip
```

Every one of those is from the in-gel digestion document (see 분석 3).

**② 판정** Nothing needs to be built to make keyterms per-step. One function
needs to stop returning a literal. The change points, in order:

1. `curated_protocol.py:4673` `stt_keyterms()` — replace the `scientific`
   literal with terms derived from the fixture. 0-6 shows the derivation
   already exists.
2. Decide the window. `stt_keyterms()` currently has protocol-wide scope
   ("protocol-wide technical domain terms" per its own docstring), while
   `_entity_inventory()` (0-6) uses a current±1 step window. These two must not
   silently disagree about what "the current step's vocabulary" means.
3. Re-check the 100-term cap and the 50-char-per-term cap in
   `_stt_multipart()` (`server.py:1159-1162`) against a protocol with more
   distinct reagents than in-gel's 20.
4. Re-check `_is_keyterm_echo()` (0-4): a step-scoped list is shorter, which
   changes coverage ratios and therefore the rejection threshold behaviour.
5. `include_control_terms=True` adds 9 Korean control phrases
   (`curated_protocol.py:4699-4703`). Those are protocol-independent and should
   stay as they are.

**③ 확신도** 높음 for 1–3 and 5; 중간 for 4 (the direction of the threshold
shift is clear, the magnitude is not measured).

### 0-6. 현재 단계의 시약·장비 이름을 얻는 기존 함수

**① 사실** Yes — `CuratedProtocolSession._entity_inventory()`
(`curated_protocol.py:4612`). It:

- takes the step window `{current-1, current, current+1}`, clamped to range;
- concatenates `self.fixture.facts_for_step(index)` text, casefolded;
- tests membership of an alias map and returns the entities actually present.

So the mechanism "read the active step's own text, return the domain terms in
it" is built, tested, and in production use. Its **alias map is in-gel-specific**
(`ambic`, `solution a`, `gel plug`, `trypsin`, …), so on a different protocol it
returns entities only where the names coincide.

Structured alternatives that are protocol-derived rather than literal:
`fixture.draft.protocol.materials` (`Material.name_source_text`) and
`.equipment` (`Equipment.name_source_text`) — both populated from the analysis
of whatever document was approved, both already required non-empty by
`load_curated_protocol_fixture` (`curated_protocol.py:965-972`).

**② 판정** The step→vocabulary function exists. The gap is that the production
one is keyed by a hardcoded alias table rather than by
`protocol.materials` / `protocol.equipment`, which are the fields that already
carry the right answer for any document.

**③ 확신도** 높음.

**③ 확신도** 높음.

### 1-2. `register()` 의 application/pdf 제약과 해제 지점

**① 사실** The constraint is not one check. It is five, at four layers:

1. **`protocol_catalog.py:1931`** —
   `if media_type.casefold().split(";",1)[0].strip() != PDF_MEDIA_TYPE: raise ProtocolRegistrationError`.
2. **`protocol_catalog.py:1935`** — `extract_protocol_pdf(source)` immediately
   after; the function's entire contract is a local PDF file.
3. **`experiment_protocol.py:658` `_validate_pdf()`** — raises unless
   `pdf.media_type == PDF_MEDIA_TYPE`, `page_count > 0`,
   `len(pdf.pages) == page_count`, and page numbers are exactly `1..page_count`.
4. **`experiment_protocol.py:696` `_validate_evidence()`** — for **every**
   evidence record in the protocol: `source_page_number` must be within
   `pdf.page_count`, and `source_excerpt` must satisfy
   `excerpt in pdf.pages[n-1].text` — a verbatim substring test against
   extracted page text.
5. **`experiment_protocol_store.py:91`** — the SQL `CHECK` above.

And the type system carries it: `ProtocolMetadata.pdf: ProtocolPdfExtraction`
(`experiment_protocol.py:251`) is a **required, non-defaulted** field. There is
no `ExperimentProtocol` without a PDF extraction.

Change points, file · function:

| 순서 | 위치 | 성격 |
|---|---|---|
| 1 | `protocol_catalog.py:1931` `ProtocolCatalog.register` | 얕음 — media type 분기 |
| 2 | `protocol_catalog.py:1935` `register` → `extract_protocol_pdf` | 중간 — 소스별 추출 어댑터 필요 |
| 3 | `experiment_protocol.py:251` `ProtocolMetadata.pdf` | **깊음** — 필수 필드의 타입을 바꾸는 일 |
| 4 | `experiment_protocol.py:658` `_validate_pdf` | 깊음 — page/`media_type` 불변식 |
| 5 | `experiment_protocol.py:696` `_validate_evidence` | **가장 깊음** — 아래 참조 |
| 6 | `experiment_protocol_store.py:91` `pdf_objects.media_type CHECK` | 스키마 마이그레이션 |
| 7 | `experiment_protocol_store.py:88` `pdf_objects` / `ProtocolFileStore` | 중간 — 비-PDF 바이트 저장 |
| 8 | `experiment_protocol_analysis.py:230` `ANALYSIS_RESPONSE_SCHEMA` | 파생 — 3·5가 바뀌면 스키마 해시가 바뀜 |

Item 5 is the load-bearing one, and it is not an artefact. `SourceEvidence`
is `(source_page_number: int, source_excerpt: str)` and the validator proves
the excerpt is verbatim on that page. That is the mechanism by which
`AGENTS.md` rule 1 ("never invent … quantities, units, timers …") is
*enforced* rather than merely asserted. A non-paginated source has no page
number, so admitting one means either inventing a page coordinate or
redesigning what "evidence" means.

**② 판정** "PDF 만 받는 제약"은 한 줄의 방어가 아니라 증거 모델 그 자체다.
Removing the `register()` check alone produces a system that fails three layers
later with a validation error — not a system that accepts markdown. A genuine
change requires a paginationless evidence coordinate (e.g. a stable segment /
offset anchor) defined and validated with the same verbatim rigour, which is a
domain-model change, not a media-type change.

**③ 확신도** 높음 for the enumeration; 중간 for the claim that no cheaper route
exists — I traced the type and validation graph but did not attempt a design.

### 1-3. 커넥터 데이터가 `CuratedProtocolFixture` 가 되려면

**① 사실** `load_executable_fixture()` (`protocol_catalog.py:3585`) constructs
a fixture from: the approved `ProtocolRevisionRecord`, the stored analysis, a
re-read of the source PDF, and `unaccounted_segments_by_page()`. Every
ingredient traces to a registered PDF.

Missing for a connector snapshot, in dependency order:

1. **Evidence coordinates.** 1-2 item 5. Nothing else can proceed without it.
2. **A registration identity.** `ProtocolCatalog.register` derives
   `protocol_id` from the PDF SHA-256 (`_protocol_id(extraction.sha256)`) and
   deduplicates on `find_protocol_revision_by_checksum`. A snapshot has
   `source_hash` (canonical-JSON SHA-256, `protocol_sources.py:134`) — a
   usable identity, but it lives in the other database (1-1).
3. **A structured analysis.** `load_executable_fixture` requires
   `self._latest_analysis(revision)` to be non-`None`. protocols.io steps are
   free text; producing an `ExperimentProtocol` from them means running the
   analysis path, which currently takes `ProtocolPdfExtraction` as input.
4. **An approval.** `entry.available_for_execution` must be true — i.e. an
   `ApprovalPolicy` decision or a recorded development activation. The
   workspace stack's own reviewer decision
   (`/api/workspace/reviewer/revisions/{id}/decision`) is a **different**
   approval subsystem and does not set this flag.
5. **Readiness.** `ReadinessAssessment` must not carry
   `NO_EXECUTABLE_STEPS`, and blocking constructs must be resolved.
6. **Page-coverage records.** `unaccounted_segments_by_page(extraction,
   analysis.page_coverage, …)` feeds the unread-page disclosure. A
   paginationless source has no page coverage; the disclosure's meaning would
   have to be redefined or explicitly declared inapplicable.

**② 판정** 여섯 가지 중 실질적 선행 조건은 (1)이고, 나머지는 (1)이 정해진 뒤에야
설계할 수 있다. 주의: `CLAUDE.md` 의 server-owned workflow authority 규칙과
`AGENTS.md` 2–3 은 두 번째 승인 하위 시스템을 금지하므로, (4)는 워크스페이스
승인을 카탈로그 승인으로 "연결"하는 식이 아니라 하나의 권위로 수렴시키는
설계여야 한다.

**③ 확신도** 높음 for 1–5; 중간 for 6 (I read the call but not the full
coverage semantics).

필드 모두 생성 자체가 불가능하다.

**③ 확신도** 도메인 모델 쪽 판정은 **높음**. protocols.io 가 실제로 무엇을

### 4-2. `narrate` / `listen` / `require_ppe` / `photo_mode` 추가 시 영향

**① 사실 — 결정적인 발견** The provider response schema is **generated from the
dataclass fields**, not written by hand:

```
# experiment_protocol_analysis.py:181-201
for field in record_fields:
    properties[field.name] = self.schema_for(hints[field.name])
    if field.default is MISSING and field.default_factory is MISSING:
        required.append(field.name)
```

Consequences, traced layer by layer:

| 계층 | 영향 | 상세 |
|---|---|---|
| **모델 요청** | **필드가 자동으로 프로바이더 스키마에 들어간다** | `ANALYSIS_RESPONSE_SCHEMA` (`:230`) is built from `ExperimentProtocol` by reflection, sent with `"strict": True` (`:520`). Adding four fields means **asking a model to produce them.** |
| **스키마 해시** | **깨진다** | `_CANONICAL_SCHEMA_SHA256 = "33ca2886…"` (`curated_protocol.py:57`). `load_curated_protocol_fixture` (`:892-899`) recomputes the schema hash and rejects a mismatch, *and* cross-checks `provenance["canonical_schema_sha256"]`. Both the constant and `candidate_a_curated_analysis.provenance.json` must be regenerated. |
| **저장(쓰기)** | 자동 | `_encode` walks `fields(value)` and the allowlist is by **class name** (`experiment_protocol_store.py:334`), so new fields serialise with no change. |
| **저장(읽기)** | **안전 — 단, 기본값이 있을 때만** | `_decode_domain` (`:483-505`) permits absent fields and fills defaults, with an in-code comment explaining that requiring an exact match "made every stored analysis unreadable the moment a field was added". A field **without** a default still raises. |
| **검토 화면** | 수동 | `protocol_catalog.py` review projection + `static/index.html` `#protocol-review-content` / `renderProtocolBlockers` (`:1758`). |
| **실행 경로** | 수동 | `CuratedProtocolSession` — whichever of narrate/listen/photo_mode actually changes turn behaviour. |
| **보고/안전 투영** | 수동 | `report_projection.py:79` (`ProtocolSourceStep | Any`), `safety_pack.py:142`, `:230`. |
| **테스트** | 최소 1개 직접 | `tests/test_stored_payloads_still_load.py` reads real on-disk stores; its docstring records that exactly this class of change once broke decoding while 1,145 tests missed it. |

**② 판정 — 이 네 필드는 `ProtocolSourceStep` 에 넣으면 안 된다.**

Not a style preference; it follows from the first row. `ProtocolSourceStep` is
a **source-derived** record — every existing field is either text lifted from
the document or evidence pointing at it. `narrate`, `listen`, `require_ppe`,
`photo_mode` are **operator/reviewer policy**: the document does not state
them. Because the schema is generated by reflection, adding them to this
dataclass automatically instructs the analysis model to emit them — i.e. asks
a model to invent PPE requirements. That is precisely `AGENTS.md` rule 1, and
`CLAUDE.md`'s "Model/voice output never … converts an observation into an
instruction."

The two escape hatches that exist today, both already reviewer-owned and
append-only:

- `workspace_store.py:665` `protocol_adaptation_revisions(… changes_json …)`
  with `no_update` / `no_delete` triggers, surfaced as `LabAdaptationRevision`
  (`:187`) — a lab-adaptation record keyed to a base revision;
- the `findings/*` routes (`server.py:4022`, `:4054`, `:4091`, `:4123`), which
  already record per-construct reviewer decisions as protocol events.

Either keeps the policy separate from the source record, out of the provider
schema, and out of `_CANONICAL_SCHEMA_SHA256`.

**③ 확신도** 높음 for every row in the table (each read directly). 중간 for the
recommendation, which is a design judgement built on those facts.

### 4-3. 검토자 화면의 단계별 설정 구조

**① 사실**

- **Per-revision**, yes: `#reviewer-workspace` (`index.html:305-414`) with
  `stageReviewerDecision` → `submitReviewerDecision`
  (`index.html:804-805`) → `POST /api/workspace/reviewer/revisions/{id}/decision`.

### 7-1. 경로와 변환 지점

**① 사실**

```
getUserMedia({channelCount:1, echoCancellation/noiseSuppression/autoGainControl})
  → new AudioContext()              ← 샘플레이트 지정 없음 (index.html:1586)
  → audioWorklet /mic-capture-worklet.js
  → port.onmessage: Float32Array
  → resamplePcm16(f, micContext.sampleRate, 16000)   ← ★유일한 변환 지점★ (index.html:1603)
  → socket.send(Int16Array.buffer)                    (WebSocket /ws)
  → FrameBuffer.push()  → 20 ms · 640 byte 프레임      (audio.py:33)
  → webrtcvad.is_speech(frame, 16000)                 (vad.py:110)
  → clean_path(pcm) → pcm_to_wav(pcm, 16000)          (audio.py:112, :124)
  → POST /v1/stt
```

Resampling happens **once, in the browser**, at `index.html:1571` /
`:1603`. `resamplePcm16` is linear interpolation, the JS twin of
`audio.resample_linear` (`audio.py:64`, whose docstring calls it "suitable for
this teaching demo"). The server performs **no** rate conversion:
`clean_path()` (`audio.py:112`) only validates PCM16 framing.

Return path: TTS requests `{"codec":"pcm","sample_rate":16000}`
(`server.py:1287`); the browser plays via
`playContext.createBuffer(1, len, 16000)` (`:2047`, `:2051`, `:2042`).

**③ 확신도** 높음.

### 7-4. 브라우저가 실제로 내보내는 원본 샘플레이트

**① 사실** `micContext = new AudioContext()` (`index.html:1586`) — **no
`sampleRate` option.** The context therefore runs at the platform default, and
the code reads it back as `micContext.sampleRate` to drive the resampler

`getUserMedia` constraints (`:1581-1584`) request only `channelCount:1` plus

**② 판정** The source rate is **whatever the platform chooses** — commonly
48000 on desktop, but the code neither requests nor records it as a fixed
value. **판정 불가** as to the actual number in any given session: it is
runtime-dependent and I did not run a browser. The `client.audio_ready`
control message does report `playContext.sampleRate` (`:1613`), so the
**playback** rate is observable server-side; the **capture** rate is not
reported.

**③ 확신도** 코드 사실 높음; 구체적 수치 판정 불가.

### 7-5. `.agent/architecture.md` 의 "16 kHz" 는 어디서 오는가

**① 사실** The document says: "AudioWorklet → 16 kHz PCM frames → /ws". That
is accurate as a description of what crosses the socket (7-1).

Tracing the constraint to its origin:

- **VAD 에서 오는가 — 아니오.** 7-3 measures 48000 as valid.
- **프레임 산술에서 오는가 — 아니오, 하지만 결합돼 있다.** `FRAME_BYTES`,
  `SAMPLES_PER_FRAME`, and `endpoint_silence_frames` are all derived from
  `SAMPLE_RATE` and `FRAME_MS`, so they follow the constant rather than pin it.
- **STT 에서 오는가 — 부분적으로.** `pcm_to_wav(pcm, sample_rate=SAMPLE_RATE)`
  (`audio.py:124`) writes a correct WAV header, so the rate is *declared* to
  the provider, not assumed by it. Whether xAI `/v1/stt` accepts a
  48 kHz WAV is **판정 불가** — I have no xAI STT specification in this
  repository and, per `CLAUDE.md`'s No-fake-external-validation rule, I will
  not assert a provider capability I did not observe.
- **TTS 에서 오는가 — 부분적으로, 반대 방향으로.** `synthesize()` **requests**
  `sample_rate:16000` (`server.py:1287`) and the browser hardcodes 16000 in
  three `createBuffer` calls. That is an output-path choice, independent of
  capture.

**② 판정** 16 kHz 는 단일 외부 제약에서 나온 값이 아니라 **`audio.py:10` 의
모듈 상수 하나**에서 나오고, 파이프라인 전체가 그 상수를 따라간다. VAD 가
강제하지 않고, 프레임 산술은 파생일 뿐이며, 특정 제공사 요구인지는 확인할
근거가 이 저장소에 없다. 가장 정확한 설명은 "설계 시 선택된 표준 음성 대역
레이트이며 코드 전체가 그것을 중심으로 정렬되어 있다"이다.
`.agent/architecture.md` 의 기술은 **코드와 일치한다.**

**③ 확신도** 상수 추적 높음; 제공사 요구 여부 **판정 불가**.

## 가장 먼저 손대야 할 것 3가지 (제안 · 미실행)

### 1. `protocol_answer_envelope` 의 무게이트 curated 설명문 (`curated_protocol.py:6488-6630`)

**근거.** 분석 3 항목 #4. It is the only finding in this entire analysis where
the system can **state something untrue about the active protocol**. The text
asserts "Solution A는 25 mM AMBIC 수용액 2 parts와 acetonitrile 1 part를
혼합한…" as the active protocol's content; on any other protocol whose step
text mentions one of these reagents, that is spoken as fact. `AGENTS.md` rule 1
forbids exactly this, and `.agent/product_context.md` principle 3 ("Evidence is
visible") is contradicted by it.

**왜 첫 번째인가.** The fix pattern already exists **twenty lines away in the
same file**: `entity_answers` at `:5402` does
`if not candidate_a: entity_answers = {}`, with a comment giving the reason
("Arbitrary PDFs may share entity names but not context or authority"). One
block was gated and its sibling was not. This is a small, local, precedented
change against a correctness risk — the best ratio in the report.

**확신도.** 중간-높음. The ungated state is verified; the runtime consequence
is inferred from the call graph (`plan.requested_entities` → `_entity_inventory`
→ step text), not observed on a second protocol.

### 2. `stt_keyterms()` 를 픽스처에서 파생시키기 (`curated_protocol.py:4673`)

**근거.** 분석 0-5 · 0-6 · 3 항목 #1 #3. The user's opening question was
whether per-step keyterm updating needs building. It does not: the context is
already rebuilt every turn and already varies the step label. What is frozen is
one 20-item literal of in-gel reagents, sent for **every protocol**.
`_entity_inventory()` (`:4612`) already demonstrates the step→vocabulary
derivation, and `protocol.materials` / `protocol.equipment` already carry the
document-derived names for any approved protocol.

**왜 두 번째인가.** Highest capability gain per line changed, and it is the
question actually asked. But it must follow #1, because it touches
`_is_keyterm_echo()`'s false-positive surface (분석 0-4) — changing recognition
behaviour while a known false-statement path is still open makes attribution of
any regression harder.

**주의.** `_scientific_entity_inventory()` (`:2219`) falls back to the in-gel
defaults on an **empty** input. Deriving keyterms without fixing that fallback
would leave the literal reachable by a different route.

**확신도.** 높음 on the mechanism; 중간 on the echo-gate side effect's
magnitude.

### 3. 라이선스 PDF 없이 무엇이 지켜지는지 확정하기 (`tests/conftest.py:21-35`)

**근거.** 분석 8-1 · 9-2. Fourteen modules — including
`test_protocol_catalog.py`, which holds the only active defence of the
PDF-only premise (9-1), and `test_curated_protocol_cascade.py`, the largest
test module at 4,624 lines — are skipped whenever
`data/runtime/candidate-a-source/in-gel-digestion.pdf` is absent. The baseline
of **1521 passed, 0 skipped** is only reproducible on a machine that has the
uncommitted, externally licensed file.

**왜 세 번째인가.** Not a defect — `conftest.py`'s docstring is explicit and
honest, and the decision to skip rather than fake is the right one under
`AGENTS.md`. But it is the **measurement precondition** for items 1 and 2:
both touch `curated_protocol.py`, whose test lives in the skip list. Changing
it in an environment without the PDF produces a green run that proves nothing.

**구체적 행동 (실행하지 않음).** Record, in the verification section that
`README.md` owns, the two distinct baselines — with and without the licensed
PDF — so a contributor can tell which one their green run represents. That is
a documentation change, not a test change, and it does not touch the skip
mechanism.

**확신도.** 높음 — conftest list, file presence, and the 0-skip run are all
directly measured.
