# 기밀 모드 설계 — L0부터 L3까지

## 목적과 원칙

연구자가 쓰는 편의 기능과 PI가 허용하는 외부 처리 범위를 분리한다. 연구실 관리자는 아래
등급 중 하나를 배포 정책으로 고르고, 대학원생은 그 범위 안에서 원문을 올린다. 이것은
프로토콜 내용의 승인 절차가 아니다. 분석과 근거 검사가 통과하고 실험자가 시작 버튼을
누르는 기존 실행 규칙은 그대로다.

모든 등급에서 `CuratedProtocolSession`만 워크플로 상태를 바꾼다. 외부 모델이든 로컬
모델이든 답이나 도구 호출을 **제안**할 뿐이며, 신원·리비전·관찰·타이머·확인·안전 검사와
서버의 답변 검사를 우회하지 않는다. 설정하지 않은 역할은 다른 공급자로 자동 전환하지
않고 실패해야 한다.

## 등급

| 등급 | 허용 범위 | 필요한 것 | 현재 코드에서 바꿀 경계 |
|---|---|---|---|
| **L0 공개·시판 원문만** | 외부 공급자를 쓸 수 있지만, 업로드하는 사람이 원문이 공개되었거나 시판 제품에 딸린 프로토콜이라고 확인한 자료만 받는다. | 업로드 화면의 `예·아니요·모름`과 출처 메모, 덧붙이기 전용 기록, 관리자가 켜는 `예` 전용 업로드 정책, 목록·상세·실험 노트 표시 | `protocol_catalog.py`에 출처 확인 사건을 보존하고 `server.py`가 정책을 검사한다. 이 확인은 저작권·공개 여부의 검증이나 PI 승인으로 간주하지 않는다. |
| **L1 원문 내부 처리** | 원문 파일과 원문/단계에서 파생한 글·이미지를 외부 모델에 보내지 않는다. 연구자의 말소리는 아직 외부 STT를 쓸 수 있으므로, 말로 원문 내용을 읽으면 그 발화는 외부로 갈 수 있음을 고지한다. | 기관 내부 또는 로컬 분석·번역 모델, 내부 OCR, 원문 기반 답변·라우터·보고서 역할의 내부 처리, 단계 문장을 내부에서 합성하는 TTS 또는 화면 전용 대안 | `model_providers.py`의 `analysis`·`translation`뿐 아니라 원문 문맥을 받을 수 있는 `router`·`answer`·`supplemental`·`report` 역할에 내부 공급자 어댑터를 둔다. 원문 이미지 OCR도 내부화한다. 외부 TTS에는 원문 기반 문장을 보내지 않는다. |
| **L2 말소리도 내부 처리** | L1에 더해 마이크 음성과 받아쓰기를 연구실 밖으로 보내지 않는다. | GPU 또는 내부 음성 서버의 로컬 STT, 필요하면 내부 TTS, 언어·샘플레이트 계약, 제한 시간·취소·진단 녹음 정책 | `voice_providers.py`에 로컬 STT/TTS 어댑터를 추가한다. `VOINEY_LAB_STT_PROVIDER`·`VOINEY_LAB_TTS_PROVIDER`가 내부 공급자를 명시하며, 실패 때 외부 공급자로 넘어가지 않는다. `server.py`의 기존 음성 턴과 취소 울타리는 유지한다. |
| **L3 완전 내부 배치** | 원문, 말소리, 모델 문맥, 보고서 사실을 포함한 모든 처리를 기관 네트워크 안에서 한다. 인터넷이 끊겨도 정해진 범위가 동작한다. | 내부 모델·STT·TTS·OCR, 모델 파일 저장소와 검증된 업데이트 절차, 내부 신원·저장·백업·삭제, 외부 통신 차단, 운영 모니터링과 용량 계획 | 외부 공급자와 Google 링크 가져오기, 웹 설명·AI 도식·공개 지식 검색을 끄고 네트워크 egress를 배포 계층에서도 막는다. 기존 역할 인터페이스와 한 상태 기계는 유지하며 별도 실행 판정 계층을 만들지 않는다. |

현재 코드는 L0의 질문·덧붙이기 기록·표시와 `VOINEY_LAB_PUBLIC_SOURCE_ONLY` 정책만
구현하며 기본값은 `false`다. L1–L3는 이 문서의 설계일 뿐 실행 가능한 모드가 아니다.
L0도 자기 신고의 입력 범위를 좁힐 뿐, 외부 공급자가 받는 데이터의 보관·학습 조건을
바꾸지 않는다.

L1에서 “분석·번역만 로컬”로 바꾸고 라우터, 답변, 보고서, OCR 또는 단계 TTS를 외부에
남기면 원문에서 파생한 내용이 여전히 밖으로 나갈 수 있으므로 L1이라고 표시하면 안 된다.
L2도 로컬 STT 하나만으로 충분하지 않고 L1 경계가 먼저 충족되어야 한다. L3의 외부 통신
차단은 애플리케이션 설정과 기관 방화벽 양쪽에서 확인한다.

## 구현 경계

1. **공급자 역할은 그대로 둔다.** `model_providers.py`와 `voice_providers.py`의 기존 역할별
   설정·제한 시간·오류 계약에 `internal` 또는 구체적인 로컬 공급자를 추가한다. 하나의
   “기밀 모드 모델”이 라우팅과 상태 변경을 함께 맡게 하지 않는다.
2. **입력에서 등급을 검사한다.** L0는 파일 bytes나 링크를 가져오기 전에 출처 확인을
   검증한다. L1 이상은 시작 점검에서 모든 활성 역할의 공급자와 기능 플래그를 검사하고,
   한 역할이라도 경계 밖이면 준비되지 않은 상태로 닫는다.
3. **등급을 표시하되 증명으로 부르지 않는다.** 화면과 보고서는 사용자가 남긴 출처 상태와
   메모, 배포가 선언한 처리 등급을 구분한다. `예`는 라이선스 검증 결과가 아니다.
4. **기록·삭제 계약을 유지한다.** 로컬 모델을 도입해도 원문·분석·실험 장부는 기존
   `data/runtime/` 저장소와 `scripts/pilot_data_delete.py` 범위에 둔다. 모델 추론과 원음은
   로그에 넣지 않으며 진단 녹음은 별도 동의 없이 켜지 않는다.

## 품질·지연·비용 위험

| 등급 | 품질 위험 | 지연 위험 | 비용·운영 위험 |
|---|---|---|---|
| L0 | 출처 확인이 자기 신고라 잘못 고를 수 있다. 모델 품질은 현재 공급자와 설정에 의존한다. | 외부 네트워크와 공급자 제한의 영향을 받는다. | 호출 비용과 공급자 약관 변경을 계속 확인해야 한다. |
| L1 | 로컬 LLM/OCR이 혼합 언어 실험 용어, 표, 근거 인용을 덜 정확히 처리할 수 있다. | 긴 PDF 분석과 번역이 보유 GPU에서 길어질 수 있다. | GPU, 모델 저장, 업데이트와 장애 대응 인력이 필요하다. |
| L2 | 로컬 STT가 소음, 마스크, 한·영 혼용, 제품명과 수치·단위를 잘못 받아쓸 수 있다. | 첫 음성 응답과 긴 발화 처리 시간이 늘 수 있다. | 음성 모델용 GPU 메모리와 동시 사용자 용량이 추가로 필요하다. |
| L3 | 외부 지식·업데이트가 차단되어 모델과 용어집이 뒤처질 수 있다. | 모든 역할이 한 내부 용량을 다투면 대기열이 길어진다. | 설치·패치·백업·감사·모델 공급망을 기관이 전부 운영한다. |

바이오, 화학, 배터리, 소재 분야는 공개 관행, 특허 시점, 공정 노하우와 안전 문서 구성이
달라 기밀 민감도와 받아들일 등급이 다를 수 있다. 이는 아직 측정하지 않은 **가설**이며,
분야별 PI 인터뷰와 실제 자료 분류로 확인해야 한다.

## 평가 계획

운영 의존성을 바꾸기 전에 GPU에서 후보를 오프라인·가짜 전송 환경으로 비교한다. 사적 원문은
평가 자료로 자동 재사용하지 않고, 공개·허가된 자료와 사람이 만든 정답 세트를 사용한다.

- **로컬 STT**: 바이오·화학·배터리·소재의 한·영 혼용 실험 용어, 제품명, 수치·단위,
  소음 조건을 포함한다. 전체 받아쓰기 오류뿐 아니라 핵심 용어 인식, 누락·치환, 첫 결과와
  전체 처리 지연을 측정한다.
- **로컬 LLM/OCR**: 원문 근거가 있는 분석·번역과 표/스캔 입력을 평가한다. 근거 없는 값,
  원문 문자열 훼손, 누락, 검토 카드 수와 처리 지연을 현재 계약과 같은 검사로 센다.
- **턴 이해**: 한국어·영어 혼용 명령과 질문에서 의도 분류, 읽기 전용 요청의 무변경,
  완료 확인, 기록 제안을 재생한다. 제안 수와 서버가 거부한 이유를 세고, 잘못된 상태 변경이
  실제 장부에 적용되지 않았음을 전후 상태로 확인한다.
- **운영성**: 역할별 p50·p90 지연, 동시 처리량, GPU 메모리, 오류·시간 초과, 예상 장비비와
  운영 시간을 같은 입력 세트에서 잰다. 측정 전에 사람이 허용 기준과 자료 사용 범위를
  확정한다.

후보가 정해진 허용 기준을 충족하고 기존 서버 경계 시험·음성 현장 시험을 통과하기 전에는
운영 공급자나 실행 의존성을 바꾸지 않는다. 가짜 전송 시험은 contract-tested라고만 기록하고,
실제 내부 장비 요청이 성공한 경우에만 그 환경에서 live-tested라고 적는다.
