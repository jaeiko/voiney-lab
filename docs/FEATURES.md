## F1. 계정과 로그인

계정 모드의 API 문서(`/docs`, `/redoc`, `/openapi.json`)도 로그인이 필요하다. 상태를 바꾸는 브라우저 요청과 음성 소켓은 다른 Origin을 거부한다. 명시한 앱 Origin은 기존 bearer 경로를 쓰며 다른 Origin의 쿠키가 HTTP 쓰기를 허가하지 않는다.

- **무엇**: `VOINEY_LAB_AUTH_MODE` 가 `dev`(기본)면 로그인 없이 개발 신원 한 사람으로 쓴다. `accounts` 면 모든 `/api` 요청과 `/ws` 가 로그인을 요구하고, 가입은 **초대 링크로만** 된다(한 번, 기본 72시간).
  비밀번호는 scrypt 해시, 세션은 HttpOnly·SameSite=Lax 쿠키(HTTPS 요청이면 Secure), 30일. 로그인 잠금은 "이 이름 + 이 기기"다: 브라우저는 기기 표시 쿠키(`voiney_device`, 무작위, HttpOnly, HTTPS면 Secure, 1년)를 첫 화면의 `/api/auth/session` 에서 받고, 같은 기기에서 한 이름으로 15분 안에 5번 틀리면 그 기기에서만 그 이름이 15분 잠긴다(429). 기기와 상관없이 한 이름이 15분 안에 30번 틀리면 그 이름 전체가 15분 잠긴다. 쿠키 없는 요청은 하나의 "알 수 없는 기기"로 센다. 앱 출처(bearer)는 로그인 본문의 `device` 로 같은 규칙을 따른다. 현재 비밀번호를 확인하는 변경 요청(비밀번호 바꾸기·계정 지우기)에도 같은 제한을 적용한다. 잠금 기록에는 이름과 기기 표시의 요약값만 남는다.
  관리자 계정은 파일럿 지표를 보고, 실험 노트·검토본에 "확인함"을 남기고, 연구실 계정을 끄고 켠다. 계정은 설정 탭 **계정 지우기**에서 비밀번호를 다시 확인하고 스스로 지울 수 있다(마지막 관리자는 안 됨).
  파일럿 실행기는 기본으로 `accounts` 로 연다(`--dev-identity` 를 주면 `dev`).
- **어디**: `accounts.py` (`AUTH_MODES`, `AccountStore.create_invite`, `sign_up`, `LOGIN_FAILURE_LIMIT`, `LOGIN_NAME_FAILURE_LIMIT`, `DEVICE_COOKIE_NAME`, `SESSION_LIFETIME`), `server.py` (`commercial_identity_boundary` 미들웨어, `_ACCOUNT_OPEN_PATHS`, `/api/auth/*` 경로, `_request_device`, `_ensure_device_cookie`, `POST /api/auth/delete-account`, `_account_is_admin`), `identity.py` (`DevIdentityProvider`, OIDC), `scripts/pilot_invite.py`.
- **설정**: `VOINEY_LAB_AUTH_MODE`, `VOINEY_LAB_APP_ORIGINS`(앱 출처에 토큰 로그인), `VOINEY_LAB_WORKSPACE_ENABLED`·`VOINEY_LAB_WORKSPACE_DATA_DIR`(계정은 작업공간이 있어야 한다), OIDC 는 `VOINEY_LAB_OIDC_ISSUER` 등.
- **시험**: `tests/test_lane_on_accounts_store.py`, `tests/test_lane_on_auth_api.py`, `tests/test_lane_fx4_pilot_login.py`, `tests/test_lane_fx5_account_erasure.py`, `tests/test_lane_fx5_delete_account_route.py`, `tests/test_lane_pre_device_lock.py`.
- **한계**: 초대 만들기·계정 목록은 화면이 없고 `scripts/pilot_invite.py` 로만 한다. 비밀번호 찾기(메일)는 없다. 기기 표시는 비밀이 아니어서 쿠키나 앱 저장소를 지우거나 바꾸면 새 기기가 된다. 그래서 이름 전체 잠금(30번)이 남고, 이름을 아는 사람이 기기를 바꿔 가며 30번 틀리면 그 이름은 여전히 15분 잠긴다. 묶은 앱은 저장한 무작위 `device`를 로그인·비밀번호 변경·계정 삭제 본문에 보낸다([F16](#f16-모바일-웹과-스토어-앱)). OIDC 는 가짜 검증기로만 시험했다.

## F2. 프로토콜 들여오기

개발용 고정 프로토콜도 본인 연구실에 연결된 항목만 목록에 나온다. 서버의 기동 준비는 계정 요청 문맥 없이 전체 카탈로그의 준비·개수 확인을 수행한다.

- **무엇**: PDF·Word(.docx)·사진(JPG·PNG·HEIC)과 화면에 붙여 넣은 논문 Methods 문단을 원문으로 받는다. Word·사진·붙여 넣은 UTF-8 글은 서버에서 PDF 로 바꿔 같은 분석·원문 근거 검사·확인 카드 길로 보낸다. 붙여 넣은 글은 빈 글과 제어 문자를 거절하고 원문 체크섬을 보존하며, 보통 과학 낱말을 PDF 줄 사이에서 쪼개지 않는다. 같은 연구실 안에서 같은 파일(SHA-256)은 다시 등록하지 않고, 같은 PDF 를 다시 올리면 그 프로토콜의 검토본을 제안한다. 다른 연구실이 같은 파일을 올리면 별도의 카탈로그 항목으로 등록한다. 원문 바이트는 공유할 수 있지만 분석·검토·소유 범위는 연구실마다 따로 남는다. 스타터 팩 도구도 같은 규칙을 쓴다.
  엑셀(.xlsx)은 원문이 아니라 고른 프로토콜에 붙는 **시약 표**로 저장하고 분석에 쓰지 않는다.
  **공개 Google Drive·Docs·Sheets 링크**도 받는다: 서버가 내려받아 올리기와 같은 길로 넘기고(Docs 는 PDF 로, Sheets 는 있는 프로토콜의 시약 표로), 링크 주소를 장부에 출처로 남긴다. 비공개 파일은 "공유 설정을 바꾸거나 파일을 내려받아 올려 주세요"라는 서버 문장으로 거절한다.
  새 올리기 화면은 파일이나 프로토콜 링크를 받기 전에 **"이 원문은 공개되었거나 시판 제품에 딸린 프로토콜인가요?"**를 `예·아니요·모름`으로 묻고 선택 사항인 출처 메모를 받는다. 답과 메모는 프로토콜 장부의 덧붙이기 사건으로 남으며, 같은 답을 다시 보내면 중복 사건을 만들지 않고 답이 달라지면 앞 기록을 보존한 채 최신 답을 목록·상세·실험 노트에 투영한다. 예전 원문은 `확인 기록 없음`으로 보인다.
  `VOINEY_LAB_PUBLIC_SOURCE_ONLY=true`이면 새 파일·프로토콜 링크는 `예` 답만 허용한다. 누락·`아니요`·`모름`은 파일을 저장하거나 Google에서 가져오기 전에 `public_source_required`로 거절한다. 기본은 `false`이고, 이미 등록된 프로토콜·기존 프로토콜에 붙이는 Sheets 시약 표·실행 가능 판정은 바꾸지 않는다. 이 답은 올린 사람의 자기 신고이며 공개 여부·라이선스·PI 승인 결과가 아니다.
  원문 저장·변환·PDF 추출과 OCR 상태 조회는 작업 스레드에서 실행한다. 업로드가 취소돼도 진행 중인 쓰기·등록이 끝난 뒤 임시 파일을 닫고 정리한다. 등록 뒤 OCR 상태만 읽지 못하면 등록 성공은 유지하고 OCR 상태 조회 실패를 알린다. 목록은 연구실 범위를 먼저 거르고 저장된 원문 메타데이터·분석·원장으로 만들며 PDF를 다시 추출하지 않는다. 예전 업로드의 누락된 메타데이터는 서버 시작 때 한 번 보충한다. 검증된 불변 분석 개정은 원문·개정·레코드 바이트를 기준으로 재사용하고, 바이트가 달라지면 저장소의 검증을 다시 거친다.
  **쪽 수와 쪽 작은 그림**(줄 RX1): 등록 직후(분석 전)에도 `GET …/review-draft/source-pages` 가 쪽 수와 해상도를, `GET …/review-draft/source-pages/{n}/image?size=thumb` 이 그 쪽의 작은 그림(36 dpi, 메모리 캐시 256장)을 준다 — 새 올리기 화면이 분석할 쪽을 고르는 데 쓴다. **이름 바꾸기**(줄 RX1): `POST /api/protocols/{id}/title` `{title}` 은 1–120자 한 줄을 덧붙이기 장부 사건(`protocol_title_renamed`: 새 이름, 전 이름, 누가, 언제)으로 남기고, 그 뒤 목록·상세·확인 화면의 `title` 이 그 이름이다. 원문·메타데이터·분석은 그대로다. 빈 이름·제어 문자·너무 긴 이름은 400 `protocol_title_invalid`.
- **어디**: `server.py` `register_protocol_pdf`, `_source_disclosure_from_values`, `_enforce_public_source_policy`, `attach_protocol_reagent_table`, `import_protocol_link`, `get_protocol_source_pages`, `post_protocol_title`; `experiment_protocol_pdf.py` (`SOURCE_MEDIA_TYPES`, `convert_source_to_pdf`, `methods_text_to_pdf`, `docx_to_pdf`, `image_to_pdf`, `find_office_converter`); `pdf_text_engine.py` `write_text_document`; `protocol_link_import.py` (`parse_google_link`, `fetch_google_link`, `ALLOWED_LINK_HOSTS`, `MAX_REDIRECTS`, `sniff_media_type`, `LINK_IMPORT_MESSAGES`); `protocol_catalog.py` (`ProtocolCatalog.register`, `ProtocolSourceDisclosure`, `record_source_disclosure`, `read_reagent_workbook`, `review_version_suggestion`, `source_page_count`, `rename`); 저장은 `experiment_protocol_files.py`(`objects/sha256/…`)와 `experiment_protocol_store.py`.
- **한도(코드 값)**: 원문 64 MiB, 붙여 넣은 글 256 KiB, 사진 1억 화소, 시약 표 5 MiB·셀 20,000개, Word 변환 120 s. 링크: 호스트 `drive.google.com`·`docs.google.com`·`drive.usercontent.google.com`, 리디렉션 5번, 공인 주소만, 전체 60 s.

## F3. 사진 글자 읽기 (OCR)

- **작업 상태**: 서버 재시작으로 끊긴 OCR은 `protocol_ocr_interrupted` 실패로 기록하며 다시 올리기나 OCR 요청으로 재시도할 수 있다. OCR 작업이 살아 있는 동안 분석 상태도 작업 중임을 알린다. 분석 모델 클라이언트의 설정 오류는 실패로 기록해 대기 상태에 남기지 않는다.
- **무엇**: 글자 층이 없거나 읽을 수 없는 **쪽만** OCR 한다. 올리기 직후 자동으로 OCR → 자동 수락 → 분석까지 이어진다(사람의 승인 단계 없음).
  엔진은 NAVER CLOVA OCR 과 Google Cloud Vision. 둘 다 설정하면 둘 다 읽고, 한글이 30 % 이상인 쪽은 CLOVA 의 글을 쓴다. 숫자 값은 두 엔진이 **같은 자리에서 같게** 읽어야 자동으로 정해지고, 다르게 읽은 값은 그 쪽의 확인 카드가 된다. 숫자가 15 % 이상 다르거나 신뢰도가 0.90 미만인 쪽은 같게 읽은 값도 묻는다.
- **어디**: `experiment_protocol_pdf.page_ocr_reason`(어느 쪽이 OCR 이 필요한지), `server.py` `_automatic_ocr_on_upload`, `_schedule_ocr_then_analysis`; `protocol_ocr.py`(`validate_ocr_result`, 결과는 원본 SHA-256 과 쪽마다 정확히 한 번); `protocol_ocr_providers.py`(`ClovaOcrRecognizer`, `GoogleVisionRecognizer`, `DualEngineOcrProvider`, `select_page_text`, `readings_by_place`); `protocol_catalog.py` `_ocr_page_gate`.

## F4. 분석

- **무엇**: 분석 역할 모델이 단계·양·시간·온도·재료·장비·안전 주의를 구조(JSON)로 뽑는다. 모델의 답은 믿지 않는 초안이고 서버가 구조·근거·도메인을 검사한다.
  분석 지침은 번호 없는 Methods 문단의 실행 지시도 원문 순서대로 한 번씩 제안하고, 번호가 있으면 인쇄된 번호와 순서를 보존하라고 한다. 이것은 모델 초안의 지침이며 누락이 없다는 보증이 아니다.
  - **긴 문서**: 60쪽을 넘거나 출력이 한 번 호출 예산(48,000 토큰)을 넘을 것 같으면 15쪽(겹침 1쪽) 조각으로 나눠 기본 8개씩 동시에 분석하고 합친다(최대 400쪽, 넘으면 호출 전에 거절). 429 가 오면 남은 조각의 동시 수를 절반으로. 다시 시도해도 실패한 조각의 쪽은 "분석 실패 쪽" 확인 항목이 되고, 모든 조각이 실패해야 문서가 실패한다.
  - **자동으로 다시 하기**: 공급자 429·일시적 5xx 는 최대 5번 다시 보낸다. 출력 한도에서 잘린 답과 구조가 깨진 답은 요청마다 한 번 다시 분석한다(잘렸으면 추론 한 단계 아래로). 안전 필터가 막은 답은 바로 한 번 더 보낸다. 근거 검사 실패·시간 초과·설정 없음은 다시 하지 않는다.
  - **문서 일부만 분석**: 올리기(파일·공개 링크)와 "다시 분석"에서 분석할 쪽(처음·끝)을 고를 수 있다. 서버가 그 쪽이 문서에 있는지 확인하고(없으면 422 `analysis_page_range_invalid`), 분석 요청 장부(`protocol_analysis_requested`)·시작·결과 사건에 `page_range` 를 남긴다. 그 쪽만 쪽 번호를 그대로 단 채 모델에 보내고, 쪽 밖을 인용한 항목은 확인 카드가 된다. 속 빈 통과 기준도 그 쪽의 번호 단계로만 센다. 긴 범위는 그 안에서 조각으로 나눈다. 번호 없는 서술 문단을 단계로 받는 규칙(번호 섞임 허용)은 그대로다. 쪽을 고르지 않으면 지금처럼 문서 전체를 분석한다. 상세 화면에 "분석한 쪽 · 2–3쪽 (전체 12쪽)"을 보인다(`review()` 의 `analysis_page_range`).
  - **사람의 "다시 분석"**: 통과한 분석도 새로 만들 수 있다. 새 분석이 통과하기 전에는 지금 분석으로 계속 쓰고, 이미 시작한 실험은 시작한 버전으로 이어 간다. 같은 단추를 연달아 눌러도 한 번만 돈다. 옛 분석기로 만든 분석에는 "분석기 개선 전 분석 · 다시 분석 권장"이 붙는다.
  - **번역**: 분석이 통과하면 그 버전의 문장을 번역 역할 모델로 한국어로 한 번 만들어 둔다(용어집 먼저, 시약·장비 이름은 영어 유지). 기계 검사를 통과한 문장만 보여 주고 아니면 원문을 보여 준다. 문체는 실험실 연구자가 쓰는 말이다: 해요체, 한 문장에 한 동작, 영어로 부르는 시약·장비 이름(acetonitrile, DTT …)은 괄호 한국어 없이 영어 그대로, "귀하"·"~하십시오"·직역투 금지, 숫자·이름은 원문과 글자까지 같게, 단위는 명시한 한국어 대응만 허용(`STYLE_GUIDE`, 번역 지침 판 `STYLE_VERSION` 5 — 프롬프트 이름 `revision_translation_v5`). 판 4는 다섯 가지를 더 지킨다: 영어 낱말에 "해요"를 붙이지 않고("resuspension해요" → "재부유해요"), 한 프로토콜 안에서 같은 동작은 같은 말("세척해요"), 원문 저자의 "we"는 3인칭("이 논문의 저자들은" — "우리"·"저희"가 든 번역은 검사가 거절한다, `first_person`), 원문 끝의 설정 줄("300 rpm, 25°C, 00:10:00")은 한 번만 두고 값을 문장에서 두 번 말하지 않음, 어색하거나 부정확한 말 금지("피펫으로 빨아들여요", "하얗게"). 숫자·단위 검사는 그대로다. 저장하는 번역 행과 용어집은 만든 지침 판을 정체에 담는다(덧붙이기만, 옛 행은 판 0으로 남는다): 생성은 지금 판에 없는 문장만 — 옛 판에만 있거나 옛 판에서 검사에 걸린 문장도 — 다시 만들고, 화면·말은 문장마다 검사를 통과한 가장 새 판의 행을, 없으면 옛 판의 행을, 그것도 없으면 원문을 쓴다(행마다 그 판의 용어집으로 검사). 사람이 확인한 번역은 다시 만들지 않는다. 이미 올린 프로토콜은 `scripts/retranslate_protocols.py --data-dir DIR` 이 호출 없이 다시 만들 문장 수와 호출 수를 보이고, `--run` 이 서버와 같은 생성으로 만든다(`--max-calls` 상한, 키는 셸에서, `.env` 를 읽지 않음). 원문 단계가 "1. Harvest …"처럼 점 붙은 번호로 시작해도 한국어의 "1단계: "를 그 단계의 번호로 본다(그 밖의 숫자는 모두 비교). 어휘와 번역 검사 문장 목록은 원문·분석 내용·개정·용어집을 기준으로 재사용한다. 음성 세션은 첫 어휘 계산과 저장 번역 검사를 작업 스레드에서 준비하고 턴은 준비된 어휘를 읽는다. 열린 세션의 번역 묶음은 순서대로 합치고 준비 중 세션 구성이 바뀌면 그 결과를 버린다.
  - **한국어 먼저**: 말과 화면의 안내는 원문 문장을 옮기는 모든 곳(단계 읽기·다음 단계·미리보기·범위 요약·완료 조건·끝점·조건 질문·주의·목적)에서 그 문장의 검토본이나 저장된 번역을 쓴다. 없으면 그 턴에 번역 역할로 그 문장을 한 번 번역해 같은 검사를 통과할 때만 쓴다(한 턴에 세 문장까지, 문장마다 한 번 — 공급자 실패는 60초 뒤 다시, 한 번에 6초 안; 서버 프로세스 안에 두고 그 실험의 단계 카드에도 붙인다). 그래도 없으면 "이 문장은 아직 번역되지 않았어요. 원문을 화면에 띄울게요."라고 말하고 원문은 화면에만 보인다(화면 위에 "아직 번역되지 않은 문장은 원문 그대로 보여요."). 영어 원문을 소리로 읽는 것은 "원문 그대로 읽어 줘"·"영어로 읽어 줘"라고 할 때뿐이다. 번역이 없는 안전 주의는 "이 안전 주의는 아직 번역되지 않았어요. 화면의 원문을 꼭 확인해 주세요."라고 말한다.
    **화면도 한국어 먼저**: 실험 화면의 지금 단계와 다음 단계 문장에 한국어가 없으면 서버가 같은 길(그 자리 번역, 검사 통과 때만, 프로세스에 한 번)로 뒤에서 번역해 단계 카드를 다시 보낸다(`protocol.fixture.state`, `action: "translation_update"`). 서버는 지금 단계의 `translation_status`와 다음 단계의 `next_step_translation_status`를 각각 `available`·`pending`·`rejected`·`missing` 중 하나로 보낸다. 화면은 만드는 중일 때만 "번역 준비 중", 수량·부정 등 기계 검사가 거절했으면 "번역 검사를 통과하지 못해 원문을 보여 드려요.", 만들 번역도 저장 번역도 없으면 "번역이 없어 원문을 보여 드려요."라고 사실대로 구분한다. 거절 상태도 `translation_update`로 다시 보내므로 준비 중 표시에 머물지 않는다. 기존 `translation_missing`·`next_step_translation_missing`은 원문 표시 여부, `translation_pending`은 실제 생성 중임을 계속 알린다. 답은 말하지 않고 화면에만 보이는 원문 문장(답 상자의 단계 문장 따위)도 한국어로 바꾸거나 그 자리에서 번역하고, 없으면 답에 `translation_missing` 을 싣는다. 상태의 `primary_summary` 는 단계 이름 없이 한국어 본문만 담는다(화면이 이름을 옆에 쓴다).
    **번역 문체**: 흔한 실험 낱말은 한국어(밴드·젤·바이알·튜브·비즈·상층액), 시약·장비 고유 이름과 약어는 영어로 둔다. 같은 프로토콜에서는 피펫·비즈·젤처럼 표기를 통일하고, 사람이 확인한 문장이 다른 표기를 정했다면 새 기계 번역이 그 표기를 따른다. 사람이 확인한 문장과 옛 저장 행은 고치지 않는다. 용어집의 `GC vial`·`Porapak tubes`처럼 묶인 표현도 보통명사는 한국어로 정리해 `GC 바이알`·`Porapak 튜브`로 보낸다. `Band100`·`Gel-100`처럼 숫자가 붙은 식별자와 고유 이름은 보존한다. 용어 검사는 같은 `COMMON_LAB_WORDS` 표로 band(s)↔밴드, gel(s)↔젤, vial(s)↔바이알, tube(s)↔튜브, bead(s)↔비즈, supernatant(s)↔상층액, pipette(s)↔피펫을 대조한다. 영어 이름 옆의 보통명사에도 적용하고, 고유 이름·식별자의 일부는 바꾸지 않는다. 저장 행도 읽을 때 같은 검사로 다시 확인하며 지침 판은 5 그대로다. 숫자·단위·부정·위험 낱말 검사는 유지한다.
    **단위 대조**: 시간은 `min/minute/minutes ↔ 분`, `h/hr/hour/hours ↔ 시간`, `s/sec/second/seconds ↔ 초`, `months ↔ 개월`, `days ↔ 일`, `weeks ↔ 주`, `overnight ↔ 하룻밤`을 허용한다. `parts ↔ 부`, `volumes ↔ 배 부피`, `samples ↔ 시료 N개`도 한국어로 쓴다. 숫자의 소수 자리와 쉼표는 그대로 지키며, 단위를 환산하지 않는다(`1.0 → 1`, `15 min → 900초`는 거절). 분·시간·초 외 SI 단위의 기존 동등 표기는 유지한다.
    **번역 호출 실패**: 묶음 호출은 180초로 제한한다. 재번역 도구는 429·500/502/503·시간 초과(408/504 포함)·연결 오류를 같은 공급자에 최대 두 번 다시 보낸다. Retry-After는 30초 이내일 때 따르고, 없으면 1–2초·2–4초 범위로 기다린다. 30초 넘는 대기 요청·안전 차단·인증/요청/결제 오류는 다시 보내지 않는다. 응답 꼴은 기존 코드 울타리 제거와 값 보존 구조 복구로 읽고, 읽을 수 없는 꼴·빈 응답·시간 초과 묶음은 기존 반분 경로로 보낸다. ID 누락/중복/알 수 없는 ID·빈 번역도 꼴 오류이며, 이런 응답은 영구적인 `missing` 행으로 저장하지 않는다. 성공한 반쪽은 즉시 저장한다. `--max-calls`는 용어집·일시 오류 재시도·분할 전송을 모두 합친 실제 전송 상한이다. SDK·공급자 내부 재시도는 끄고 상한으로 보내지 않은 호출은 실패로 세지 않는다. 결과의 `failed_calls`는 용어집과 회복된 재시도를 포함한 모든 실패 전송이며 `failure_kinds`에 허용한 코드만 센다. 각 비동기 클라이언트는 만든 이벤트 루프 안에서 닫는다. 새 설정은 없다.
    **번역 추론 비교**: `scripts/model_reasoning_eval.py translation-sample/translation`은 사람이 카탈로그 복사본에서 분야·길이가 고른 같은 60문장을 low/medium/high로 재는 도구다. 기본은 0호출 계획이고 호출·예약 비용 상한을 필수로 받는다. 묶음은 현재 용어집·묶음 프롬프트와 검사를, 그 자리는 서버의 현재 프롬프트·6초 제한과 검사를 그대로 쓴다. 결과에는 원문·번역을 넣지 않고 검사율·명시적 문체 금지 꼴의 기계 대리값·응답 꼴·지연·토큰/비용 어림만 둔다. 이 결과는 번역의 자연스러움이나 과학적 정확성에 대한 사람 검토가 아니다. 명령은 `docs/EVALUATION_SIM.md`에 있다.
    **자막은 말한 글**: `reply.complete` 가 말한 글(`speech_text`, 말하지 않은 답은 없음)과 한국어 본문(`primary_text`)을 싣고, 새 화면의 자막과 대화 기록은 말한 글을 보인다(답 상자는 보이는 글). 인사말·타이머 알림·서버 말도 말한 글을 `speech_text` 로 싣는다. 예전에는 자막이 화면 글을 보여 "원문 · English" 아래의 영어가 자막에 나왔다.

## F5. 원문 근거 검사

- **무엇**: 분석이 말한 모든 것(단계 문장·값·안전 주의·재료…)이 원문(또는 받아들인 OCR 글)에 실제로 있는지 서버가 기계적으로 대조한다. 찾지 못한 항목은 문서를 버리지 않고 "확인 필요" 항목이 된다. 원문이 확인하지 못한 메타데이터와 설명은 비운다. 뽑은 단계가 원문 번호 단계의 25 % 미만이면 "속 빈 통과"로 거부한다. 타이머는 그 단계의 원문 범위에 적힌 시간만 인정한다.
  거부된 항목만 그 쪽 글과 함께 한 번 더 물어 원문 그대로의 구간을 받고(분석마다 한 번, 긴 문서는 조각마다), 받은 구간도 같은 검사를 거친다. 이 되묻기는 분석을 "검토 대기"로 저장한 **뒤에** 돈다(한도 300 s, 요약에 "원문 위치를 다시 찾는 중"). 다시 찾은 항목의 카드는 서버가 닫고("원문 위치를 다시 찾아 확인했어요"), 사람이 아무것도 정하지 않은 채 모든 카드가 닫히면 분석은 통과로 저장된다.
  쪽 범위를 고른 분석([F4](#f4-분석))은 근거 검사와 아래 "분석에 없을 수 있는 원문" 찾기도 그 쪽만 본다. 범위 밖의 쪽은 빠진 원문으로 세지 않는다.
  번호 단계와 번호 없는 단계가 섞인 원문은 그대로 받고, 번호 방식이 바뀌는 경계를 확인 카드("이어져요")로 묻는다.
  **분석에 없을 수 있는 원문**: 근거 검사는 "뽑은 것이 원문에 있나"만 보므로, 모델이 아예 뽑지 않은 지시는 따로 찾는다(기준 자료 없이). 쪽마다 분석의 모든 인용(단계·세부 동작·안전 주의·참고·완료 기준·값·재료·장비·제목)이 덮는 글자를 빼고, 머리말·꼬리말·쪽 번호·여백 줄(긴 문서 쪽 끝 판정과 같은 규칙), 표지, 참고문헌 목록, 저작권·라이선스·DOI·목차 줄을 뺀 뒤 남은 줄 중 **실행 지시처럼 보이는 줄**만 모은다: 번호·글머리 뒤에 문장이 오는 줄, 영어 명령형 동사로 시작하는 문장(앞의 "After 10 min," 같은 여는 말 뒤 포함), 한국어 "~한다/~하세요/~할 것" 꼴. 숫자+단위(시간·온도·부피·농도·속도)만 있는 줄과 문장이 아닌 번호 줄(제목·표 행·소속)은 헛경보가 많아 기록만 하고 보이지 않는다. 가까운 줄(사이에 다른 줄 하나까지, 인용된 줄이 끼면 끊음)은 한 곳으로 묶는다. 검토 대기 분석에서는 확인 카드가 되고([F6](#f6-확인-카드)), 다 통과한 분석에서는 시작 전 알림이 된다([F7](#f7-시작-전-확인과-시작)).

## F6. 확인 카드

- **무엇**: 근거 검사가 다 확인하지 못한 분석은 "검토 대기"로 남고 실행되지 않는다. 서버가 물어야 할 항목만 **한 장씩** 카드로 보여 주고, 단추도 서버가 허락한 것만 준다(맞아요 · 직접 고칠게요 · 원문에 없어요 · 다른 줄이에요 · 다시 분석 …). 한 쪽의 OCR 값은 카드 한 장("모두 맞아요")으로 묶는다.
  모든 항목을 정하고 이름을 적어 "검토 완료하고 등록"하면 검토본(v1, v2 …)이 생기고 최신 검토본이 실행된다. 값마다 "원문 · AI 제안 · 검토자 입력"으로 출처를 표시한다.
  **안전 주의 글은 고칠 수 없다**(메모만). 원문에 없는 것만 비울 수 있다. 안전 주의 속 OCR 숫자는 두 엔진의 읽기 중 하나만 고를 수 있고, 어느 읽기도 맞지 않으면 등록을 거부한다. 단계는 비울 수 없다(다시 분석) — 아래 "프로그램에 하는 말" 카드의 **빼 주세요**만 예외다.
  항목이 12개를 넘으면 카드를 만들지 않고 추론 한 단계 위로 한 번 다시 분석하고, 그래도 많으면 안내만 한다(긴 문서는 다시 분석하지 않는다).
  **분석에 없는 원문일 수 있어요**: 검토 대기 분석에는 [F5](#f5-원문-근거-검사)가 찾은 곳마다 카드가 붙는다("2쪽의 이 줄들이 실험할 단계인가요?"). 단추는 **단계가 아니에요**(확인만 하고 단계·값·안전 주의를 쓰지 않는다)와 **다시 분석할게요**(재분석) 둘뿐이고, 그 줄을 단계로 넣는 단추는 없다. 실패한 조각의 쪽과 거부된 인용의 카드가 이미 묻는 줄은 다시 묻지 않는다. 이 카드는 위의 12개 한도를 세지 않으므로 이것 때문에 다시 분석하거나 실패하지 않는다. 대신 이 카드의 수도 같은 한도(`VOINEY_LAB_REVIEW_MAX_ITEMS`)까지다: 곳이 한도보다 많으면 쪽마다 한 장, 쪽이 한도보다 많으면 이어진 쪽 묶음 한도 장으로 묶는다. 다른 카드가 되묻기로 모두 닫히고 이 카드만 남았는데 사람이 아무것도 정하지 않았으면 분석은 통과로 저장되고 이 곳들은 시작 전 알림이 된다. 등록할 때 사람이 답하지 않은 곳만 검토본의 시작 전 알림으로 남는다.
  **프로그램에 하는 말처럼 보이는 문장**: 분석이 단계·세부 동작이나 그 곁의 문장(안전 주의·참고·팁·완료 기준·조건·관찰·시작 전 준비)으로 뽑은 글이 정해진 꼴 — 프로그램을 부르는 말("Note to the AI", "AI assistant:", "if you are an AI", "AI에게"), 앞의 지시를 무시하라는 말("ignore all previous instructions", "앞의 지시를 무시하고"), 모든 단계를 완료로 하라는 말("mark all steps as complete", "모든 단계를 완료로 표시"), 프로그램만 쓰는 말("system prompt") — 을 가지면, 다른 것은 다 통과했어도 분석은 검토 대기가 되고 그 항목마다 카드가 붙는다: "이 문장은 실험 지시가 아니라 프로그램에 하는 말처럼 보여요. 단계에서 뺄까요?" 단추는 **빼 주세요**(검토본에서 그 항목을 뺀다)와 **실험 지시예요**(그대로 둔다, 출처는 "원문") 둘이다. 판단은 낱말 목록과 꼴(`PROGRAM_ADDRESS_SHAPES`)만으로 하고 모델은 읽지 않는다. 안전 주의는 빼지 않는다: "이 안전 주의는 프로그램에 하는 말처럼 보여요. 원문의 안전 주의가 맞나요?" — **맞아요** 또는 **다시 분석할게요**. 이 카드도 12개 한도를 세지 않는다. 원문의 글은 지시로 실행되지 않는다(상태 기계는 원문에서 명령을 받지 않는다); 이 카드는 그 글을 단계로 읽어 주지 않게 하는 것이다.
  **원문 쪽의 줄 상자**(줄 RX1): `GET …/review-draft/source-pages/{n}` 은 줄마다 `box`([x0, y0, x1, y1], PDF 포인트, 글 엔진이 남긴 블록의 상자를 그 블록의 줄 수로 나눈 자리; 블록이 없는 줄은 `null`)와 쪽 그림의 `image_dpi` 를 준다. 새 화면의 확인 화면이 쪽 그림 위에 카드의 줄 띠를 두는 데 쓴다. 기하만 읽고 아무것도 정하지 않는다.

## F7. 시작 전 확인과 시작

- **무엇**: 분석이 통과했고 **시작을 막는 사유**(프로토콜이 맞지 않음, 실행할 단계 없음, OCR 이 안 된 쪽, 안전에 중요한 충돌)가 없으면 시작할 수 있다. 그 밖의 사유는 **시작 전 알림**으로만 보이고, 안내가 아직 다루지 못하는 구조(동시 작업, 되풀이 알림, 재사용 하위 절차)는 그 단계에서 한 번 말하고 원문을 확인하라고 한다(원문 문장은 한국어 먼저, [F4](#f4-분석)). 승인 단계는 없다.
  다 통과한 분석에 [F5](#f5-원문-근거-검사)가 찾은 곳이 있으면 검토 대기로 보내지 **않고** 시작 전 알림 한 줄로 알린다: "분석에 없을 수 있는 원문이 n곳 있어요(2·5쪽). 시작 전에 원문을 확인해 주세요."(사유 코드 `source_text_possibly_missed`, 막지 않음). 곳의 쪽·줄은 분석 통과 장부 기록(`possibly_missed`, 숫자만)에 남고 `GET …/review` 의 `possibly_missed`·`execution_notices` 로 나간다. 검토 대기 분석에서는 같은 곳이 카드라 사람이 답해야 등록된다는 점이 다르다([F6](#f6-확인-카드)).
  시작 마법사는 (로그인) → 내 목소리 → 안내 목소리 → 프로토콜 → **핵심 값 확인**(시간·온도·속도·양 중 2개를 원문 조각 옆 객관식으로, 정답과 보기는 서버가 만든다; 틀리면 확인 카드를 연다) → **안전 주의**(원문과 한국어를 나란히, "읽었어요") → **오늘 원문과 다르게 할 값**(바꿀 값이 없어도 한 번 지난다, 아래) → **이 프로토콜로 시작**. 모든 답은 프로토콜 장부에 남는다.
  **오늘 원문과 다르게 할 값**: 서버가 실행할 분석(또는 검토본)의 단계 문장에서 시간·온도·속도·부피·농도 값을 단계와 함께 나열하고, 사람이 바꿀 값 옆에 새 값을 적는다. `GET …/start-check/changes` 는 값마다 문장 안의 자리(`start`·`end`)와 단계마다 문장·저장된 한국어·값 id(`steps[].text`·`text_ko`·`value_ids`)도 준다(줄 RX1; 새 화면이 단계 문장에 값을 형광으로 표시하는 데 쓴다. 번역은 읽기만 하고 시작하지 않는다). 서버는 단위 종류가 같을 때만 받는다(시간→시간, rpm↔×g·M↔%는 다름; 다르면 "단위 종류가 달라요. 원문 값(15분)과 같은 종류인 초·분·시간 단위로 넣어 주세요."). 안전 주의 글과 경고·한계 문장("Do not exceed …")의 값, 완료 기준은 목록에 없다. 새 값이 원문 값의 절반 미만이거나 2배를 넘으면(같은 종류의 기준 단위로 비교, 0 °C 이하 온도는 언제나) 서버가 받지 않고(422 `run_change_large_unconfirmed`) 화면이 "2단계 시간을 10분에서 30분으로 바꿀까요? 원문 값과 많이 달라요."로 한 번 더 묻는다. **네, 이 값으로 할게요**를 누르면 그 값만 `confirm_large` 로 다시 보내고 장부에 `confirmed_large` 로 남는다. 고른 것은 계정·분석 식별자와 함께 장부(`protocol_run_changes_chosen`)에 남고, **바꿀 값 없이 다음**도 빈 선택으로 남는다.
  **시작은 반드시 이 단계를 지난다**: 시작 요청(`session.start`)이 이 단계에서 받은 선택 id(`run_change_set_id`)를 함께 보내고, 서버는 그 선택만 한 번 적용한다(`protocol_run_changes_applied`, 실험 id). 시작 확인(`VOINEY_LAB_START_CHECK_ENABLED`, 기본 켬)과 카탈로그가 켜져 있으면 선택을 이름 대지 않은 새 실험 시작은 `run_changes_required` 로 거절하고 이 단계로 돌아간다. 다른 계정의 선택·이미 쓴 선택·지금 분석의 값과 맞지 않는 선택은 `run_changes_stale` 로 거절한다. 예전 선택이 시간으로 골라져 조용히 적용되는 길은 없다. 실험 탭의 "바로 시작" 카드도 안전 주의와 이 단계를 지난 뒤에만 바로 시작하고, 아니면 시트를 이 단계에서 연다. 이어하기(복구)는 실험이 가진 값을 그대로 쓴다.
  **지난번처럼·연구실판**: 같은 계정의 같은 프로토콜 지난 실험 기록에 바꾼 값이 있으면 한 번에 다시 채운다. 기록 소유 규칙 그대로 본인 기록만 읽고, 지금 분석의 같은 단계·같은 종류·같은 원문 값일 때만 다시 나온다. 채운 값도 서버가 다시 검사한다. 사람이 바꾼 값이 있는 선택에서 **이 조건을 연구실판으로 저장**을 명시적으로 고르면, 서버가 검사한 조건 묶음을 같은 덧붙이기 사건에 `연구실판 vN`으로 남기고 다음 시작에서 불러올 수 있다. 같은 계정·정확히 같은 원문 리비전과 시작 대상에서만 보이며, 원문·분석·검토본을 바꾸지 않는다. 단계 추가·삭제·순서 변경을 담는 프로토콜 판이 아니다.
  안전 문서: 기관이 승인한 안전 문서 카탈로그(SOP·SDS·장비 설명서)는 선택이다. 없으면 사용 범위 `source_protocol_only` 로 원문 안전 주의만 쓰고, 화면·답·기록이 "기관 안전 문서 없음 · 원문 안전 주의만"이라고 말한다.

## F8. 듣기

- **세션 준비**: 프로토콜 PDF 읽기·실행 개정 선택·안전 문서 조회는 작업 스레드에서 끝낸 뒤 음성 세션을 시작한다. 재연결도 같은 준비 경로를 쓴다.
- **무엇**: 화면이 마이크 소리를 16 kHz PCM 으로 보내고, 서버가 20 ms 마다 WebRTC VAD 로 듣는다. **1초(1000 ms) 조용하면** 그 말을 끝으로 보고 한 번에 글로 옮긴다(15초가 넘으면 자른다). 목소리 기준값을 쓰지 않는 세션에서는 WebRTC가 낮은 팬 소리를 계속 말로 보더라도, 한 턴 안의 최근 1초 중 60% 이상을 말로 본 경우 그 말 프레임의 낮은 쪽 20%보다 6 dB 이상 큰 프레임이 실제로 나온 뒤부터 그 선보다 큰 프레임만 말 끝을 계속 열어 둔다. 그 1초는 **안정된 기계 소리여야 한다**(줄 LIVE3): 말 프레임 크기의 20–80퍼센타일 차가 6 dB 안일 때만(팬·펌프·원심분리기 모사 0.3–5.8 dB, 말은 합성 6.5 dB·사람 녹음 10.5 dB 이상) 바닥을 정한다. 전에는 착용자의 첫 1초 말에서 바닥을 잡아 문장 끝의 작은 말을 침묵으로 세어 잘랐다(녹음 재생에서 문장마다 160–320 ms, 합성 문장은 둘로 나뉨). PCM·1초 기준·15초 상한은 바꾸지 않는다. 답은 문장마다 음성 합성으로 보낸다. 말하는 도중에 끼어들면 안내를 멈춘다. 자기 목소리가 마이크로 되돌아온 것(최근 3초, 12자 이상, 80 % 겹침)은 버린다.
  - **쉼이 있는 한 문장**(2026-10-25, 줄 HEAR 결정 4): 말 끝 뒤 1.5초(`CONTINUATION_JOIN_SECONDS`) 안에 다시 말하면, 앞말의 답이 아직 소리 나지 않았고 그 턴이 아무것도 바꾸지 않았을 때 한 말로 잇는다. 앞말의 턴을 취소하고 그 소리를 뒷말 앞에 붙여 한 번에 글로 옮긴다. 앞말이 덜 끝난 말("…에서", "…하고")이거나 아직 받아 적는 중이면 2초(줄 RA 의 창, 규칙 길에서도)까지 잇는다. 답이 소리 나는 중의 말은 전처럼 끼어들기다. 답을 준비하는 동안 시작한 말은 답이 소리 나기 시작해도 끊지 않고, 앞말이 버려져도(받아 적은 말 없음) 새 턴으로 남긴다.
  - **모든 말을 들어요**(결정 2): 기본은 크기로 거르지 않는다. **옆 사람 말 거르기**(실험자 설정 `speaker_filter`)를 켜고, 설정에서 목소리를 맞춘 지 14일(상수 `VOICE_REFERENCE_MAX_AGE_DAYS`) 안이며, 맞춘 마이크로 실험할 때만 맞춘 목소리보다 많이 작은 말(민감도 높음 9 dB · 보통 12 dB · 낮음 18 dB)을 다른 사람 말로 보고 글로 옮기지 않는다. 그 밖(맞추지 않음·오래됨·마이크 바뀜)은 거르지 않고, 이번 실험이 거르는지와 그 까닭을 화면에 알린다(`speaker.filter`). 거르기가 켜져 있는데 선 바로 아래(6 dB 안)의 말을 연달아 두 번 거르면 선을 "낮음"으로 내리고, 이미 낮음이면 이번 실험 동안 끄고, 그 사실을 말과 화면으로 알린다.
  - **목소리 맞추기**(결정 1): 실험 중에는 하지 않는다. 설정(새 화면은 첫 로그인 안내도)에서 한 문장을 읽으면 화면이 실험 때와 같은 마이크·처리로 녹음해 `POST /api/voice/calibration` 으로 보내고, 서버가 VAD 가 말소리로 본 부분의 가운데 크기만 잰다. 소리는 바로 버리고 글로 옮기지 않으며, 크기·잰 때·마이크의 짧은 id 만 실험자 설정 `voice_reference` 로 남는다(화면이 쓸 수 없다). 실험 중의 "목소리 맞춰 줘"와 화면 요청에는 "실험 중에는 목소리를 맞추지 않아요. 실험이 끝난 뒤 설정에서 맞춰 주세요."라고만 한다. 작업공간 저장은 스키마 12(`speaker_filter`·`voice_reference` 를 받는 CHECK; 줄 HEAR2 결정 6 — 스키마 11 저장소는 측정을 500 으로 거절했다). 실패하면 까닭을 쉬운 말로 보인다: 목소리가 작음(`too_little_voice` → "조용한 곳에서 문장을 끝까지 읽어 주세요"), 녹음이 짧음(`audio_length`), 보내지 못함(`audio_invalid`), 서버 오류(5xx), 연결 없음.
  - **버린 소리는 화면에만 알린다**(결정 3; 2026-10-26 줄 HEAR2 결정 4): 너무 짧음·내 안내의 메아리·받아 적은 말 없음·‘음’ 같은 소리·말이 아닌 소리 표시·용어만 나열·크기로 거름·언어를 알 수 없음·일시정지 중·쓸 수 없게 된 끼어들기 등 어떤 이유로든 소리를 버리면 이유 코드와 크기(dB)·길이(ms)를 기록과 지표(`speech_dropped`)에 남기고(소리·말한 글은 남기지 않는다) `speech.dropped` 사건에 이유를 쉬운 말로(`reason_ko`, 서버의 `DROP_REASON_WORDS_KO` 한 표) 넣는다. 두 화면은 마이크 옆에 "잘 안 들렸어요 · 너무 짧은 소리였어요"처럼 알림과 이유를 몇 초 보인다. **소리로는 말하지 않는다** — 줄 HEAR 의 "30초 안에 두 번이면 한 번 말함"은 주변 소음마다 되풀이돼 없앴다(사람 음성 시험 2).
  - **이어 붙일 때 조용한 가운데 말을 되살린다**(줄 SAFE2, 2026-10-31 실측 뒤): 원심분리기 소음(10 dB)에서 "관찰 기록해 줘: 측정값 100 mL"는 상대 게이트가 문장의 작은 가운데 1초를 침묵으로 세어 둘로 나뉘고, 이어 붙이기가 앞 조각만 앞에 두어 받아쓰기는 162프레임 중 앞 89·뒤 49만 받았다(14자 중 8자 오류, 숫자 틀림; LIVE3 전 코드도 세 조각으로 45프레임을 잃었다). 이제 말 끝은 잘라 낸 프레임 중 **VAD 자신은 말로 본 것**(게이트나 착용자 크기가 뒤집은 것)을 `trailing`으로 들고, 이어 붙일 때 두 조각 사이에 되돌려 놓는다. 조용한 방에서는 잘라 낸 것이 침묵이라 되돌릴 것이 없고 이어 붙인 말은 전과 같다; 말 끝 뒤에 들린 소리(쉼·타자)는 넣지 않으며 꼬리는 길어야 말 끝의 1초다. 같은 소리 재생: 받아쓰기 입력 138 → 188프레임(문장 전체). 듣기 시험대는 같고, 10/31 진단 14건은 이어 붙이기 4·잃은 꼬리 210 그대로, 가장 긴 발화만 262 → 365프레임(말 뒤 타자를 게이트가 뒤집은 클립).
  - **계속되는 충격음에도 말 끝은 1초**(줄 LIVE3, 2026-10-31 사람 시험 뒤): 답을 준비하는 동안(재생 전) 들린 소리는 **말 모양이 보인 뒤에만** 앞말에 이어 붙인다. 타자·피펫·튜브 랙처럼 말처럼 시작하지만 말 모양이 없는 소리는 끼어들기 후보로 끝까지 듣다가 `transient_noise`로 조용히 버리고, 앞말의 턴은 그대로 답한다. 전에는 처리 중의 충격음마다 앞말을 취소하고 그 소리 앞에 다시 붙여 10초 상한까지 사슬이 이어졌다(사람 시험의 약 20초 "요청 이해 중", 10–14초 녹음, 두 번 적힌 문구). 말 모양이 후보의 마지막에서야 보이면 그때 이어 붙인다. 그 세션 녹음 14개 재생: 이어 붙이기 25→4, 가장 긴 발화 8.2→5.2초, 충격음 덩어리 거절 0→12.
  - **짧은 충격음은 말을 다시 열지 않는다**(줄 LISTEN3): 착용자가 말을 마친 뒤 타자·도구·피펫처럼 갑자기 난 짧은 소리가 WebRTC의 재개 수를 채워도, 160--400 ms의 제한된 PCM 창에 말의 주기성과 대역 에너지가 함께 없으면 끝내던 1초를 다시 세지 않는다. 충격음만 뭉친 입력은 STT에 보내지 않고 `transient_noise`("말이 아닌 짧은 소리였어요")로 조용히 버린다. 바로 뒤의 짧고 작은 실제 명령은 WebRTC 네 프레임과 같은 말 모양이 함께 있을 때 살린다. 글·의도·프로토콜 상태를 보지 않는 음향 경계이며 1초 말 끝과 15초 상한은 그대로다.
  - **받아쓰기 공급자가 실패하면**(줄 HEAR2 결정 1·2, 2026-10-26): 요청이 거절·시간 초과·연결 실패하면(`SpeechProviderError` 의 `status`·`code`: 공급자의 코드 `quota_exceeded` 같은 것, 없으면 상태로 `unauthorized`·`rate_limited`·`provider_error`·`provider_refused`, 답이 없으면 `timeout`·`unreachable`) 그 말은 `speech.dropped reason=stt_failed` 로 버리고 코드와 쉬운 말("받아쓰기 서비스가 답하지 않아요 · 받아쓰기 서비스의 한도가 다 됐어요")을 화면에 보이며, 지표 `speech_dropped reason_code=stt_failed`(공급자 코드는 `event_kind` 차원)와 로그 `stt.failed code= status=` 에 코드만 남긴다(공급자 본문은 남기지 않는다). **한 번의 장애에 한 번** "받아쓰기 서비스가 답하지 않아요. 관리자에게 알려 주세요."를 말하고, 공급자가 다시 답하면 다음 장애에 다시 말한다. 답하는 동안의 끼어들기 실패도 같다. 예전에는 턴 오류(역추적)로만 남고 화면은 "듣는 중"으로 돌아갔다(2026-10-26 시험의 44번).
  - **한국어 받아쓰기 힌트**(줄 STT5, 2026-10-29): 일반 턴과 끼어들기는 같은 최대 100개 목록을 쓴다. `다음`·`타이머`·`일시정지`·`다시 시작`·`종료`·`특이사항`·`메모`·`기록해 줘`·`화면 크게`가 먼저, revision의 저장 번역 용어집에서 검사를 통과한 한국어 이름, 기존 단계·제어 말, 원문의 현재 단계 주변 기술용어 순이다. 공통 항목은 50자 미만·5단어 이하이고 중복을 뺀다. 번역 문장이나 새 용어를 만들지 않으며, 힌트는 상태를 바꾸는 근거가 아니다. 턴에서는 세션 준비 때 만든 용어집을 읽을 뿐 다시 계산하지 않는다.
  - **Chirp 3 용어 힌트 복구**(줄 STT4·STT5, 2026-10-28~29): `VOINEY_LAB_GOOGLE_STT_V2_ADAPTATION_ENABLED`는 기본 false라 `google_cloud_v2`의 첫 요청부터 인라인 adaptation을 싣지 않는다. 2026-10-29 같은 한국어 WAV에서 `chirp_3` 인라인 힌트는 `us`·`eu` 모두 404였고 `us` 힌트 없음은 200이었다. 사람이 설정을 true로 켠 요청만 HTTP 400·404로 거절하면 같은 OAuth 토큰·공급자·모델·지역·소리로 adaptation만 뺀 요청을 **한 번** 더 보낸다. 성공하면 턴을 계속하되 `stt_adaptation_disabled`를 턴 진단 화면·`stt_adaptation_fallback` 지표·상태/코드만 있는 로그에 남기고, 같은 음성 세션의 뒤 요청은 처음부터 adaptation을 빼서 보낸다. 다른 공급자로 가지 않으며 workflow 상태를 이 복구가 바꾸지 않는다. 두 번째 요청도 실패하면 기존 `speech.dropped reason=stt_failed` 길을 따른다.
  - **이어 붙임의 상한**(줄 HEAR2 결정 2): 이어 붙여 둔 소리가 10초(`CONTINUATION_JOIN_MAX_SECONDS`)에 이르면 그 턴은 그대로 받아쓰고 다음 소리는 전처럼 끼어들기 후보가 된다 — 주변 소음이 끝없이 턴을 취소·재시작하던 사슬(시험에서 20초에 101번, 31.9초)의 끝.
  - **48→16 kHz 변환**(줄 HEAR2 결정 7): 화면은 마이크 샘플률(노트북 48 kHz)을 16 kHz 로 바꿀 때 64탭 저역 필터(`createPcm16Downsampler`, 0.45×16 kHz, 20 ms 블록 사이 기억 유지, 0.67 ms 지연)를 거친 뒤 고른다. 측정(합성 목소리 + 8 kHz 위 소음 −10 dB): 고르기만 하면 음성 대역 신호 대 오차 10 dB, 필터 뒤 47 dB; 조용한 곳은 같다.
  - **일시정지 중**(결정 7): 재개 말("다시 시작", "이어서 하자", "계속하자", "재개"와 그 끝말)만 알아듣는다. 그 밖의 말에는 소리로 아무것도 답하지 않는다(언어 확인·되묻기·버림 알림도). 응급 말에는 여전히 정해진 응급 안내를 한다. [일시정지]를 누르면 나오던 안내 소리가 멈춘다(`playback.stop`). 단계 타이머는 계속 간다.
  - **언어 확인**(결정 8): "음성 인식 언어가 불확실합니다"는 말이 **분명히** 영어·베트남어일 때만(공급자가 영어·베트남어로 들은 두 단어 이상, 요청 말 둘이 든 세 단어 이상, 또는 여섯 단어 이상) 묻는다. 한국어 말을 라틴 글자로 받아 적은 짧은 글은 언어를 알 수 없음으로 버리고 알린다.
  - **시끄러운 곳**: 거르기를 쓰는 세션에서는 웅성거림·펌프 소리로 VAD 가 계속 말소리를 들어도 내 목소리 크기로 말 끝을 찾는다. "시끄러운 곳 모드"(실험 시작 전에 고르는 설정)를 고르면 다음·완료·타이머 시작과 기록을 한 번 되묻는다. 실험 중에는 소음 때문에 모드를 묻지 않는다(결정 9) — 다른 사람 말 세 번·소음이 선 가까이 같은 조건은 코드와 숫자로만 기록하고(`noise.condition`), 주변 소음 크기는 1분마다 숫자로 기록한다(`noise.floor`).
  - **기다림 소리**: 답이 0.7초 넘게 걸리면 짧은 소리를 낸다.
  - **문장 단위로 말하기**: 안내(단계 읽기·다음 단계·질문 답 등)는 첫 문장을 합성하자마자 재생하고, 나머지 문장은 재생하는 동안 만들어 같은 턴의 다음 소리 조각으로 이어 보낸다. 문장은 소수점·단위를 가르지 않는 곳에서만 나누고, 나눈 문장들을 이어 말하면 한 번에 말하던 것과 글자가 같다. 화면 글은 나누지 않는다. 끼어들면 남은 문장은 만들지도 보내지도 않는다. 뒤 문장을 합성하지 못하면 거기서 멈추고 오류를 알린다(이미 나온 문장은 끝까지 재생). 시작 인사·타이머 알림·되묻기·응급 문장은 지금처럼 한 번에 합성한다(타이머 알림은 15초 전에 미리 합성).
  - **같은 문장 기억**: 같은 연구실(조직)·공급자·모델·목소리·언어·문장의 소리는 서버 메모리에 둔다(최대 512문장·16 MiB, 오래 안 쓴 것부터 지움, 서버를 다시 켜면 비워짐). 다른 연구실이 만든 문장은 쓰지 않고 새로 만든다(응답 시간으로 다른 연구실이 같은 문장을 썼는지 알 수 없게). 작업 공간이 꺼진 서버는 개발 연구실 하나로 본다. 단계 읽기·시작·완료 확인 질문 같은 프로토콜 문장과 서버의 정해진 문장, 시작 인사만 해당한다. 실험자의 말을 되읽는 문장·기록 문장·"다시 말해 줘"·질문 답·모델이 쓴 답·응급 문장은 매번 새로 합성한다.
  - **다시 들려주기**: "방금 답변 다시 들려줘"·"안 들려"·"다시 들려줘"는 직전 턴이 낸 소리 조각을 순서대로 모두 다시 낸다(여러 문장 답이면 처음부터 끝까지). 앞말 없이 바로 낸다(줄 HEAR2 결정 5: 화면에만 "직전 답변을 다시 들려드려요."; 관찰 질문이 열려 있을 때의 "다시 들려줘"는 질문을 다시 묻는다). 새 턴의 첫 소리가 나오면 그 턴으로 바뀌고, 다시 들려 달라고 한 턴의 짧은 대답은 남기지 않는다. 남기는 소리는 120초(16 kHz)까지이며, 넘는 조각과 그 뒤 조각은 통째로 빠진다.
  - **응급**: 현재 사고를 말한 눈·피부 노출, 흡입·호흡 곤란·어지러움, 불·연기·불꽃, 대량 쏟음, 베임·출혈, 쓰러짐·의식, 가스·이상한 냄새, 화상, 감전, 삼킴과 "도와주세요"를 먼저 인식한다. 기존 고정 문장으로만 응답하고 관찰·이상 사항·완료·타이머를 바꾸지 않는다. 가정·과거·부정·예방 질문은 현재 사고로 읽지 않는다.

## F9. 말 한 번의 길

턴 취소는 시작된 영구 저장의 결과를 기다린 뒤 처리한다. 완료가 저장됐으면 현재 단계와 보조 보고서를 같은 완료에 맞추고, 화면의 일시정지는 취소된 턴의 복원이 끝난 뒤 적용한다. 잘못된 제어 메시지는 복구 가능한 오류 하나로 답하며 음성 연결을 유지한다.

- **무엇**: 글로 옮긴 말은 한 줄로 간다. ① 응급 판정(`server.py`) → ② **앞단 규칙**(모델을 기다리지 않음: 글자 품질, 멈춤·"종료", 열린 질문의 예/아니요, 끝점 질문에 대한 답, 남은 시간, "그거", 다시 말해 줘, 지금 단계를 이름 댄 완료, 시작, 실험 중 문제(문제 도움, 라우터 먼저에서도 앞단 규칙) 등) → ③ (켰을 때) **LLM 라우터**: 답하거나 `change_state`·`record_log` 도구로 바꾸기를 **제안** → ④ **서버 검증**: 이 말의 글자 그대로의 근거, 질문·가정이 아님, 지금 단계만, 열린 서버 질문이 없을 것 → 같은 상태 기계(`CuratedProtocolSession`)가 바꾼다.
  한국어 의문·추측 어미와 물음표는 규칙과 라우터 검사에서 같은 함수로 읽는다. "투명해졌나", "타이머 시작했나", "재개했나", "투명해질지", "타이머 시작할지" 같은 말은 관찰·완료·타이머 시작·재개·이상 사항 기록을 허용하지 않고, 열린 질문도 소비하지 않는다. 설명을 함께 요청해 기존 답변 경로로 들어가도 완료 확인을 갱신하거나 지우지 않는다. 분명한 진술·명령과 "다음"·"다음 단계"·"넘어가"의 진행 동작은 유지한다.
  모델이 늦거나·실패하거나·거부되거나·답이 검사에 걸리면 같은 말을 규칙 길로 처리한다(두 번째 결정이 아니다). 라우터 모델이 요청 한도(429)에 걸리면 그 말을 멈추고 "지금 답하지 못했어요. 다시 말씀해 주세요."라고 한다.
  모델이 쓰는 답의 말투는 프롬프트가 정한다: 해요체, 짧은 문장, 합니다체·"~하십시오"·"귀하" 금지, 원문 저자의 "we"는 "이 논문의 저자들은"(`ROUTER_SYSTEM_PROMPT`).
  모델이 쓴 답은 서버 검사를 통과해야 쓴다: 숫자는 인용한 원문에서만, 상태를 바꿨다는 말 금지, 화면 라벨 금지, 서버 값은 정확히, 근거 없는 안전 지시는 빼고 "이 상황의 안전 안내는 원문에 없어요."를 붙인다.
  "설명하고 다음으로 넘어가"처럼 설명과 이동 명령을 함께 말하면 원문의 설명 뒤에 완료 확인을 연다. 설명에 든 "왜 하는지"를 질문 어미로 읽어 확인을 없애지 않는다. 다음 단계를 알려 달라는 미리보기는 그대로 보기만 한다. 타이머 켜기·맞추기·계속 돌리기, 조사 없는 한 단계 복귀와 문제의 "이상해졌어"도 같은 기존 관문으로 처리한다. 미래의 특정 단계로 바로 이동하라는 말에는 한 단계씩 진행하는 방법을 알리고 완료·단계를 바꾸지 않는다.
  **라우터 먼저**(꺼짐)를 켜면 앞단 규칙은 시스템 정보·애매한 지칭 되묻기·짧고 분명한 명령·서버 질문의 답만 맡고, 라우터가 읽기 전용 도구(`show_visual`, `clarify`, `not_for_me`)도 쓴다.
  모델의 되묻기 후보는 서버가 전달한 원문 용어만 허용한다. 후보를 눌렀을 때 명령이나 확인 응답이 새 사용자 말로 실행되는 것을 막는다.

## F10. 단계 · 완료 · 타이머

- **무엇**: "다음", "완료했어"는 말의 꼴로 단계를 마치고 다음 단계를 읽는다. 다만 끝점 관찰이 남았거나, 단계 타이머가 돌고 있거나, "바로 확인" 모드거나, 마지막 단계면 "N단계 끝났나요?"를 먼저 묻는다. 이 완료 확인을 기다리는 동안 "다음"을 다시 말해도 완료로 간주하지 않고 같은 관문을 유지하며 "완료했으면 ‘네’라고 말해 주세요. 아직이면 ‘아니요’라고 말해 주세요."라고 말과 화면에 다시 알린다. 되풀이 단계(…될 때까지)는 실험자가 말한 관찰로 끝난다. "이전 단계로", "방금 완료 취소"는 한 번 묻고 사건을 덧붙인다(지우지 않는다). "잠깐"은 바로 멈추고 "재개"·"계속"이 풀며, "종료"는 한 번 묻는다.
  **타이머 말 명령**(줄 HEAR2 결정 3, 2026-10-26): "타이머 일시정지해 줘/멈춰", "타이머 다시 시작/계속", "타이머 취소/꺼 줘", "타이머 처음부터 다시"는 앞단 규칙 `timer_control` 이 실험 일시정지 낱말보다 먼저 읽는다(전에는 "타이머 일시정지"가 실험 전체를 멈췄다). 멈춘 타이머는 남은 시간이 그대로 서고 알림도 자며, 다시 시작하면 멈춘 만큼 시작 시각을 밀어 마감을 맞춘다; 취소는 지우고, 처음부터는 같은 값(원문 값 또는 오늘 바꾼 값)으로 지금부터 다시 센다. 상태를 바꾸는 명령이라 되읽는다("3단계 타이머를 멈췄어요. 12분 30초 남은 채로요."), 시끄러운 곳 모드에서는 한 번 묻고, 질문꼴("타이머 멈출까?")은 상태만 말한다; 도는 타이머가 없으면 "지금 도는 타이머는 없어요." 장부·실험 기록에 `timer_paused`·`timer_resumed`·`timer_cancelled`·`timer_restarted`(그때의 타이머 상태 포함)를 남기고, 화면은 "일시정지 · 9:00 남음"으로 보인다. "타이머/타임/시간 얼마나 남았어"와 끝에 독립된 군말 "어"·"음"이 붙은 말은 읽기 전용 `timer_status`이고 타이머 상태를 바꾸지 않는다. 실험 일시정지 말은 전처럼 실험만 멈춘다.
  **받아쓴 글이 틀려도 상태는 한 번만, 분명할 때만**(줄 SAFE2, 2026-10-31 실측 뒤): ① 실험이 일시정지가 아닌데 "재개"·"다시 시작"이 들리면 아무것도 바뀌지 않고("일시정지 상태가 아니에요"), 그 단계 타이머가 멈춰 있으면 "지금 실험은 일시정지 상태가 아니에요. N단계 타이머를 다시 시작할까요?"를 한 번 묻는다 — "타이머 재개"의 첫 낱말이 깨진 실측 행("다이모 재개")의 길. ② 타이머 낱말이 한 글자(자모) 틀리게 들리면("다이머 일시정지", "타이모 취소") 타이머 낱말로 읽되 한 번 묻고("N단계 타이머를 멈출까요?") "네"에만 한다 — 전에는 "다이머 일시정지"가 실험 전체를 멈췄다. 동사가 잘린 "타이머 잠깐 멈"도 타이머의 일시정지다. ③ 인식기가 같은 말을 두 번 쓴 것("다음. 다음.", "네. 네.", "타이머 일시정지 타이머 일시정지", "종료. 종료." — 사람 탐침 14 클립 중 7개, 소리에는 한 번)은 모든 규칙과 기록이 한 번으로 읽는다: 단계 이동 한 번, 완료 확인 한 번, 기록 한 번. 전체가 한 어구의 되풀이일 때만 줄이고 "안녕 안녕하세요"·"100 100 mL"는 그대로다.
  **타이머**는 원문에 적힌 시간만 시작한다(다른 시간을 말하면 "원문은 15분입니다…"라고 묻는다). 그 단계의 시간을 오늘 바꿨으면 바꾼 시간으로 시작한다("20분 타이머를 시작했습니다.", 묻는 말은 "이 단계 시간은 20분(오늘 바꾼 값 · 원문 15분)이에요.").
  **오늘 바꾼 값**: 시작 마법사에서 고른 값([F7](#f7-시작-전-확인과-시작))이나 실험 중에 말한 값("이번엔 3단계 15분 대신 20분", "3단계 온도 40도로 바꿔 줘", 앞단 규칙 `run_value_change`)은 그 단계에 올 때마다 "이 단계는 바꾼 값으로 해요: 시간 20분(오늘 바꾼 값 · 원문 15분)."이라고 말하고 단계 카드에 같은 글로 보인다. 음성 세션이 시작 준비 상태이고 아직 첫 단계를 시작하지 않았을 때도 같은 앞단 규칙으로 바꿀 수 있으며, 이때 실험을 시작하거나 단계를 넘기지는 않는다. 말로 바꾸면 수치 확인 방식대로 한다: 되읽기·조용히는 바로 바꾸고 "3단계 시간을 바꿨어요: 20분(오늘 바꾼 값 · 원문 15분). 되돌리려면 '3단계 원문대로'라고 말씀해 주세요."로 되읽고, 바로 확인이나 시끄러운 곳 모드는 "3단계 시간 15분을 20분으로 바꿀까요?"를 먼저 묻는다. 다만 새 값이 원문 값의 절반 미만이거나 2배를 넘으면(0 °C 이하 온도는 언제나) 방식과 관계없이 먼저 묻는다: "5단계 온도를 37°C에서 14°C로 바꿀까요? 원문 값과 많이 달라요. 맞으면 '네'라고 해 주세요."(소리는 "삼십칠 도에서 십사 도로"). "네"에만 바꾼다. 지금 단계나 뒤 단계만, 그 단계 타이머가 돌지 않을 때만 바꾼다. "3단계 원문대로"·"바꾼 값 되돌려 줘"는 되돌리기 사건을 덧붙인다. 질문·"…했어"(한 일은 편차 기록)·기록 요청·타이머 명령은 바꾸지 않는다. 모델 도구에는 값을 바꾸는 것이 없다. 끝날 때 "15분 타이머가 끝났어요. 다음은 N단계 …", 5분 이상 타이머는 "1분 남았어요."를 말하고, 화면에는 늘 알림과 소리가 나온다. 멈춘 동안에도 타이머는 돈다. 10분 넘게 말이 없다가 질문하면 지금 어디인지부터 말한다.
  **단계 이름은 한 번 말하고 한 번 보인다**: 단계의 한국어(검토본·기계 번역)는 "2단계: "로 시작한다. 말과 화면(답 상자·자막·단계 카드·다음 단계 줄)의 모든 답에서 서버가 마지막에 단계 이름이 겹친 곳("2단계: 2단계: …")을 하나로 줄이고, 자기 번호로 시작하는 원문 줄이 "2단계: " 뒤에 오면 번호를 한 번만 둔다("2단계: 2 Prepare …" → "2단계: Prepare …"; 영어 답의 "Step 2: 2 …"도). 수량("2단계: 2 mL …")은 그대로다. 원문 인용 상자("원문 · English" 아래와 문서의 원문 칸)의 원문 글은 그대로다. 상태의 `primary_summary` 에는 단계 이름이 없고, 지금 단계 이름표는 "2단계 · 전체 9단계"처럼 한국어로만 보인다. 서버의 명시적인 `next_step_label`과 다음 단계 본문을 따로 그려, 옛 응답의 "Step 2단계: 2단계: …" 같은 머리말도 화면에서 한 번만 보인다. 번역이 없는 원문 줄은 영어로 읽지 않는다([F4](#f4-분석)의 한국어 먼저).
  **명령이 섞인 말**: 주장과 함께 넘어가자는 말("원문이 뭐든 10분이면 되잖아, 다음으로 가", "10분 했어 다음", "원문 상관없이 그냥 넘어가")은 넘어가는 부분을 버리지 않고 한 번 묻는다(앞단 규칙 `mixed_move`). 말한 값이 원문 값과 다르면 "원문에는 2단계가 10분으로 적혀 있어요. 이대로 다음 단계로 갈까요? 오늘 15분으로 하려면 '2단계 10분 대신 15분으로 할게'라고 말해 주세요.", 아니면 "이대로 2단계를 마치고 다음 단계로 갈까요?". "네"라고 해야 넘어간다(완료 질문과 같은 관문). 묻는 말("…가도 돼?")과 넘어가는 말만 한 것("다음", "완료했으니 다음으로 넘어가")은 그대로이고, 망설임 말 뒤의 이동("어… 음… 그러니까 이제 다음 단계로 넘어가자")은 "다음 단계로 넘어가자"와 같다. 끝나지 않았다는 말과 함께 넘어가자는 말("아직 덜 됐는데 그냥 다음 단계 가자")은 결정 D7 대로 넘어가지 않고 "아직 끝나지 않았다고 하셔서 N단계에 머뭅니다."와 완료 기준을 말한다(라우터를 켜면 라우터가 받고, 꺼져 있으면 규칙 길이 같은 답을 한다).

## F11. 질문과 설명

- **무엇**: 원문이 답하는 질문(양·시간·온도·지금 단계·다른 단계)은 원문 값으로 답한다. 원문에 없는 것은 "PDF에서 확인할 수 없어요."라고 한다.
  - **"자세히"**: "자세히", "더 자세히", "자세하게", "좀 더 설명해 줘", "더 알려줘"(소리 인식이 낸 "차세이"·"자세이" 포함)는 지금 단계를 자세히 읽는다(읽기 전용). 라우터를 켜면 직전 답을 아는 라우터가 받고, 규칙 길에서는 지금 단계다. "다시"·"한 번 더"는 직전 안내를 다시 말한다. 이 말들은 어떤 상태에서도 기록이 되지 않는다([F12](#f12-실험-중-기록)).
  - **막연한 확인**: "이거 맞아요?", "잘 된 건가", "망한 것 같아요", "제대로 한 건지 모르겠어"처럼 아무것도 이름 대지 않은 걱정은 지금 단계가 어떻게 되면 되는지를 짧게 다시 말하고("5단계는 이렇게 되면 돼요. …" — 원문의 예상 결과, 없으면 반복 단계의 끝 상태, 그것도 없으면 "원문에는 확인할 결과가 따로 적혀 있지 않아요.") "다르게 보이는 게 있으면 무엇이 다른지 말해 주세요." 뒤에 아래 문제 도움을 붙인다. 기록하지 않고 아무것도 바꾸지 않는다. 무엇이 문제인지 말한 것("젤이 아직 파래", "튜브가 터졌어")은 지금처럼 문제 도움·이상 사항이 맡는다.
  - **"그거"**: 가리킬 값이 하나면 그것으로, 둘·셋이면 "A요, B요?"로 되묻고, 더 많으면 화면 목록을 띄운다. 다음 말이나 화면 누르기로 고른다.
  - **AI 일반 지식**: 원문이 설명하지 않는 용어 뜻("HPLC water 가 뭐야?")에는 규칙의 답 뒤에 "PDF에는 따로 설명이 없어요. 일반적으로는 …"을 붙이고 화면에 "AI 일반 지식"으로 표시한다. 120자 이내, 숫자·방법·양·안전·완료 기준이 든 설명은 서버가 뺀다. 켰을 때만 나온다(개발 실행기는 켜고 파일럿 실행기는 끈다).
  - **문제 도움**: 실험 중 문제를 말하거나("젤이 아직 파래", "침전이 생겼어", "the gel is still blue") 물으면("왜 안 되지?", "왜 아직 파래?") 아무것도 바꾸지 않고 출처가 붙은 짧은 도움을 말하고 화면에 보인다. 문제를 일어난 일로 말하면 지금처럼 이상 사항으로 기록하고 되읽은 뒤에 붙인다. 물은 말은 기록하지 않는다. 되풀이 단계에서 그 단계가 기다리는 상태가 아직이라는 말("탈색될 때까지" 단계의 "아직 파래")은 기록하지 않고 도움만 준다. 그 단계의 끝점 낱말로 한 말("탈색이 안 됐어")과 "그냥 다음 단계 가자" 같은 명령은 지금처럼 끝점 규칙과 완료 관문이 맡는다.
    **아직 일어나지 않은 문제·이유·만약 질문**("침전이 생기면 어떻게 해?", "문제가 생기면 다음으로 가도 돼?", "결과가 이상할 수 있는 이유가 뭐야?")은 더 좁은 읽기 전용 답이다. 현재 프로토콜 검토본의 단계·주의·노트·예상 결과·반복/분기 조건·문제 해결 줄과 현재 단계에 연결된 승인 안전 문서만 찾는다. 지난 기록·공개 자료·AI 일반 지식은 이 답의 근거가 아니다. 답변 역할을 켰으면 모델은 서버가 준 원문 후보 중 한 줄의 식별자 또는 `unsupported`만 고르며 문장을 쓰지 않는다. 화면과 말은 선택된 원문을 그대로 쓰고 쪽·단계를 붙인다. 연결된 안전 문서는 승인되고 현재 단계에 적용되는 원문 발췌만 쓰며, 검토된 한국어가 없으면 영어 안전 지시를 소리 내 읽지 않고 화면에서 확인하라고 한다. 근거가 없거나 모델이 `unsupported`를 고르면 "원문에 없음"과 현재 단계·쪽을 보인다. 모델을 쓸 수 없으면 그 사실을 제한 사항으로 남기고 서버의 원문 검색 결과만 그대로 보인다. 어떤 경우에도 단계·완료·타이머·기록은 바뀌지 않는다. 원문 선택이 3초를 넘기면 답보다 먼저 "원문과 맞춰 보는 중이에요."라고 한 번 말한다.
    **일어난 일 + 질문**(줄 SAFE2, 2026-10-31): "침전이 생겼는데 이러면 어떡해?", "거품이 났어 어떻게 해?"처럼 과거로 일어난 일을 말한 뒤 묻는 말은 "침전이 생겼어"처럼 지금 단계의 이상 사항으로 기록하고 되읽은 뒤(줄 SAFE1 흐름 그대로), 같은 턴에 위의 **근거 답**(원문 위치 또는 "원문에 없음")을 붙인다(`intent_arbitration.problem_reading` 의 `statement_question`, 의도 `problem_report_question`, 도움 표식 `grounded_question`). 전에는 "침전이 생겼는데 어떡해"를 물은 말로만 읽어 기록하지 않았고(줄 HELP), "이러면 어떡해"는 가정으로 읽어 답하지 않았다. 물은 말만("왜 아직 파래?", "왜 안 되지?")은 그대로 도움만, 가정은 그대로 아래. 받아쓰기가 낱말의 어미 앞에서 끊긴 말("여기서 거품이 생기", "용액이 탁해지", "탁해져서")은 보고인지 가정인지 알 수 없으므로 기록하지 않고 아래의 한 번 묻는 말로 간다(`unfinished_problem_statement`).
    **가정으로 말한 문제**("여기서 침전이 생기면", "혹시 거품이 나면 어떡해?", "만약 색이 변하면 어떻게 돼?", "생길 수도 있어?", 받아쓰기가 "-면"에서 끊긴 말)는 아직 일어나지 않았으므로 이상 사항으로 기록하지 않고 위의 근거 답으로 간다(`intent_arbitration.supposed_problem_reading`, `supposes`). "만약을 위해 봤는데 침전이 생겼어"처럼 가정 뒤에 과거로 말한 일, "표면에"·"-면서"처럼 가정이 아닌 말은 지금처럼 기록한다. "섞으면 침전이 생겨"처럼 가정이 평서문으로 끝나 지금 일어난 일일 수도 있으면 상태를 바꾸지 않고 한 번만 묻는다: **"지금 생긴 일인가요, 생기면 어떻게 하는지 묻는 건가요?"** "지금 생겼어"·"응 방금" 같은 답은 앞의 말을 이상 사항으로 기록하고, "물어본 거야"나 같은 말을 다시 하면 근거 답을 한다. 다른 말이면 그 말대로 처리한다. "타이머 끝나면 다음으로 가자"처럼 가정한 명령도 이상 사항으로 기록하지 않는다.
    보조 모델의 **AI 일반 지식**(가능한 원인 ③, 원문 밖 설명)은 문제에 대해 원인을 단정하지 않고("때문이에요"), 가정한 일을 일어난 일처럼 쓰지 않는다("침전이 생겼을 수 있어요"). 어기면 그 문장을 버리고 닫는 말만 한다(`answer_checks.supposition_violations`, 공급자 경계와 `possible_cause_violations`·`outside_pdf_violations`에서 다시). 원문 근거가 없다는 말을 먼저 하는 순서는 그대로다.
    순서: ① **원문** — 지금 단계·앞뒤 단계·같은 단원의 노트·예상 결과·주의·반복 조건과, 분석이 담지 않은 쪽 글 중 문제 해결로 읽히는 줄. 화면에 "원문 · p.5 · 7단계 · 반복 조건"과 원문 그대로, 말로는 검증된 한국어 읽기("원문 5쪽: …"; 자동 번역이면 그렇다고 말함, 읽기가 없으면 "원문 N쪽에 관련 문장이 있어요. 화면에서 확인해 주세요."). ② **지난 기록** — 같은 계정·같은 연구실·같은 프로토콜의 지난 실험에서 같은 단계에 남은 이상 사항·관찰과 그 뒤 기록("지난 기록 · 10월 20일 · 7단계", "그 뒤 관찰: …"). 다른 계정·연구실 기록과 소유자 없는 연구실 기록은 읽지 않는다. ③ **공개 자료**(공개 지식 등급을 켰을 때, F20 — 관련도 하한을 넘은 조각만, 화면에 "공개 자료 · 일반 참고 — <출처 이름>"·제목·위치·조각 그대로·주소·라이선스 두 개까지, 말로는 "공개 자료에 관련 내용이 있어요."만) 그리고 보조 설명이 켜져 있을 때만 "AI 일반 지식으로는, …일 수 있어요."(가능한 원인 후보 두 개까지, 답을 다 말한 뒤). ④ "조건을 바꾸려면 담당자와 확인하세요. 바꾸기로 하면 '오늘 바꾼 값'으로 말해 주세요." 찾은 것이 없으면 "원문과 지난 기록에서 이 문제와 관련된 내용을 찾지 못했어요."와 ④.
    도움의 고정 문장에는 숫자가 없고, 허가("계속해도 돼요")·조건 변경 지시·안전 판단·상태를 바꿨다는 말·서버만 하는 질문이 없다(`answer_checks.problem_help_violations`). 모델의 원인 후보는 인용한 원문에 없는 숫자·단위, 프로토콜에 없는 시약·재료 이름, 조건 변경, 허가, 안전 판단, "~일 수 있어요"가 아닌 문장이 있으면 버리고 ④만 말한다(`possible_cause_violations`). 쏟음·노출·오염에는 원인 후보를 묻지 않는다. 도움을 준 일은 기록 장부에 "문제 도움" 사건(어느 쪽·몇 건, 찾는 데 걸린 시간; 도움 글은 남기지 않음)으로 남는다.
    찾기는 서버 안 SQLite FTS5 다(`knowledge.py`; 연구실 자료를 바깥 색인 서비스로 보내지 않는다): 값은 단위와 함께(`37°C`, `0.5 mL`), 영어 낱말 줄기, 조사를 뗀 한국어 낱말, 그리고 한국어 문제 말과 원문 영어를 잇는 일반 실험 개념("파래"·"destain" → 염색)으로 찾는다. 계약(`KnowledgeHit`·`KnowledgeContext`·`KnowledgeSource`, 쓸 수 없으면 설정 이름을 담은 `KnowledgeUnavailable`, 다른 공급자로 넘어가지 않음)은 공개 자료 공급자도 같은 모양으로 따른다.
  - **공개 자료**: 라이선스를 확인한 공개 자료에서 찾은 조각은 "공개 자료 · 일반 참고 — <출처 이름>"으로 밝히고 출처·라이선스를 보인다(F20; 문제 도움 ③ 단계에 연결, 2026-10-25). 수치는 인용한 조각에 있는 것만, 지시가 아니라 참고 사실로 말하며 원문 값을 바꾸거나 "계속해도 돼요"를 말하지 않는다(`answer_checks.public_reference_violations`).

## F12. 실험 중 기록

- **무엇**: 말한 관찰·측정·편차·메모와 이상 사항("시약을 엎질렀어", "침전이 생겼어")은 그 사람의 말 그대로 지우지 않는 장부에 남고, 서버가 되읽어 준다. 이상 사항의 되읽기 뒤에는 출처가 붙은 문제 도움이 따른다([F11](#f11-질문과-설명)). "안 보임"처럼 부정이 든 말은 통째로 남는다. "방금 기록 고쳐 줘, X가 아니라 Y"는 한 번 묻고 고침을 덧붙인다(원래 것은 남는다). 소수점이 분명하지 않은 값은 다시 묻는다.
  **빠른 기록**: "특이사항, 3번 well 탁함", "메모 …", "기록해 줘 …"는 지금 단계의 기록이다. `pH 7.2`, 시료 이름, 측정 항목처럼 무엇을 기록하는지 분명한 보통 기록은 같은 턴에 저장하고 짧게 되읽는다. 한두 음절·숫자뿐인 말이나 `측정값 37 °C`처럼 대상이 없는 값은 수치 확인 방식과 관계없이 저장 전에 한 번 되묻고, "네" 뒤에만 남긴다. 같은 관문이 인식기가 띄어 쓴 "측정 값 100 mL", 한 글자 틀린 "측정갑", "측정치"·"수치", 그리고 측정 낱말은 있는데 값이 안 들린 "측정 갑 뱅 미리"도 읽는다(줄 SAFE2, 2026-10-31 실측: 원심분리기 소음에서 값이 깨진 기록이 그대로 저장됐다). `pH 7.2`·`온도 37도`·"상층액 투명함"은 전처럼 바로 저장하고 되읽는다. "정정"이라고 하면 고칠 값을 바로 받아 처음 잘못 들은 값은 남기지 않는다. `well`·튜브·셀·시료 번호와 숫자·단위는 말한 표기를 그대로 보존한다. 이 길은 단계와 타이머를 바꾸지 않는다.
  **실험 노트 질문**(한국어, 상태를 바꾸지 않음, "넘어가"로 건너뜀): 시작 뒤 "오늘 실험 목적이나 시료를 한 줄로 말씀해 주세요.", 관찰 대상이 있는 단계를 설명 없이 마치면 "관찰한 것 있으면 말씀해 주세요.", 끝나면 "결과 한 줄과 다음에 바꿀 점이 있으면 말씀해 주세요." 목적·결과는 저장한 글을 그대로 되읽고 다음 말로 "정정: …"을 받아 고침 사건을 덧붙인다. 한두 음절이거나 맥락 없는 숫자뿐인 답은 저장 전에 한 번 확인한다. 명령이나 질문은 답이 아니라 명령으로 처리된다. 짧은 명령 낱말("자세히", "더 자세히", "다시", "한 번 더", "천천히", "취소", "원문", "그림", "타이머", "요약" …)은 어떤 노트 질문의 답도 아니고 기록되지 않는다(질문은 열린 채로 남는다). "알겠어", "고마워", "확인", "몰라"는 "넘어가"처럼 질문을 건너뛴다.
  기록 탭에서 손으로 관찰을 적고 사진·문서(최대 32 MiB, 해석하지 않음)를 붙일 수 있다.
  오늘 바꾼 값은 실험 기록에 사건으로 남는다: 시작이 적용한 값은 `session_started` 사건의 `run_changes`, 말로 바꾼 값과 되돌린 값은 `run_value_changed`·`run_value_reverted`(어느 분석·검토본·단계·값 항목인지 함께). 작업공간 타임라인에도 같은 사건이 남아 연결이 끊긴 실험을 이을 때 그 값으로 돌아온다.
  화면에서 메모·사진을 저장한 뒤에도 열린 음성 연결의 일시정지·재개·종료는 서버의 최신 버전으로 처리한다. 연결과 현재 단계가 같은지 거래 안에서 확인하며, 다른 탭이 넘겨받았거나 단계가 바뀌면 거절한다. HTTP가 직접 보내는 버전 검사는 그대로 적용한다.

## F13. 실험 노트와 보고서

- **무엇**: 실험이 끝나면 덧붙이기 장부와 실행한 프로토콜 판에서 **실험 노트 초안**을 결정적으로 다시 만든다. Word·PDF·Markdown과 새 노트 화면은 같은 공통 뼈대를 쓴다: **실험 정보, 목적, 방법, 관찰·특이사항, 결과, 해석·다음 할 일, 분야별 기록, 부록**. 실험 정보에는 날짜·시각·실험자·프로토콜 판·원문 출처가, 방법에는 원문 단계와 원문→실제 값·실제 시각·타이머 사건이 들어간다. 원문 분석에 숫자·단위 검사를 통과한 한국어 단계 번역이 있으면 한국어를 먼저 쓰고 원문을 함께 두며, 번역이 거절되었거나 없으면 그 상태를 표시한다. 목적·결과는 사람이 말하거나 입력한 것만 쓰며, 말하지 않은 목적·결과·해석과 내용 없는 절은 `기록 없음` 한 줄로 줄인다. 관찰·특이사항은 단계·시각과 말한 그대로를 쓴다. 목적·결과·관찰에는 `되읽음`·`정정됨` 상태를 표시하고 정정 전 글은 `처음 기록`으로 접어 보존한다. 노트 본문에는 준비된 모델 문장도 넣지 않는다.
  실험을 시작할 때 고정한 프로토콜 기준의 `원문 공개 범위`와 선택적인 `출처 메모`를 실험 정보에 넣는다. 예전 프로토콜은 공개 여부를 추측하지 않고 `확인 기록 없음`으로 표시한다.
  오늘 바꾼 값과 실제로 기록한 값은 방법의 원문→실제 표와 원문과 다르게 한 점에 함께 나온다. 실제 기록이 있으면 그 기록이 앞서고, 타이머를 일찍 끝냈으면 원문 시간과 실제 끝낸 시간이 나란히 나온다. 모든 표시 숫자를 프로토콜 원문 목록·실행 장부·그 둘로 다시 계산 가능한 시각·수율에서 재현하는 `audit_notebook_number_provenance` 검사가 있다. 기록 사건의 숫자는 되읽기·실험자 확인·정정 상태가 함께 있을 때만 이 감사의 근거가 된다.
  **분야별 기록**은 원문 단계 문장으로 바이오·화학 합성·배터리·소재 중 하나를 고르고 사람이 화면에서 바꿀 수 있다. 바이오는 세포주·계대 수·플레이트 배치/well 위치, 화학은 반응식·시약(몰·질량·당량)·수득량/수율·TLC Rf·정제 조건, 배터리·소재는 셀/시료 번호·전극 로딩·전해액 양·조립 환경·크림핑/소성·사이클 조건을 둔다. 원문이나 기록에 없으면 빈칸이다. 수율은 사람이 남긴 실제 수득량과 이론 수득량이 환산 가능한 같은 차원으로 모두 있을 때만 계산하고 `실제 ÷ 이론 × 100` 식을 함께 보인다.
  **그림**은 장부와 원문에서만 만든다. 단계 타임라인은 실험 완료·중단까지 포함한다. 같은 단위의 원문→실제 막대, 해당 단계에 붙인 사진, 원문 분석이 쪽·위치·캡션 근거로 그 단계에 명시적으로 고른 그림, 기록된 well 위치의 플레이트 위치, 배터리·소재의 셀/시료 번호별 표를 보여 준다. 원문 분석의 단계-그림 근거가 없으면 붙이지 않고, 같은 원문 그림은 한 노트에서 한 단계에만 쓴다. 사진과 원문 조각은 기존 증거·원문 권한을 거치고 Word·PDF에도 들어간다. 생성 모델 그림이나 기록에 없는 값의 도식은 만들지 않는다.
  **묶음 실험 노트**는 소유자가 연구 주제 이름, 시작 날짜 범위, 프로토콜로 자기의 끝난 Voiney Lab 실험 2–50개를 고르는 덧붙이기 전용 선택이다. 이름은 분류나 연구 상태가 아니라 문서 제목일 뿐이다. 서버는 날짜순 목차와 실험별 시작·끝·상태, 체크포인트 이어하기 연결, 시작에 적용된 `연구실판 vN` 조건 변경 이력을 투영한다. 각 실험은 자기 보고서 장부와 자기 원문에서 따로 다시 만들며, 값·관찰·타임라인 사건·사진·원문 그림의 보고서/세션/원문 정체가 다른 실험과 섞이지 않았는지 검사한다. 각 노트의 출처 숫자 감사와 실험 간 격리 감사가 모두 통과한 뒤에만 생성 사건을 첫 실험 보고서 장부에 덧붙인다. 실패한 생성 요청은 사건을 남기지 않는다. 화면·Word·PDF는 이 한 바인더 투영을 쓴다. 이는 Voiney Lab으로 진행한 기록을 묶는 기능이지 ELN이나 연구 관리 플랫폼이 아니다.
  **Methods 조건표**는 원문 시약·장비 이름을 두고 구매처·카탈로그 번호·Lot 번호와 입력 시점을 선택적으로 덧붙인다. 원문 목록에 이미 있는 구매처·카탈로그 값은 원문으로 표시하고, 기록 소유자는 실험 전·후 화면 입력이나 현재 단계의 말 기록으로 빈 값을 채운다. 목록에 없는 품목은 받지 않는다.
  **연구실 양식**은 같은 연구실 관리자가 위 여덟 절의 이름과 순서만 정한다. 새 판은 덧붙이기만 하며, 절을 빼거나 사실·근거 규칙을 바꾸지 못한다.
  대답하지 않은 실험 노트 질문은 일시정지·재개 뒤에도 유지하고 재개할 때 다시 묻는다. 그 질문이 열린 동안의 "넘어가"는 질문만 건너뛴다.
  기존 보고서 문장 준비는 별도 파생 출력용으로 남아 있지만 위 실험 노트 본문에는 넣지 않는다. 실험자가 아직 확인하지 않은 값은 "[미확인]"으로 표시하고 화면에서 하나씩 확인하거나 고친다.
  관찰 질문에 대한 답은 질문이 가리킨 완료 단계에 저장한다. 같은 값 확인을 다시 보내도 확인 사건은 하나만 남기며, 동시에 온 PI 확인은 각각 남긴다. 조사 뒤 보고서 갱신에도 현재 연결의 설정 식별자를 붙인다.
  방법의 "원문과 다르게 한 점·문제"에는 문제 도움마다 한 줄이 붙는다: "도움 · 7단계 (10:31) — 물음 “왜 안 되지?”: 원문 p.5·p.4 · 지난 기록 1건"(`problem_help_line`). 부록 기록 표에는 물은 말이 "문제 질문"으로 남는다.
  내보내기: 화면에서 Word(.docx)·Markdown·JSON·CSV. 서버에는 PDF(LibreOffice 필요)·랩미팅 1쪽 요약(Word·PDF)·결과 표(xlsx)도 있다. 회의용 파일 이름도 `.meeting.docx`·`.meeting.pdf`로 실제 형식에 맞춘다. 관리자는 노트에 "확인함"(이름·시각·한 줄)을 남길 수 있다.
  노트의 검토본 표에서 사람이 비운 항목은 "(비움 · 원문에 없음)"(타이머는 "(타이머 없음)")으로 적는다. 다만 프로그램에 하는 말처럼 보여 확인 카드에서 [빼 주세요]로 뺀 항목(원문 글이 `program_address_shape` 에 걸림)은 "프로그램에 하는 말이라 뺌"이다 — 원문에는 있기 때문이다(`PROGRAM_ADDRESS_CLEARED`).
  기록의 소유 계정과 연구실은 서버가 정한다. HTTP·음성 소켓 조회와 내보내기는 본인 또는 같은 연구실 관리자만 가능하다. 값 확인·정정·평점·보고서 재생성은 본인만 가능하며, 관리자가 남의 기록에 쓸 수 있는 것은 PI 확인뿐이다. 다른 연구실 기록과 권한 없는 기록은 없는 것처럼 응답한다. 옛 기록의 소유자는 작업공간 세션으로 채우며, 소유자를 모르면 해당 연구실 관리자만 읽는다.
  **같은 프로토콜 기록 비교**는 본인 기록 하나를 기준으로 소유자만 연다. 공유 켜기 앞에서 `작은 연구실에서는 누구 기록인지 알아볼 수 있어요. 말한 특이사항은 그대로 보여요.`라고 알린다. 같은 연구실·같은 프로토콜의 끝난 기록 중 내 기록과 상대 소유자가 현재 공유에 동의한 기록만 최대 20개 읽는다. 동의·철회는 보고서 장부의 `notebook_share_changed` 사건으로 덧붙이고 최신 사건이 우선한다. 상대 기록은 소유자와 보고서 식별자를 뺀 읽기 전용 투영으로 원문→실제 값·실제 시각·타이머·특이사항만 주며, 목적·결과·해석·추천·우열 판정도 주지 않는다. 철회하면 다음 조회부터 빠진다. 관리자 권한만으로 다른 사람의 비교 기준을 열거나 공유를 켤 수 없다.
  지난 실행 비교·시작 전 확인 답·하루의 실행 순번은 같은 소유 계정·연구실·프로토콜 안에서만 구한다. 소유자가 불명인 옛 기록에는 다른 사람의 시작 전 답을 넣지 않으며 순번을 비워 둔다.
  `GET /api/workspace/experiments/{session_id}/reports`는 그 실험의 보고서 요약 목록(`session_id`, `reports`)을 준다. 본인 또는 같은 연구실 관리자만 읽으며, 보고서가 아직 없거나 기록 기능을 껐으면 빈 목록이다. 보고서를 생성하거나 실험 상태를 바꾸지 않는다.

## F14. 연결 끊김

실험을 다시 연결할 때 `reconnect` 필드가 없어도 기존 일시정지·차단을 유지한다. 재개는 현재 설정·세대의 명시적인 음성/화면 제어로만 하며, HTTP 실험 `/transition`은 상태를 바꾸지 않고 409 `voice_control_required`로 응답한다. 다른 연결이 넘겨받으면 옛 연결의 음성 메모·완료는 거절하고 기존 `experiment.session.error` 사건의 `workspace_conflict` 코드로 알린다.

계정 모드에서는 로그아웃·비밀번호 변경·계정 끄기·계정 삭제 시 그 계정의 열린 음성 연결을 모두 닫는다. 다른 계정의 연결은 계속된다. 계정 경로는 이미 시작된 음성 보고서 저장 스레드도 완료를 기다리며, 계정 삭제는 그 뒤 삭제 목록을 만들어 늦은 저장이 기록을 다시 남기지 않게 한다. 만료나 운영자 도구의 세션 회수도 주기적으로 확인한다.

- **무엇**: 화면은 1초마다 서버와 신호를 주고받아 **3초 안에** 끊김을 알아챈다. 빨간 띠와 소리·진동으로 알리고, 화면을 읽기 전용으로 바꾸고, 마이크를 멈춘다. 끊긴 동안 화면은 서버 시각으로 단계 타이머를 이어 세고 1분 전·끝 알림을 낸다. 1·2·4·8초, 그 뒤 15초마다 다시 이어 **같은 실험**을 계속하고, 서버 상태로 화면을 바꾼다. 놓친 타이머 알림을 전하고 끊긴 시간을 내용 없는 사건으로 남긴다.
- **일시정지한 타이머**(줄 HEAR2 결정 3): 다시 연결할 때 장부의 마지막 타이머 사건을 읽어 멈춘 타이머는 멈춘 자리 그대로, 다시 시작·처음부터 한 타이머는 그 시작 시각으로, 취소한 타이머는 없이 되살린다(`_standing_timer`).
- **어디**: `static/connection.js` (`SILENT_LOST_MS`, `resumable()`); `server.py` `_send_heartbeats`, `_restore_lost_connection`, `_restore_standing_timer`, `_reconnect_timer_notices`, `_record_connection_restored`.
- **시험**: `tests/test_lane_net_reconnect.py`, `tests/test_lane_net_screen_timer.py`.
- **한계**: 실험이 작업공간 실험에 묶였을 때만 이렇게 동작한다(아니면 오류로 끝난다). 웹에서는 화면이 꺼지거나 다른 앱으로 가면 화면 타이머 알림이 울리지 않을 수 있다.

## F15. 파일럿 지표와 평점

- **무엇**: 파일럿 지표는 **숫자·코드·시각만** 둔다(말한 글·소리·프로토콜 글·모델 출력 없음): 말 한 번(라우터 결과·지연), 표시(내보내기 등), 분석 결과, 끝 평점. 행마다 계정 id. 실험이 끝나면 지금 화면은 "이번 실험에 도움이 됐나요?" 1–5 와 한 줄 메모(선택, 200자)를 묻고, 새 화면(`/app/`, 줄 RX4)은 끝 화면에서 "오늘 안내는 어땠나요?"를 표정 단추 다섯(많이 불편했어요 … 아주 편했어요 = 평점 1–5)과 칩 여섯(`tags`: `heard_well` · `missed_often` · `translation_awkward` · `screen_easy` · `timer_easy` · `figure_helped`, `pilot_metrics.FEEDBACK_TAGS`)과 한 줄로 묻는다. 둘 다 같은 `POST /api/pilot/feedback` 이고 같은 `rating` 열에 남는다(새 화면의 뜻은 "편했는지"다 — 지표를 읽을 때 화면을 구분하지는 않는다). 칩은 `pilot_feedback.tags`(쉼표로 이은 코드)로 남고 `notes` 내보내기에만 나온다. 예전 파일은 열 때 열을 더한다.

## F17. 공급자와 설정

- **무엇**: 모델 역할은 `router`·`answer`·`translation`·`analysis`·`report`·`supplemental` 여섯이고, 역할마다 공급자(`xai`·`anthropic`·`openai`·`google`)·모델·추론 수준을 적는다. 기본값은 없다("설정 필요") — 빈 역할을 부르면 다른 공급자로 가지 않고 그 설정 이름을 적은 오류로 닫힌다. STT·TTS 공급자(`google_cloud`·`elevenlabs`·`xai`, STT만 `google_cloud_v2` 추가)도 같다.
  `google_cloud_v2`는 REST V2 Recognize·기본 모델 `chirp_3`·인식기 `_`를 쓴다. API 키 대신 저장소 밖의 ADC JSON(소유자만 접근)과 프로젝트·지역 설정이 필요하다. 기존 자격 파일 설정 이름으로 서비스 계정 키·AWS WIF external_account·개발자 authorized_user를 google-auth ADC 로더 한 경로에서 읽는다. 파일이 없거나 틀리면 다른 자격을 찾지 않는다. AWS 메타데이터·Google STS·서비스 계정 토큰 교환도 같은 제한 시간과 고정 주소 검사 안에서 실행하며 개발자 quota 프로젝트를 요청 헤더에 전달한다. 기본 지역 `us`, 턴 언어 ko/en/vi(미지정은 ko-KR), 16 kHz 모노 PCM16, 자동 구두점·단어 시각을 요청한다. 모든 공급자에 보내는 힌트 목록은 한국어 명령·저장 번역 용어집의 한국어 이름·기존 단계와 제어 말·원문 기술용어 순이며 서버 공통 상한 100개다. 인라인 음성 적응은 `VOINEY_LAB_GOOGLE_STT_V2_ADAPTATION_ENABLED=true`일 때만 이 목록을 V2 한 구절 100자·1,000개·총 100,000자 한도 안에서 보낸다. 공식 REST 모양은 `adaptation.phraseSets[].inlinePhraseSet.phrases[].value`이고, Chirp 3 문서는 adaptation과 `us`·`eu`, 한국어를 지원한다고 적는다. boost는 보내지 않는다. 그러나 2026-10-29 같은 한국어 WAV 실측은 `us` 힌트 404(3,573 ms), `eu` 힌트 404(5,021 ms), `us` 힌트 없음 200·3글자(3,915 ms)였으므로 지역 기본 `us`는 유지하고 adaptation 설정 기본만 false로 둔다. true로 켠 요청의 기존 한 번 제거 재요청과 세션 기억은 유지한다. 문서와 공급자 응답이 다른 내부 원인은 확인 안 됨이다. `VOINEY_LAB_GOOGLE_STT_V2_DENOISE`는 기본 true이며 이 문제와 무관했다. OAuth 토큰은 메모리에만 두며 인증과 두 인식 시도는 같은 요청 제한 시간을 나눠 쓴다. 그 밖의 실패는 `SpeechProviderError`의 HTTP 상태·허용된 Google 코드로 기존 장애 안내를 거치고 상태는 바꾸지 않는다. 빈 결과는 빈 받아쓰기다. 설정·사람 확인 순서는 `docs/DEPLOYMENT_RUNBOOK.md` 2절과 `docs/TROUBLESHOOTING_GUIDE.md` 6절이다.
  설정 이름은 모두 `VOINEY_LAB_` 로 시작한다(SDK 표준 이름 제외). 옛 이름이 셸이나 `.env` 에 있으면 서버·실행기·시험이 시작을 거부하고 이름만 알린다 — `python scripts/migrate_env.py --check` 로 보고 `--write` 로 바꾼다. 실행기의 기본값은 셸·`.env` 의 값을 덮지 않는다.
  시작 확인과 작업공간의 boolean 오타는 해당 설정 이름을 적은 오류로 거부한다. 미설정·빈 사용 범위도 신원 판단과 서버 설정에서 똑같이 거부한다.

## F19. 화면과 시작 및 종료

- **무엇**: 홈·프로토콜·실험·기록·설정 다섯 탭과 시작 시트로 나눈다. 프로토콜 목록(`#/protocols`)의 항목은 상세(`#/protocols/<id>`)로, 새 올리기는 `#/upload`의 파일·공개 링크 선택 → 경과 시간과 작업 표시 → 결과로 이어진다. 상세에는 분석 요약·원문 대조·시약 표·검토본 기록·다시 분석이 접고 펼치는 묶음으로 있다. 번호 없는 단계는 화면이 붙인 번호임을 구분하고, 쪽 카드에서 원본 쪽을 열며, OCR 값 단추는 엔진 이름을 보여 준다.
  올리기와 상세의 다시 분석에 "분석할 쪽 (선택)" 두 칸(처음·끝)이 있고, 상세는 서버가 알린 분석한 쪽을 보인다. 시작 시트의 안전 주의 다음 단계는 "오늘 원문과 다르게 할 값"(서버의 값 목록과 새 값 칸, **지난번처럼**)이고, 실험 중 단계 카드는 그 단계의 바꾼 값을 서버가 준 글 그대로 보인다(`renderRunChanges`).
  실험 전 카드는 선택에 따라 **새 실험 시작**·**이 프로토콜로 시작**·**실험 이어하기**다. 모든 시작은 시트의 마지막 단추를 거친다. **만든 지 오래된, 시작하지 않은 실험 칸**(줄 SAFE2, 사람 결정 2026-10-31): 작업공간에 `ready`로 만들어 두고 시작하지 않은 실험은 `VOINEY_LAB_READY_EXPERIMENT_MAX_AGE_HOURS`(기본 12시간) 안에서만 음성 세션이 이어 받는다. 더 오래된 것을 `session.start`가 이름 대면 서버는 그 칸을 그대로 두고 새 실험을 만들며 `session.ready` 에 `stale_ready_replaced` 를 싣고, 이어 하기 후보 목록(`GET /api/workspace/experiments?active_only=true`)에서도 뺀다(10/31 실험이 10/28 칸을 이어 받아 기록 목록의 시각이 어긋났던 원인; 목록의 `run_started_at`은 줄 UI1 그대로). 진행 중·일시정지·차단 실험은 나이와 관계없이 전처럼 이어진다. 안전 **읽었어요**는 서버에 현재 대상 확인을 남기며 거절 사유가 오면 해당 확인 단계로 돌아간다. 안내 목소리 미리듣기는 한 번에 하나, 같은 단추로 멈춘다. 마지막 시작을 보내지 못하면 시트를 닫지 않고 이유를 보여 준다. 핵심 값 불러오기에 실패하면 확인 단계의 **다시 불러오기**로 재시도한다.
  프로토콜 목록은 화면이 보이는 동안 저절로 새로워진다: 연구실 목록(`/api/protocols`)을 분석 중인 항목이 있으면 5초마다, 없으면 30초마다 다시 받고, 탭을 열 때·화면으로 돌아올 때·시작 시트를 열 때 바로 받는다. 화면이 숨겨지면 멈추고 로그인 전에는 받지 않는다. 조용한 새로고침이라 상태 줄을 덮지 않고, 같은 목록은 다시 그리지 않으며, 실패하면 보던 목록을 둔다. 시작 시트의 칸(예: "오늘 원문과 다르게 할 값")에 적는 중이면 그 시트는 다시 그리지 않는다(적은 값과 키보드가 그대로, 다음 누름에 새 목록으로 그린다). 같은 연구실 사람이 올린 프로토콜도 같은 방식으로 나타나고 분석이 끝나면 새로고침 없이 시작할 수 있다. `development_only`인 개발용 예시는 개발 모드와 관리자에게만 보이고, 계정 모드의 일반 사용자 목록에서는 서버가 빼서 내려 준다. 시작 시트와 시작은 "분석을 통과한 프로토콜을 골라 주세요"·"아직 실행할 수 없습니다"로 거절하기 전에 서버에 한 번 다시 묻는다.
  프로토콜의 상태는 실행 가능 여부(`available_for_execution`)를 먼저 보고 그린다. 실행 가능한 프로토콜은 그 위에서 다시 분석이 돌거나 준비 코드가 `analysis_required`(시작 전에 읽을 알림이 있음)여도 목록·상세·올리기 결과·시작 시트 어디서도 "분석 중"·"분석 필요"로 보이지 않는다(다시 분석은 "다시 분석 중" 표로 따로 보인다). 상세의 실행 준비 판정은 "상태 · 실행 가능 · 시작 전에 읽을 알림 있음"이다. 준비 코드의 이름은 바꾸지 않았다(저장 검사와 세션 사건이 쓴다).
  기록 탭은 지난 실험 목록에서 하나의 기록(`#/records/<id>`)으로 들어간다. **종료**를 누른 뒤 서버가 끝났다고 보낼 때 끝 화면이 되고, 끝난 실험은 이어하기에서 빠진다. HTTP 세션 만료 401과 로그아웃은 소리·연결을 정리하고 이미 쓴 초대 링크 없이 로그인 화면으로 간다.
  실험 중 홈은 돌아가기만 제안하고, 음성 연결 중 올리기가 잠겨 있으면 그 이유를 말한다. 레일의 **설정**은 실험 화면 위의 시트를 연다. 남의 실험은 이어하기 후보에서 빼고 목록·상세에 읽기 전용으로 표시하며, 기록·첨부·체크포인트·값 정정·평점·보고서 재생성 제어를 숨긴다. 소켓이 1008로 닫히면 계정을 다시 확인해 로그인이 끝났을 때 로그인 화면으로 간다. 원문 확인이 남은 카드는 서버의 상태·할 일을 그리고 등록 차단 이유를 보여 준다.

  **작업 공간 앞에서 손대지 않는 실험 흐름**: 마지막 [이 프로토콜로 시작] 뒤의 보통 진행은 말로 단계 이동·일시정지·재개·종료와 종료 확인까지 갈 수 있다. 화면에는 그 말을 작게 안내한다. `화면 크게`와 `보통 화면`은 결정적인 앞단 규칙이 현재 설정·turn·generation 울타리가 있는 `screen.display_mode`를 보내며, 단계·확인 질문·타이머·기록을 바꾸지 않는다. 기기에 저장되는 **멀리 보기**는 검은 바탕·흰 글자로 지금 단계의 한국어(최소 72 px), 타이머 숫자(최소 144 px), 다음에 할 말(최소 32 px)만 보인다. 번역이 없으면 영어 원문을 키우지 않고 `번역 준비 중`을 보이며, 되묻기의 화면 단추를 숨길 때는 말할 선택지 이름을 적는다. 설정에서도 보통 화면·멀리 보기를 고른다. 일시정지·종료 단추는 복구와 접근성을 위해 남고, 메모·사진처럼 운영체제 입력이 필요한 선택 작업, 브라우저가 소리를 다시 막은 때의 [소리 켜기], 마이크가 끊긴 때의 [마이크 다시 연결하기]는 터치 예외다. 세부 설정은 Bluetooth 이어셋·목걸이형 마이크를 포함한 브라우저 마이크 목록과 `지금 고른 마이크`를 보인다. 실험 중 실제 입력 장치 식별자가 바뀌면 새 장치 이름을 화면에 10초 알린다. 393 px 올리기 화면은 가로 넘침 없이 줄어든다. 이 글자와 배치는 가짜 서버·Chromium 네 화면 크기에서 contract-tested이며 실제 작업 공간 거리·창·소음에서 읽힌다는 현장 검증은 아니다.

## 합성 음성 회귀 시험대

`scripts/sim/`은 공개 원문 발췌와 올린 프로토콜의 복사본에서 정해진 문장을 만들어
`ListenerSession.accept_chunk` → `run_turn_safely`의 실제 서버 경계를 시험한다.
오프라인은 가짜 VAD/STT/TTS로 이해와 전후 상태만 재며 외부 호출은 차단한다.
사람이 실행하는 별도 명령은 Google TTS 캐시·합성 소음·실제 STT·응답 TTS를 사용한다.
합성 소음에는 작업 공간 팬·배기·순환 펌프와 팬+원심분리기·팬+알아들을 수 없는 옆 말 모사가 있고, 30 cm·1 m 목소리 감쇠와 Google STT V2 Chirp 3 잡음 제거 켬·끔을 조건 축으로 둔다. 이는 현장 녹음이나 거리 실측이 아닌 수식 견본이다.
줄 LISTEN3의 오프라인 충격음 축은 타자·유리 부딪힘·피펫 클릭을 수식으로 만들고 각각 30 cm·1 m에서 말 뒤와 소음만 입력을 잰다. `legacy`와 `current` 처리를 같은 문장 묶음으로 비교하며 착용자 말 버림·충격음의 말 끝 재개·소음의 STT 진입·잘못 바뀐 상태를 센다. 줄 LIVE3는 충격음 위치 축(`--impact-pattern`)을 더했다: 말 뒤 한 번(`single`, LISTEN3 그대로), 말 뒤 4초 동안 계속(`continuous`), 말 위에 겹침(`mid_speech`, 말 최대치보다 6 dB 큰 충격). 함께 세는 것은 이어 붙이기 수(`continuation_joins`), 착용자 마지막 프레임부터 마지막 말 끝까지의 지연(`end_delay_ms` p50/p95, 1.5초 넘으면 `late_end`)이다. 실제 도구 녹음이나 거리 실측은 아니다. 진단용 고정 표본은 개발 분할에서 분야(바이오 12·화학 6·소재 6·토양 6)·갈래·길이를 고르게 뽑은 30 case id(`scripts/sim/manifests/live3_dev_diag_30.json`, `scripts/sim/diagnostic_manifest.py --check`)다.
두 방식 모두 같은 카탈로그 복사본의 실행 가능한 업로드를 선택할 수 있다.
호출 전 예약 원장과 호출/비용 상한을 지키고 공급자를 대체하지 않는다.
단계·타이머·확인·기록·변경 값의 예상 밖 변화, 영어 원문 복사, 단계 이름 겹침,
버린 말과 지연을 프로토콜·갈래·조건별로 집계한다. STT 실패는 공급자 HTTP 상태와 허용된 짧은 코드만 개별 결과와 집계에 남긴다. 점수에는 원음·받아쓰기·답변이나 공급자 본문을 남기지 않는다.
시험: `tests/test_sim_harness.py`. 명령·비용 가정·읽는 법·측정 한계는
[EVALUATION_SIM.md](EVALUATION_SIM.md)에 있다. 유한한 회귀 시험이며 현장 성능 검증이 아니다.
개선용·시험용은 고정 씨앗으로 나누며 같은 발화를 두 묶음에 중복하지 않는다.
시험용은 개별 결과를 감추고 갈래·프로토콜별 점수만 제공한다. 저장 번역 조건과 사람 실행 라우터 비교 조건도 같은 분할과 서버 경계를 쓴다. 영어 구간 제목은 원문 영역에 두고 한국어 설명에서 읽지 않는다. 영어 복사 점수는 확인된 한국어 읽기가 보존한 원문의 과학 이름을 복사 오류로 세지 않는다. 응급 별도 묶음은
현재 사고 10갈래와 비응급 대조군에서 놓침과 헛경보를 함께 센다.
