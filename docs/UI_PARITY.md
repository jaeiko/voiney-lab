# 두 화면의 사용자 기능 비교

기준은 `src/voiney_lab/static/index.html`의 정적 제어와 동적으로 그리는 제어, `src/voiney_lab/static/admin-metrics.html`이다. **있음**은 새 화면 안에서 제공, **다르게**는 같은 목적의 다른 흐름 또는 명시적 이전 화면 연결, **없음**은 새 화면 안에는 없으며 다음 화면 이관 작업이 필요하다는 뜻이다. 이전 화면은 `/index.html?legacy=1`로 계속 열린다. 서버에만 있는 기능을 이전 화면 기능으로 세지 않는다.

초대 발행·계정 끄기와 켜기는 기존에도 화면 기능이 아니라 운영 스크립트였다. 새 화면에 관리 UI가 생겼다고 주장하지 않는다. 위의 **없음**은 기본 전환 전 사람이 검토할 잔여 목록이며, 이전 화면으로 빠져나갈 수 있다는 사실만으로 기능이 완전히 이관됐다고 세지 않는다.

## 기본 화면 전환 점검

- `VOINEY_LAB_NEW_UI=true`와 새 화면 빌드가 함께 있을 때 `/`와 `/index.html`은 `/app/`로 보낸다. 쿼리를 유지하고, 브라우저는 기존 해시를 유지한다.
- `/index.html?legacy=1`은 설정과 관계없이 이전 화면이다. 새 화면이 맡지 않은 상세도 이 주소를 써서 반복 넘김을 막는다.
- 설정을 끄거나 빌드가 없으면 이전 진입 화면과 기존 설치 시작 주소로 돌아간다. 두 화면 파일을 유지한다.
- 이전 루트 화면 설치 manifest의 id `/`를 유지하고, 전환 시 시작 주소 `/app/`, 범위 `/`를 쓴다. 새 manifest의 아이콘은 같은 서버에서 받는다. 기존 새 화면 직접 설치의 id `/app/`는 `/`로 바뀌므로 중복 설치 여부도 실제 기기에서 확인해야 한다.
- 초대 링크의 쿼리와 계정 로그인 API는 그대로다. 로그인 후에도 요청한 기록 주소를 유지한다.
- 앱의 원격 시험 주소를 서버 루트로 정하면 같은 설정으로 새 화면에 도착한다. `mobile/`의 묶음 모드는 아직 정적 이전 `index.html`을 복사하고 원격 API 주소 연결도 완성되지 않았다. 앱 이관 작업이 이를 해결하고 기기에서 검증하기 전에는 **묶음 앱 전환 준비 완료가 아니다**.
- 기본값을 켜는 결정과 배포 환경 변경은 사람이 한다. 자동화 시험은 가짜 기록과 브라우저 흉내이며 실제 실험·기기·음성 검증이 아니다.
