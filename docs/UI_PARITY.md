# 두 화면의 사용자 기능 비교

기준은 `src/voiney_lab/static/index.html`의 정적 제어와 동적으로 그리는 제어, `src/voiney_lab/static/admin-metrics.html`이다. **있음**은 새 화면 안에서 제공, **다르게**는 같은 목적의 다른 흐름 또는 명시적 이전 화면 연결, **없음**은 새 화면 안에 없는 기능이다. 현재 표의 모든 연구자 작업은 새 화면에서 수행할 수 있으며 기본 전환에는 사람 음성 시험이 남아 있다. 이전 화면은 `/index.html?legacy=1`로 계속 열린다. 서버에만 있는 기능을 이전 화면 기능으로 세지 않는다.

초대 발행·계정 끄기와 켜기는 기존에도 화면 기능이 아니라 운영 스크립트였다. 새 화면에 관리 UI가 생겼다고 주장하지 않는다. 이전 화면 링크는 되돌아갈 경로로 남기며, 그 링크 자체를 이관 완료의 근거로 세지 않는다.

## 기본 화면 전환 점검

- `VOINEY_LAB_NEW_UI=true`와 새 화면 빌드가 함께 있을 때 `/`와 `/index.html`은 `/app/`로 보낸다. 쿼리를 유지하고, 브라우저는 기존 해시를 유지한다.
- `/index.html?legacy=1`은 설정과 관계없이 이전 화면이다. 알려지지 않은 주소의 이전 화면 연결과 명시적 되돌리기에만 이 주소를 쓴다. 프로토콜 상세는 새 화면이 맡는다.
- 설정을 끄거나 빌드가 없으면 이전 진입 화면과 기존 설치 시작 주소로 돌아간다. 두 화면 파일을 유지한다.
- 이전 루트 화면 설치 manifest의 id `/`를 유지하고, 전환 시 시작 주소 `/app/`, 범위 `/`를 쓴다. 새 manifest의 아이콘은 같은 서버에서 받는다. 기존 새 화면 직접 설치의 id `/app/`는 `/`로 바뀌므로 중복 설치 여부도 실제 기기에서 확인해야 한다.
- 초대 링크의 쿼리와 계정 로그인 API는 그대로다. 로그인 후에도 요청한 기록 주소를 유지한다.
- 앱의 원격 화면과 묶음 화면도 새 화면을 연다. `mobile/scripts/prepare-web.mjs`는 빌드한 `app/`을 포함하고 `app-bridge.js`를 첫 요청 전에 넣는다. 묶음의 서버 주소·인증 다리가 구현되어 있다. 실제 기기의 HTTPS·로그인·마이크·설치 검증 전에는 **묶음 앱 전환 준비 완료가 아니다**. 웹 화면 걷기만으로 앱 검증을 대신하지 않는다.
- 기본값을 켜는 결정과 배포 환경 변경은 사람이 한다. 자동화 시험은 가짜 기록과 브라우저 흉내이며 실제 실험·기기·음성 검증이 아니다.

## 다른 흐름의 판단 근거

기존 표의 다르게 17행을 각각 판단했다. 기능을 채운 행은 위 표에서 있음으로 바뀌었다.

| 원래 다르게였던 기능 | 판단 | 이유 |
|---|---|---|
| 실험 중 돌아가기 띠 | 유지 | 홈의 돌아가기 카드·실험 탭으로 돌아간다. 실행 화면은 단계와 타이머에 집중한다 |
| 상세의 분석 요약·알림·안전 | 채움 | 시작 흐름 밖에서도 전체 내용을 확인해야 한다 |
| 원문 대조·원본 쪽·그림 | 채움 | 상세 안에서 근거와 원본 쪽을 연다 |
| 재분석·범위·OCR 선택 | 채움 | 실행 가능본도 범위를 다시 고를 수 있어야 한다. OCR 선택은 기존 확인 카드에 있다 |
| 올린 뒤 분석할 쪽 선택 | 유지 | 파일을 등록한 뒤 작은 그림을 보고 골라 범위를 빠뜨리지 않는다 |
