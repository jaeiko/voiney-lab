# 오늘 실험 계획 — 논문을 보고 절차를 바꿔 가며 하는 실험 (설계)

> **상태: 설계만, 구현 전** (2026-10-25, 줄 PLAN). 이 문서에 적은 동작·화면·이름·저장 형태는 아직 코드에 없다.
> 사람이 [10절 "사람이 정할 것"](#10-사람이-정할-것)에 답하고 설계를 승인하면 [9절](#9-구현-단계-나누기)의 줄로 나눠 구현한다.
> 지금 동작은 [`FEATURES.md`](FEATURES.md), 결정과 날짜는 [`DECISIONS.md`](DECISIONS.md), 근거(파일럿 취소와 의견)는
> [`../.agent/product_context.md`](../.agent/product_context.md) 의 Evidence 표다.

## 0. 한눈에

- **무엇**: 올린 원문(논문 Methods·프로토콜·노트 사진·말로 부른 계획)을 분석한 단계 위에, 연구자가 오늘 할 대로 고친 **오늘 실험 계획**을 둔다.
  그 계획으로 실험하고, 실험 중에도 말로 고치고, 실험 노트에 **"논문 원문 → 오늘 실제"**를 남긴다. 다음번에는 **지난번 계획에서 시작**한다.
- **결과물은 프로토콜이 아니라 실험 기록이다.** 연구자가 프로토콜을 따로 쓰지 않는다. 고친 것은 계획에, 한 것은 실험 노트에 남는다.
- **바뀌지 않는 원칙**: 원문에서 온 단계는 원문 인용과 근거 검사 그대로다. 연구자가 쓰거나 바꾼 것은 **"연구자 작성"**으로 표시하고 누가·언제 썼는지
  덧붙이기 장부에 남긴다. 모델은 계획 변경을 **제안**만 하고, 사람이 확인해야 서버가 적용한다. 원문 안전 주의는 지우거나 고칠 수 없다.
  승인 단계는 없다. 상태 기계는 `CuratedProtocolSession` 하나다.
- **권고 데이터 모델**(4절 B안): 계정마다의 **계획 장부**(작업공간 DB 의 덧붙이기만 하는 표)에 고침을 쌓고, 시작은 지금의 "오늘 바꾼 값" 선택 id
  (`run_change_set_id`)로 계획 판을 이름 댄다. 실행 경로는 분석(또는 검토본)에 계획을 적용한 **계획 실행본**을 읽는다.
- **구현**: 서버 세 줄(PLAN1 계획 모델·장부·시작, PLAN2 실행 중 고치기·음성·문제 도움, PLAN3 실험 노트·미리 알아 둘 것) + 화면 한 줄(RX-PLAN, 새 React 화면).

## 1. 왜 — 배경

**파일럿 취소(2026-10-24–25, 메일)**: 파일럿 후보였던 화학 연구실(석사 연구자 1명)이 파일럿을 취소했다. 이유는 선행 논문의 실험 방법을 참고해
연구 목적에 맞게 조건과 **절차**를 수시로 바꾸며 실험하므로, 이 프로그램을 쓰려고 기존 실험 기록 외에 프로토콜을 따로 쓰는 것이 추가 업무라는 것이다.
함께 준 의견은 셋이다.

1. 실험실 안에서 이동이 잦아 **태블릿**에서 쓰고 싶다.
2. "HPLC water" 같은 용어는 실험 전에 미리 아는 정보다. 필요한 것은 **실험 중 생긴 문제와 질문에 대한 전문적인 답**이다.
3. **별도 프로토콜 작성 부담.**

**사람 결정(2026-10-25)**: 목표 연구실은 화학·바이오 웻랩 전체로 유지한다. 정해진 절차를 반복하는 실험뿐 아니라, 논문을 보고 절차 자체를 바꿔 가며
하는 탐색형 실험도 이 제품으로 할 수 있어야 한다.

## 2. 사용자 흐름

### 2.1 세는 법과 기준

- **누름**: 화면을 누르거나 클릭하는 수. 키보드로 친 **글자 하나도 누름 하나**로 센다(장갑과 태블릿에서는 글자가 가장 비싸다). 한글 자판의 실제 누름은
  글자보다 많지만 기준 B 도 같은 규칙으로 세므로 비교는 공정하다. OS 파일 고르기는 1.
- **말**: 연구자가 하는 말의 수. 확인 대답 "네"도 하나로 센다.
- 아래 숫자는 이 설계에서 센 **목표**이고 측정이 아니다. 지금 마법사의 누름은 `docs/USER_GUIDE.md` 3절의 단계에서 센 어림이다
  (내 목소리 2 · 안내 목소리 1 · 프로토콜 2 · 핵심 값 2 · 안전 주의 1 · 오늘 값 1 · 시작 1 ≈ **10**). 구현 줄이 걷기 시험으로 실제 수를 잰다(8.3절).

**기준 장면 S** — 논문 Methods 2쪽(분석하면 12단계), 오늘 고칠 것 7개: 값 2개(시간·온도), 단계 빼기 1, 단계 넣기 1("원심분리 10분"), 순서 바꾸기 1,
문장 고치기 1, 시약 바꾸기 1.

**비교 기준 B — 별도 프로토콜 쓰기**(연구실이 부담이라고 한 것): 문서 편집기로 7곳을 고친 12단계 프로토콜을 친다(단계당 50자로 어림 ≈ 600자),
저장하고 올린다(누름 4), 마법사(누름 10). 합계 **누름 ≈ 614**, 말 0. 단계당 50자는 어림이다 — 연구실의 실제 프로토콜 한 편으로 다시 잰다.

### 2.2 흐름마다

각 흐름은 화면 길과 말 길을 함께 적는다. 말 예시와 대답은 `docs/VOICE_AND_TONE.md` 를 따른 초안이고, 최종 문구는 구현 줄이 COPY_DECK(줄 RX)에 넣는다.

**F1. 논문 PDF·Methods 사진 올리기 → 필요한 부분만 분석** (지금 있음)
- 화면: [올리기] → [파일 고르기] → 파일 → "분석할 쪽" 두 칸(예: 4, 5) → 올리기 단추. **누름 ≈ 6**(글자 2 포함). 사진도 같다.
- 말: 없음(올리기는 화면).
- 바뀌는 것 없음. 분석·근거 검사·확인 카드는 지금 그대로다.

**F2. "오늘 실험 계획" 초안** (새)
- 분석이 통과하거나 검토본이 등록되면 초안은 **분석한 단계 그대로**("원문대로", 고침 0개)다. 따로 만드는 행동이 없다. **누름 0, 말 0.**
- 초안은 프로토콜 상세와 마법사의 "오늘 계획" 단계에 보인다. 계획 장부의 기록은 첫 고침에서 생긴다.
- 확인 카드가 남은 분석(검토 대기)에는 계획을 만들 수 없다(실행할 분석이 아직 없다). 카드는 원문에 맞추기이고 계획은 원문과 다르게 하기라서 섞지 않는다.

**F3. 연구자가 고침 — 시작 전** (새)
- **화면**(계획 화면, 7절): 단계 카드마다 [고치기] → 큰 선택지 [빼기] [값 바꾸기] [문장 고치기] [시약 바꾸기] [뒤에 단계 넣기] [옮기기] → 값·글 입력 → [적용하기].
  고침 하나에 누름 3–4 + 친 글자. 장면 S: 값 2×(3+글자 3) + 빼기 3 + 넣기(3+글자 8) + 옮기기 3 + 문장(3+글자 20) + 시약(4+글자 10) ≈ **누름 66**.
- **말**(음성 연결의 시작 전 단계, D5): 마법사의 **이 프로토콜로 시작** 뒤 첫 인사("…준비되었습니다. 시작할까요, 아니면 먼저 질문하시겠어요?")와
  "시작" 사이에 말로 고친다. 이 단계는 지금도 있고("N단계부터 시작해줘"가 여기서 된다), 같은 상태 기계 안이다.

  ```text
  연구자: 3단계는 빼고 5단계 뒤에 원심분리 10분 넣어 줘.
  보이니 랩: 3단계를 빼고, 5단계 뒤에 '원심분리 10분'을 넣을까요?     (화면: 두 고침을 원문 옆에 보여 준다)
  연구자: 네.
  보이니 랩: 고쳤어요. 되돌리려면 '방금 고친 거 취소'라고 말해 주세요.
  ```

  장면 S: "2단계 시간 20분, 4단계 온도 40도로" · "3단계는 빼고 5단계 뒤에 원심분리 10분 넣어 줘" · "8단계를 6단계 앞으로" · "7단계 TFA 대신 포름산" ·
  "9단계는 '상온에서 밤새 둔다'로 바꿔 줘" — 말 5 + "네" 5 = **말 10, 누름 0**.
- 화면과 말은 같은 계획 장부에 쌓인다. 어느 쪽에서 고쳐도 다른 쪽에 바로 보인다.

**F4. 시작** (지금 마법사 + 한 단계의 내용이 바뀜)
- 마법사의 "오늘 원문과 다르게 할 값" 단계가 **"오늘 계획"** 단계가 된다: 고침이 없으면 "원문대로 해요"와 [원문대로 하기], 있으면
  "바꾼 것 7개 · 뺀 단계 1 · 넣은 단계 1"과 [이 계획으로 하기]·[고치기]. 지금처럼 반드시 지나는 단계이고 누름 1이다.
- 그 앞의 안전 주의 단계에는 기준의 원문 안전 주의가 **모두** 보인다. 계획은 이 목록을 줄이지 못하므로 "읽었어요" 확인은 계획이 바뀌어도 그대로 맞다.
  그때까지 화면에서 뺀 단계의 것은 "뺀 단계(3단계)의 안전 주의"로 표시된다. 연구자 주의는 "오늘 계획" 단계와 실험 중 화면에 "연구자 주의"로 따로 보인다.
- 마지막 단추는 그대로 **이 프로토콜로 시작**(`AGENTS.md` 규칙 5). 시작 전 확인(핵심 값 2문항·안전 확인)은 지금처럼 분석(또는 검토본)에 묶인다(4.5절).
- **누름 ≈ 10**(지금과 같다).

**F5. 실험 중 고침** (새, 말만)

| 말 | 대답 (초안) | 하는 일 |
|---|---|---|
| "7단계 건너뛸게" | "7단계를 건너뛸까요?" → "네" | 뒤 단계 빼기(뺀 단계는 노트에 "실험 중 뺌") |
| "이 단계 건너뛸게" | "지금 5단계를 하지 않고 넘어갈까요?" → "네" | 지금 단계를 "건너뜀"으로 남기고 다음 단계로 |
| "여기서 세척 한 번 더" | "6단계 세척을 지금 단계 뒤에 한 번 더 할까요?" → "네" | 원문 단계를 한 번 더(원문 인용 그대로, 결정은 연구자) |
| "다음에 원심분리 10분 넣을게" | "지금 단계 뒤에 '원심분리 10분'을 넣을까요?" → "네" | 연구자 단계 넣기, 10분 타이머 |
| "8단계 먼저 할게" | "8단계를 다음에 할까요?" → "네" | 뒤 단계끼리 순서 바꾸기 |
| "3단계 15분 대신 20분" | (지금 동작 그대로) | 오늘 바꾼 값(줄 EASY) |

- 지금 단계나 뒤 단계만 고친다. 그 단계 타이머가 돌고 있으면 고치지 않는다(오늘 바꾼 값과 같은 규칙). 끝낸 단계는 고치지 않는다(기록은 지우지 않는다).
- 한 고침에 **말 2(말 + "네"), 누름 0**. 실험 화면에 고치기 단추는 두지 않는다(단계는 말로만 넘기는 원칙 그대로, 7절).

**F6. 실험 노트** (새 표, 5절)
- 실험이 끝나면 지금처럼 장부에서 노트를 만든다. "논문 원문 → 오늘 실제" 표와 바꾼 이유(말한 경우), 다음에 할 일이 들어간다. **추가 누름 0.**

**F7. 다음번 — "지난번 계획에서 시작"** (새)
- 홈 큰 카드(새 화면 홈 표의 새 줄): **지난번 계획으로 시작** · {프로토콜} · 바꾼 것 n개. 누르면 마법사가 핵심 값부터 열리고 "오늘 계획"에 지난번 계획이 채워져 있다.
  카드 1 + 핵심 값 2 + 안전 1 + [이 계획으로 하기] 1 + 시작 1 = **누름 ≈ 6**. 이번에 더 고칠 것은 말(F3)이나 화면.
- "지난번 계획"은 그 사람이 그 프로토콜로 **마지막에 실제로 한 계획**(실험 중 고침까지 반영한 판)이다. 따로 저장하는 행동이 없다(D13).
- 분석이 다시 돌아 기준이 바뀌었으면 "새 분석에 맞춰 다시 맞췄어요. 맞추지 못한 고침 n개"를 보인다(D10).
- 기준 B 로는: 지난 문서를 복사·고치기·다시 올리기(누름 ≥ 4 + 고친 글자) + 마법사 10.

**N1. 원문 없이 — 말로 계획 부르기** (새)
- 올리기 화면의 [말로 계획 만들기] → 단계마다 [말하기]를 누르고 한 단계를 말한다 → 받아 적은 글이 단계 목록으로 보이고 칸에서 고칠 수 있다 →
  [이대로 올리기]. 8단계: **누름 ≈ 10, 말 8**, 글자 0(고칠 때만).
- [이대로 올리기]를 누르면 그 글이 **연구자가 말로 쓴 원문**으로 등록된다(바뀌지 않는 원문 바이트, 출처 "연구자가 말한 계획"). 그 뒤는 F2 와 같은 분석·근거 검사다.
  그래서 단계는 모두 그 글의 인용이고, 모델은 그 글에 없는 것을 넣을 수 없다(D8).
- 이 받아 적기는 음성 연결 밖의 새 STT 경로라 사람이 정한다(D5). 정하지 않으면 N1 은 같은 화면에 글로 치거나 노트 사진(N2)으로 한다.
- 받아 적는 말도 응급 관문을 먼저 지난다("불났어요"에는 정해진 응급 안내). 원문 안전 주의는 없으므로 마법사의 안전 단계는
  "이 원문에는 안전 주의가 없어요. 연구실 안전 자료를 확인해 주세요."(안전 문장이라 사람이 문구를 정한다)와 연구자 주의를 보인다.

**N2. 원문 없이 — 손글씨·노트 사진**
- F1 의 사진 올리기 그대로다(두 OCR 엔진 비교 → 분석 → 확인 카드). 출처 표시는 "노트 사진"이다. 손글씨에서 OCR 이 얼마나 맞는지는 잰 적이 없다
  (확인 안 됨, 8.3절 평가에 넣는다).

## 3. 권한과 근거 규칙

`AGENTS.md` 규칙 1(지어내지 않음)·2(모델은 제안만)·4(권한 하나씩)·5(승인 없음)와 맞춘다.

1. **출처는 셋뿐이다.** ① **원문** — 원문 인용, 근거 검사 통과, 쪽 번호. ② **연구자 작성** — 사람이 화면에 쓰거나 말해서 확인한 글과 값.
   누가(계정)·언제·어디로(화면·말)·어느 계획 고침인지 장부에 남는다. ③ **오늘 바꾼 값** — ②의 한 종류(줄 EASY 의 `RunChange`), 원문 값을 같은 단위 종류로 바꾼 것.
   "AI 제안"은 실행되는 어떤 것의 출처도 아니다. 모델의 제안은 사람이 확인한 뒤에야 ②가 되고, 그 글은 사람이 한 말이어야 한다(아래 4).
2. **원문 단계는 그대로다.** 분석과 검토본은 바뀌지 않는 기록이고 계획은 그것을 고치지 않는다. 문장을 고친 원문 단계는 원래 문장이 늘 함께 보인다
   ("원문: …"), 새 문장은 "연구자 작성"이다.
3. **연구자 작성은 늘 그렇게 보이고 들린다.** 화면은 글자 이름표 "연구자 작성"과 테두리(색만으로 구분하지 않음), 단계에 올 때 한 번
   "이 단계는 연구자가 넣은 단계예요." / "오늘 고친 문장이에요."라고 말한다. "원문 · p.N" 표시는 연구자 작성에 절대 붙지 않는다.
4. **모델은 제안만 한다.** 계획 고침은 말 한 번의 한 줄(`AGENTS.md` 규칙 3)로 읽는다: 응급 관문 → 앞단 규칙 `plan_edit`(결정적) → (켜져 있고 규칙이 못 읽을 때만)
   라우터의 제안(D3) → 서버 검사 → 되읽기 → 사람의 "네" 또는 [적용하기] → 적용. 서버 검사: 정해진 고침 종류만, 가리킨 단계가 있고 지금·뒤 단계일 것,
   넣거나 고친 글은 그 말 안의 글일 것(명령 낱말을 뺀 나머지와 대조), 글 속 숫자·단위는 그 말에 있는 것만, 안전 주의와 완료 기준은 고침 대상이 아님,
   말 한 번에 고침 4개까지. 질문·추측("3단계 빼도 될까?")은 고치지 않는다(`intent_fences.is_question_or_speculation` 그대로).
5. **원문 안전 주의는 지우거나 고칠 수 없다.** 단계를 빼도 그 단계의 안전 주의는 안전 목록·실험 중 안전 보기·노트에 남는다("뺀 단계의 안전 주의").
   문장을 고치거나 시약을 바꾼 단계에도 원문 안전 주의가 그대로 붙어 있다. 연구자는 **자기 주의**를 더할 수 있고 "연구자 주의 — {계정 이름} · {날짜}"로
   보인다(원문·기관 자료처럼 보이지 않는다). 바꾼 시약에는 "바꾼 시약은 원문 안전 주의가 없어요. 연구실 안전 자료를 확인해 주세요."가 붙는다
   (새 안전 문장이므로 사람이 문구를 정한다, `docs/VOICE_AND_TONE.md` 규칙 8).
6. **모델이 지어내지 않는다.** 값·시간·안전 문장·완료 기준을 모델이 쓰지 않는다. 연구자 단계의 타이머는 연구자의 말에 있는 시간만이다
   (검토본의 "검토자 입력" 타이머와 같은 방식, `protocol_catalog.py` `_with_reviewer_timers`). 연구자 단계에는 완료 기준이 없고 사람의 말("다음")로 끝난다.
7. **상태 기계는 하나다.** 계획은 실행에 들어가는 입력이다. 실험의 단계 순서는 계획 실행본이고, 실행 중 고침은 `CuratedProtocolSession` 의 전이 하나
   (`adopt_plan_version`, 4.5절)와 장부 사건이다. 두 번째 상태 기계·두 번째 `ExperimentSession` 권한·따로 판정하는 길·두 번째 프로토콜 저장소를 만들지 않는다.
   계획 장부는 고침을 담을 뿐 프로토콜을 담지 않는다(프로토콜 기록은 분석 하나다).
8. **승인이 없다.** 계획은 승인을 받지 않는다. 실행할 수 있는지는 지금 규칙(분석이나 검토본이 실행 가능, `available_for_execution`) + 계획 검사 통과이고,
   시작은 **이 프로토콜로 시작**이다. 관리자의 "확인함"은 계획과 상관없다.
9. **남의 계획은 쓰지 못한다.** 계획을 고치는 것은 주인 계정뿐이다. 읽기는 D7. 다른 연구실 계획은 없는 것처럼(404) 응답한다.
   시작은 다른 계정의 계획을 이름 대면 거절한다(지금의 `run_changes_stale` 과 같은 규칙).
10. **개인정보.** 계획의 글(연구자가 쓴 말)은 연구 자료다. 로그·파일럿 지표에는 개수·종류 코드·시각만 남긴다. 계정 지우기는 그 계정의 계획을 지운다(4.4절).

## 4. 데이터 모델

### 4.1 개념

| 이름 | 무엇 | 바뀌나 |
|---|---|---|
| **계획**(run plan) | 한 계정이 한 프로토콜로 하는 실험의 계획. `plan_id`, 주인 계정, 연구실, **기준**(프로토콜 id, 원문 리비전, 실행할 분석 또는 검토본 — 지금 `StartTarget` 의 대상 키), 이어받은 계획(지난번 계획에서 시작했으면) | 만들 때 정해짐 |
| **고침**(plan edit) | 계획 장부의 사건 하나. 아래 표의 종류 중 하나 + 대상 + 내용 + 작성자·시각·화면/말·말한 이유(있으면). 말 한 번의 고침 여러 개는 한 사건 | 덧붙이기만 |

| **계획 실행본** | 기준 분석(또는 검토본)에서 만든 실행본(`CuratedProtocolFixture`)에 계획 판을 적용한 실행본. 같은 입력이면 늘 같은 결과(결정적). 리비전 id 는 기준 id 에 계획 판을 붙인 것(예: `pdf-1-analysis-2+plan-…-v7`) | 바뀌지 않음 |

**고침의 종류** (닫힌 목록):

| 종류 | 무엇 | 대상 | 보이는 출처 | 시작 전 | 실험 중 |
|---|---|---|---|---|---|
| `change_value` | 원문 값 대신 오늘 값 — 줄 EASY 의 `RunChange` 그대로(같은 단위 종류, 절반 미만·2배 초과는 한 번 더 확인) | 원문 단계의 바꿀 수 있는 값(`start_check.changeable_values`) | 오늘 바꾼 값 · 원문 X | 됨 | 됨(지금 동작) |
| `remove_step` | 단계 빼기. 뺀 단계와 그 안전 주의는 보이게 남는다 | 원문·연구자 단계 | 뺌 | 됨 | 뒤 단계만 |
| `skip_current` | 지금 단계를 하지 않고 넘어가기 | 지금 단계 | 건너뜀 | — | 됨 |
| `add_step` | 연구자 단계 넣기. 글은 연구자의 말·글(1–200자), 시간이 있으면 그 시간의 타이머 | 위치(어느 단계 뒤) | 연구자 작성 | 됨 | 지금 단계 뒤부터 |
| `repeat_step` | 원문 단계를 한 번 더. 글은 원문 인용 그대로 | 원문 단계 + 위치 | 원문 · 한 번 더(연구자 결정) | 됨 | 지금 단계 뒤부터 |
| `move_step` | 순서 바꾸기 | 단계 + 위치 | 순서 바뀜 · 원문 N단계 | 됨 | 뒤 단계끼리 |
| `reword_step` | 원문 단계 문장 고치기. 원문 문장은 늘 함께 보임. 고친 문장에서 원문 숫자가 바뀌면 그 값은 `change_value` 와 같은 확인을 받는다 | 원문 단계 | 오늘 고친 문장 · 연구자 작성 | 됨 | 안 됨(v1) |
| `substitute_material` | 시약 바꾸기. 원래 이름은 그 단계 원문(또는 재료 목록)에 있어야 하고, 양은 그대로(바꾸려면 `change_value`) | 단계 안 재료 이름 | 바꾼 시약 · 연구자 작성 | 됨 | 안 됨(v1) |
| `add_caution` | 연구자 주의 더하기 | 단계 | 연구자 주의 | 됨 | 안 됨(v1, 실험 중에는 지금의 "메모해 줘") |
| `revert` | 앞의 고침 하나 되돌리기(새 사건) | 고침 | — | 됨 | 됨 |

고침끼리: 같은 대상의 나중 고침이 앞 고침을 덮는다(둘 다 장부에 남는다). 뺀 단계에 걸린 값·문장·시약 고침은 장부에 남지만 적용되지 않고
(노트에 "뺀 단계라 쓰지 않음"), 빼기를 되돌리면 다시 적용된다.

나중 후보(v1 밖): 한 원문 단계를 두 단계로 나누기(나눈 조각이 모두 원문 글의 연속 구간이면 원문 근거를 지킬 수 있다 — 논문의 긴 문단 단계에 쓸모).

**단계 이름(번호)** — D2 권고: 원문 단계는 **원문 번호를 그대로** 쓰고(순서가 바뀌면 "1, 2, 4, 5, 추가 1, 6…"처럼 번호가 차례가 아니어도 된다),
넣은 단계는 "추가 1", "추가 2", 한 번 더 하는 단계는 "6단계(한 번 더)"다. 논문을 옆에 두고 일하는 연구자에게 원문 번호가 공통 말이고,
지금 코드의 단계 찾기(`_step_index_for_label`)와 "2단계: 2 Prepare …" 같은 원문 인용이 그대로 맞는다.

**연구자 단계의 근거 형태**: 원문 근거(`SourceEvidence`)와 **다른 타입**인 작성자 근거(가칭 `AuthoredEvidence`: 계정·시각·고침 사건 id·글)를 둔다.
어떤 코드도 연구자 글을 원문 인용으로 착각하지 못하게 하기 위해서다. 분석과 검토본의 검사(`experiment_protocol.validate_protocol`)는 지금처럼
원문 근거만 받고, 계획 실행본 검사가 계획 고침에 적힌 단계에만 작성자 근거를 허락한다. 실행 경로에서 근거를 읽는 곳
(`curated_protocol.py` 34줄, `knowledge.py` 4줄, `server.py` 5줄, `report_projection.py` 1줄 — 2026-10-25 dev `0d18d2b` 에서 `.evidence.` 가 든 줄을 셈)은
작성자 근거를 따로 다룬다.

### 4.2 어디에 둘까 — 선택지

**A안 — 프로토콜 카탈로그 장부(`protocol_workspace.sqlite`)의 사건으로.** 오늘 바꾼 값(`protocol_run_changes_chosen`)처럼 계획 고침을 카탈로그 사건으로 쌓는다.
- 장점: 분석·검토본·오늘 바꾼 값·시작 확인과 같은 곳이라 식별자 맞추기가 쉽다. 새 저장소가 없다.
- 단점: 카탈로그는 **연구실이 함께 쓰는** 곳이다. 연구자가 쓴 글이 연구실 장부에 남고, 계정 지우기는 카탈로그에서 이름만 바꾸므로(`docs/PILOT_GUIDE.md` 7-7)
  계정을 지워도 그 사람의 글이 남는다 — 지우려면 덧붙이기만 하는 장부의 예외를 새로 만들어야 한다. 덧붙이기는 코드로만 지킨다(트리거 없음).

**B안 (권고) — 작업공간 DB(`commercial_workspace.sqlite`)의 계정별 계획 장부.** 새 표 하나(가칭 `run_plan_events`, 스키마 11 → 12), 실험 사건 표처럼
SQL 트리거로 고치기·지우기를 막는다. 행마다 연구실·주인 계정·계획 id·기준 식별자·순번·종류·내용(JSON)·내용 해시·시각.
시작은 지금의 "오늘 계획" 선택 사건(카탈로그의 `protocol_run_changes_chosen`)에 **계획 판 참조**(계획 id·순번·해시, 글 없음)를 더해 이름 댄다.
- 장점: 계정 범위가 저장 위치와 같다(남의 계획 쓰기 금지, 기록 권한 표와 같은 판단). 트리거로 덧붙이기를 지킨다. 계정 지우기는 표 하나를 범위에 더하면 된다.
  카탈로그에는 숫자와 참조만 남는다. 백업은 작업공간 폴더 그대로. 시작 계약(`session.start` 의 `run_change_set_id`)이 바뀌지 않는다.
- 단점: 저장소 두 곳(카탈로그 기준 + 작업공간 계획)을 정확한 식별자로 잇고, 하나가 없으면 닫힌다(지금도 실험 세션이 그렇다). 작업공간을 끈 배치
  (`VOINEY_LAB_WORKSPACE_ENABLED=false`)에서는 계획이 없다 — 설정 이름을 대며 "오늘 계획"이 지금의 "오늘 바꾼 값"만 보인다. 파일럿(계정 모드)은 작업공간이 필수라 영향이 없다.
  스키마 이전 한 번(`docs/MIGRATION_NOTES.md` 에 기록, 되돌리기는 이전 전 백업).

**C안 (권하지 않음) — 검토본처럼 계획을 새 분석 리비전으로.** 계획을 적용한 프로토콜 전체를 카탈로그의 분석 리비전으로 저장하고 실행 경로가 그것을 읽는다.
- 장점: 실행 경로가 지금처럼 분석 리비전 하나만 읽는다.
- 단점: 모든 기록이 원문 근거를 가져야 하는 분석 검사를 풀어야 연구자 단계가 들어간다. 연구실 목록에서 "최신 판이 실행된다"는 검토본 규칙과 섞여 **연구실 전체의
  실행본**이 되고, 사실상 지운 연구실 변형과 같아진다. 두 번째 프로토콜 저장 방식이 생긴다.

**권고: B안.** 계획은 한 사람의 실험 입력이므로 계정 범위의 저장소에 두고, 카탈로그에는 시작에 필요한 숫자·참조만 둔다.
옛 `protocol_adaptation_revisions` 표는 쓰지 않는다(줄 DI 결정: 쓰는 코드 없음 그대로).

### 4.3 지금 있는 것과의 관계

| 지금 있는 것 | 관계 |
|---|---|
| **검토본**(확인 카드 → v1, v2 …) | 검토본은 분석을 **원문에 맞추는** 연구실 전체의 기록이다. 계획은 **원문과 다르게 하는** 한 사람의 고침이다. 계획의 기준은 분석이거나 검토본이다. 새 검토본이 등록되거나 다시 분석해 기준이 바뀌면, 그 기준의 계획은 "다시 맞추기"가 필요하다(D10). |
| **오늘 바꾼 값**(`RunChanges`, 줄 EASY) | `change_value` 고침이 곧 `RunChange` 다(같은 검사·같은 큰 값 확인). 마법사의 "오늘 계획"을 지나면 지금처럼 `protocol_run_changes_chosen` 이 남고, 그 `changes` 는 계획의 값 고침, 새 칸 `run_plan` 은 계획 판 참조다. 시작·이미 쓴 선택·남의 선택 거절·`protocol_run_changes_applied`·복구가 그대로 돈다. 실험 중 값 바꾸기(`run_value_changed`·`run_value_reverted`)도 그대로다. |
| **지난번처럼**(`ExperimentReportStore.last_run_values`) | "지난번 계획에서 시작"이 이것을 넓힌다. 계획이 없던 옛 기록에서는 지금처럼 값만 다시 고른다. |
| **"N단계부터 시작해줘"**, 조건 분기 건너뛰기 | 그대로 둔다. 계획의 빼기·건너뛰기는 그것과 다른 사건이고(노트에 "뺌"·"건너뜀"), 분기 건너뛰기("조건에 해당하지 않아 건너뜀")와 섞지 않는다. |

### 4.4 저장과 옛 기록

- 계획 장부 사건 종류(가칭): `plan_created`(기준·이어받은 계획), `plan_edited`(고침 1–4개), `plan_used`(어느 실험이 어느 판으로 시작·전환했는지).
- 지금 있는 사건(`session_started`, `run_value_changed`, `protocol_run_changes_chosen` …)의 모양은 바꾸지 않고, 새 사건과 새 칸만 더한다(`AGENTS.md` 규칙 9).
- 옛 기록: 계획이 없는 실험은 지금처럼 읽는다(노트도 지금 모양). 스키마 11 의 DB 는 표를 더하는 이전만 하고 데이터는 바꾸지 않는다.
- 계정 지우기: 계획 장부를 `accounts.py` 의 계정 범위 표(`ACCOUNT_WORKSPACE_TABLES`)에 더한다. 카탈로그의 선택 사건에는 글이 없으므로 지금 범위 그대로다.
- 백업: 작업공간 폴더 그대로(`scripts/pilot_state_backup.py`).

### 4.5 실행 경로가 계획을 읽는 법

1. **마법사 "오늘 계획"**: 서버가 기준(실행할 분석·검토본), 그 사람의 초안 계획(또는 지난번 계획), 바꿀 수 있는 값을 준다(지금의 `start-check/changes` 를 넓힘).
   [이 계획으로 하기]는 계획 판을 고른다 → 서버가 계획 실행본을 만들어 검사(아래)하고, 통과하면 선택 사건을 남기고 선택 id 를 준다.
2. **시작**: `session.start` 가 지금처럼 `run_change_set_id` 를 보낸다 → 서버가 선택 사건에서 계획 판 참조를 읽고 계획 실행본을 만들어 해시를 대조한 뒤
   그 실행본으로 세션을 연다. 시작 전 확인(핵심 값·안전 확인)은 **기준**에 묶인 지금 규칙 그대로다 — 계획은 원문 값과 원문 안전 주의를 지우지 못하므로
   기준에 대한 확인이 계획에도 그대로 맞는다.
3. **계획 실행본 검사**: 고침마다 대상이 기준에 있는지, 원문 안전 주의가 모두 남았는지, 남은 단계가 하나 이상인지, 연구자 단계만 작성자 근거인지, 값 고침이
   `check_run_change` 를 통과하는지. 하나라도 어긋나면 시작하지 않고 이유를 말한다.
4. **기록**: 실험 기록 `session_started` 에 `run_plan`(계획 id·판·고침 요약 — 글 포함, 기록 권한 그대로)을, 작업공간 세션의 리비전 id 에 계획 실행본 id 를 남긴다.
5. **실행 중 고침**: `CuratedProtocolSession.adopt_plan_version(새 실행본)` — 상태 기계의 전이 하나. 조건: 같은 기준, **지금 단계까지(끝낸 단계와 지금 단계)의 단계가
   같은 id·같은 글**, 바뀌는 단계에 타이머가 돌지 않음, 그 고침의 확인 질문 말고 다른 서버 질문이 열려 있지 않음. 통과하면 실행본만 바꾸고 `current_index` 와
   끝낸 기록은 그대로다(고침은 뒤 단계에만 닿으므로). 새 계획 판이 장부에 남고, 실험 기록·작업공간 타임라인에 `run_plan_changed`(판 참조) 사건이 남는다.
   체크포인트에 계획 판 id 를 더한다(오늘 바꾼 값의 체크포인트 칸과 같은 방식; 세션에 잠금·DB 연결을 두지 않는다).
   **지금 단계 건너뛰기**(`skip_current`)만 지금 단계에 닿는다: 이것은 완료와 같은 자리의 전이(지금 단계를 "건너뜀"으로 남기고 다음 단계로)이고, 계획 판에도 기록된다.
6. **복구**: 연결 복구는 실험의 마지막 `run_plan_changed`(없으면 시작 판)로 계획 실행본을 다시 만든다(`load_fixture_for_revision` 이 계획 실행본 id 를 읽게 넓힘).
7. **시작 전 말로 고치기**: 시작 전 단계의 세션에서도 같은 `adopt_plan_version` 이다(끝낸 단계가 없으므로 언제나 조건을 만족한다).

### 4.6 지난 기록 · 문제 도움과의 연결

- 계획의 원문 단계는 원문 단계 id 를 그대로 쓰고, 넣은 단계는 계획 계보 안에서 바뀌지 않는 id(예: 같은 계획에서 이어받은 판끼리 같은 "추가 1")를 쓴다.
  그래서 줄 HELP 의 지난 기록 층(`HistoryKnowledge`, 같은 프로토콜·연구실·주인)이 같은 단계의 지난 이상 사항을 찾는다.
- `knowledge.ProtocolKnowledge` 는 원문 사실만 색인한다. 연구자 글은 "원문"으로 보이면 안 되므로 그 색인에 넣지 않는다(6.2절에서 따로 다룸).
- 문제 도움의 맥락(`KnowledgeContext`)에 계획 단계의 종류(원문·고친 문장·연구자 작성·한 번 더)를 더한다.

## 5. 실험 노트

목표는 **연구실의 기존 실험 기록을 대신할 수 있는 모양**이다. 연구자가 프로토콜을 따로 쓰지 않는 대신, 이 노트가 그날의 실험 기록이 된다.
지금의 실험 노트(8개 절, `experiment_reports.NOTEBOOK_SECTIONS`)의 절 이름과 차례는 바꾸지 않고, 계획으로 한 실험에서만 내용을 더한다.

**머리 줄**: 날짜 · 제목(말한 목적) · 실험자 · **원문**: 제목 · 분석한 쪽 · DOI(원문에 있을 때만) · **계획**: 고침 n개(실험 중 m개) · 기준(분석 또는 확인한 버전).

**"2. 실제로 한 조건"에 단계 표 — 논문 원문 → 오늘 실제** (예시):

| 오늘 순서 | 논문 원문 (쪽 · 번호) | 오늘 계획 | 실제 | 이유 (말한 대로) |
|---|---|---|---|---|
| 1 | p.4 · 1 "Lyse cells in 200 µL RIPA buffer." | 원문대로 | 10:02 끝 | |
| 2 | p.4 · 2 "Incubate for 15 min on ice." | 시간 15 min → 20분 (오늘 바꾼 값) | 20분 타이머 · 10:24 끝 | "세포가 많아서" |
| — | p.4 · 3 "Wash twice with PBS." | 뺌 | 하지 않음 | |
| 3 | p.5 · 5 "Centrifuge at 12,000 ×g …" | 순서 바뀜 (원문 5 → 오늘 3번째) | 10:30 끝 | |
| 추가 1 | (원문 없음) | "원심분리 10분" · 연구자 작성 ({계정 이름} · 10/25 09:40 · 말) | 10분 타이머 · 10:41 끝 | |
| 6 | p.5 · 6 "Wash with 50 mM ABC." | 원문대로 | 10:45 끝 | |
| 6 (한 번 더) | p.5 · 6 (같은 원문) | 한 번 더 · 실험 중 10:46 고침 | 10:51 끝 | "아직 파래서" |
| 7 | p.5 · 7 "… in 0.1% TFA." | 시약 바꿈: TFA → 포름산 · 연구자 작성 | 기록 "포름산 0.1%" | |

- 숫자와 시각은 모두 장부에서 서버가 만든다(지금 노트와 같다). 원문 칸은 원문 인용 그대로, 연구자 작성은 그 표시와 작성자·시각·화면/말을 함께 둔다.
- **이유**는 연구자가 말하거나 적은 것만이다(고치는 말 속의 "…해서·…라서·…때문에" 구절, 또는 화면의 "이유(선택)" 칸). AI 가 이유를 짐작해 쓰지 않는다.
- **"4. 원문과 다르게 한 점·문제"**: 고침마다 한 줄(뺀 단계, 넣은 단계, 순서, 문장, 시약, 값)과 이유, 그리고 지금처럼 이상 사항·문제 도움 줄.
  뺀 단계의 원문 안전 주의는 "뺀 단계의 안전 주의"로 여기에도 남는다.
- **"5. 지난번과 다른 점"**: 지난번 실험의 계획 판과 오늘 판의 차이(고침 단위).
- **"6. 다음에 바꿀 점·다음 할 일"**: 끝 질문의 답(지금 그대로) + "다음에 이 계획에서 시작하면: 오늘 실제로 한 계획(실험 중 고침 포함)이 지난번 계획이 돼요."
- **"8. 부록"**: 계획 고침 기록(순번·종류·작성자·시각·화면/말), 원문 안전 주의 전체(뺀 단계의 것 포함), 연구자 주의.
- 내보내기는 지금 형식 그대로(Word·Markdown·JSON·CSV, 서버의 PDF). 연구실의 실제 기록 양식은 받지 못했다(확인 안 됨) — 파일럿 연구실 양식을 받아
  머리 줄·절 이름을 맞출지 사람이 정한다(9절 PLAN3).

## 6. 실험 전 준비와 실험 중 도움

### 6.1 "미리 알아 둘 것" (의견 2)

의견 2는 "용어는 실험 전에 아는 정보이고, 실험 중에는 문제와 질문에 대한 답이 필요하다"는 것이다. 그래서 용어·시약 설명은 **실험 전 화면에서만**
보이고, 실험 중 음성은 문제와 질문에 쓴다.

- **범위**: 계획에 나오는 시약·재료(원문 재료 목록, 계획 단계 글 속 이름, **바꾼 시약**), 장비(원문 장비와 설정), 용어(공개 자료 용어집이 아는 낱말).
- **한 항목에 보이는 것**: 이름 · 쓰는 단계 · ① 원문(그 이름이 나오는 원문 노트·주의·참고 줄, 쪽과 함께) · ② 내 지난 기록(그 단계들의 이상 사항·관찰) ·
  ③ "공개 자료 · 일반 참고 — {출처}"(줄 KNOW 의 공개 자료 등급, 그 낱말을 함께 가진 조각만, 두 개까지, [F20](FEATURES.md#f20-공개-자료-검색-moss)의 답의 규칙 그대로).
  바꾼 시약은 "원문에 없는 시약 · 원문 안전 주의 없음"과 3절 5의 고정 문장. 모델이 쓴 설명은 없다 — 보조 설명을 켠 서버에서만 지금의
  "AI 일반 지식"(120자, 숫자·방법·안전 금지) 꼴로 붙는다.
- **차례와 수**: 바꾼 시약·넣은 단계에 나오는 것 → 원문 주의가 있는 것 → 나머지, 12개까지. 이름 말고 보일 것이 없는 항목은 뺀다.
- **시점**: 계획 초안이 생길 때와 시작 전 고침마다 다시 만든다(서버 안 검색, 줄 HELP 의 `search_tiers` 처럼 등급마다 시간 한도, 늦은 등급만 빠짐).
  계획 화면의 접힌 묶음과 마법사 "오늘 계획" 단계의 "미리 알아 둘 것 n개 · 보기"로 보인다. **누를 필요는 없다(추가 누름 0).** 실험 중에는 말하지 않는다.
- 상태를 바꾸지 않고, 계획 장부에 쓰지 않는다(보기만 해요).

### 6.2 실험 중 문제 도움 — 바꾼 계획에 붙는 법

문제 도움은 줄 HELP·KNOW 그대로 쓰고(① 원문 → ② 지난 기록 → ③ 공개 자료 → ④ 닫는 말), 계획 단계의 종류에 따라 ①②만 달라진다.

| 지금 단계 | ① 원문 | ② 지난 기록 | 말로 덧붙이는 것 |
|---|---|---|---|
| 원문 단계 (그대로) | 지금처럼 단계 ± 1, 단원의 노트·주의 | 지금처럼 | — |
| 문장을 고친 원문 단계 | 원래 원문 문장과 그 이웃("원문 · p.5 · 6단계 · 오늘은 고쳐서 함") | 같은 단계 id | "이 단계는 오늘 고친 단계예요." |
| 한 번 더 하는 원문 단계 | 그 원문 단계 그대로 | 같은 원문 단계 | — |
| 연구자 단계 | 그 단계에는 원문이 없다. 단계 글의 낱말로 **원문 전체**에서 찾은 줄을 "원문의 관련 줄"로 | 같은 계획 계보의 같은 "추가 N" 단계 | "연구자가 넣은 단계라 원문에는 이 단계가 없어요." |
| 시약을 바꾼 단계 | 원래 시약 기준의 원문 줄("원문은 TFA 기준이에요") | 같은 단계 id | — |

- ③ 공개 자료는 문제의 말 + 단계 글(바꾼 시약 이름 포함)의 낱말로 찾는다. 고정 문장·검사(`problem_help_violations`, `public_reference_violations`)는 그대로다.
- 연구자 글은 ①의 "원문"으로 절대 보이거나 들리지 않는다.
- **질문에 대한 전문적인 답**(의견 2의 나머지 절반, 예: "왜 여기서 EDTA 를 넣어?")은 지금 원문 답 + "AI 일반 지식"(켰을 때)이다. 문제 도움의 층 짜기를
  질문에도 쓰는 것은 이 설계 밖의 다음 일로 남긴다(10절 D11).

## 7. 태블릿 (의견 1)

새 화면 설계 docs/UI_SPEC.md(줄 RX0, PR #128 — 이 문서를 쓸 때 dev 에 아직 없음)와 맞춘다: 2절 원칙(한 화면에 가장 중요한 행동 하나, 근거 종류를 글자와 테두리로,
서버가 주지 않은 숫자는 안 보임), 6절 토큰(`--target` 44 px, `--target-glove` 80 px, `--gap-glove` 24 px, 근거 색 `--source`·`--ai`·`--public`·`--warning-*`),
4.6절 확인 화면(원문 쪽 그림 + 카드 하나), 4.7절 시작 흐름, 4.8절 실험 중 화면.

**원칙**

1. **계획은 대개 장갑 전, 책상에서 고친다.** 그래서 계획 화면에서는 글을 칠 수 있다. 실험 중 고침은 **말로만** 하고 실험 화면에 고치기 단추를 두지 않는다
   (UI_SPEC 4.8의 큰 [멈추기] 하나 원칙과 "단계는 말로만 넘긴다"를 지킨다).
2. **한 화면에 큰 행동 하나**: 계획 화면은 [이 계획으로 하기], 단계 카드마다 [고치기] 하나.
3. **끌기·밀기·길게 누르기를 쓰지 않는다**(장갑·젖은 손가락). 옮기기는 "어디로 옮길까요?"의 큰 줄 목록에서 고른다.
4. **크기**: 모든 단추 44 px 이상, 고치기 시트의 선택지와 주 단추는 80 px·간격 24 px.
5. **출처 표시는 글자 + 테두리**: "원문"(`--source`), "연구자 작성"(새 이름표 — 새 뜻 색을 늘리지 않고 먹색 점선 테두리 + 글자를 권한다, 줄 RX 가 정함),
   "뺌"(줄 긋기 + 글자 "뺌", 글은 읽히게), "주의"(`--warning-*`).
6. **원문 옆에서**: 가로 태블릿은 왼쪽에 원문 쪽 그림(그 단계 줄에 띠 — 줄 상자 API 전에는 UI_SPEC 4.6처럼 "어림 위치"), 오른쪽에 단계 카드 목록. 세로·휴대폰은 위아래.
7. **되돌리기가 늘 보인다**: [되돌리기] 옆에 마지막 고침 이름("3단계 빼기 되돌리기").
8. **네 상태**(UI_SPEC 4절): 불러오는 중 "계획을 불러오는 중…" · 비어 있음(고침 없음) "원문대로 해요. 고칠 단계의 [고치기]를 눌러 주세요." ·
   오류 "계획을 불러오지 못했어요. [다시 불러오기]" · 정상 = 카드 목록.
9. **실험 화면**: 단계 카드에 출처 줄("연구자 작성 · 원문 없음", "원문 5단계 · 순서 바뀜")을 1.5 m 읽기 단계 글 아래 보조 줄로, 다음 단계 미리보기도 계획 차례로
   ("다음: 추가 1 — 원심분리 10분").

## 8. 위험과 막을 장치

### 8.1 위험 표

| 위험 | 막는 장치 | 지키는 시험(구현 줄) |
|---|---|---|
| 잘못 들은 말로 계획이 바뀜 | 구조 고침(빼기·넣기·옮기기·문장·시약·한 번 더·건너뛰기)은 **수치 확인 방식과 상관없이 늘 먼저 묻고** "네"에만 적용(D4). 값 고침은 줄 EASY 그대로(방식대로 + 절반 미만·2배 초과·0 °C 이하는 늘 묻기). 문장을 고쳐 원문 숫자가 바뀌어도 같은 큰 값 확인. 넣는 단계의 숫자는 되읽을 때 소리로 읽고(지금의 소수점 다시 묻기 규칙 그대로). 말 한 번에 고침 4개까지. "방금 고친 거 취소"로 한 번에 되돌림 | 평가 세트의 잘못 들은 말 변형(삼↔사, 칠↔일, 십↔십오, "단계" 빠짐), 확인 없이 적용된 구조 고침 0 |
| 단계 번호를 잘못 들음 | 되읽기에 단계의 첫 낱말 몇 개를 붙이고(예: "3단계 세척을"), 화면이 원문 옆에 고침을 보인다 | 되읽기 문구 시험, 걷기 시험 |
| 질문·추측이 고침이 됨 | `intent_fences.is_question_or_speculation` 그대로, "빼도 될까?"·"넣으면 어떨까"는 고치지 않음 | 평가 세트의 질문·가정 줄 |
| 모델이 단계·값을 지어냄 | 넣거나 고친 글은 말 안의 글, 숫자는 말 속 숫자만, 정해진 고침 종류만, 안전 주의·완료 기준은 대상 아님. 모델이 늦거나 틀리면 같은 말의 규칙 길(되묻기) | 제안 검사 시험(가짜 공급자) |
| 원문 근거 없는 단계가 원문처럼 보임 | 작성자 근거는 원문 근거와 다른 타입, "원문 · p.N" 은 작성자 근거에 못 붙음, 단계에 올 때 한 번 말함 | 모든 표시·노트·도움 경로에서 작성자 근거가 "원문"으로 나오지 않는지 |
| 원문 안전 주의가 사라짐 | 뺀 단계의 주의도 안전 목록·실험 중 안전 보기·노트에 남음, 계획 실행본 검사가 원문 주의 개수를 대조 | 빼기·문장·시약 고침 뒤 원문 주의 목록이 같은지 |
| 바꾼 시약·넣은 단계의 위험 | 원문 안전 주의 없음 표시와 고정 문장, 연구자 주의, 공개 자료는 "일반 참고"로만. 안전 판단을 하지 않음(응급 관문은 그대로) | 표시 시험, 금지 문장 검사 |
| 남의 계획을 씀 | 주인만 고침, 읽기는 D7, 다른 연구실은 404, 시작은 남의 계획 거절 | 권한 표 시험(두 계정·두 연구실) |
| 분석이 바뀌어 계획이 낡음 | 기준이 다르면 시작 거절 + "다시 맞추기"(D10) | 다시 분석 뒤 시작 시험 |
| 실행 중 고침이 끝낸 단계나 돌고 있는 타이머를 건드림 | `adopt_plan_version` 의 앞부분 같음·타이머·열린 질문 조건 | 상태 기계 시험, 체크포인트 같음 |
| 연결이 끊긴 뒤 다른 계획으로 이어짐 | 복구는 실험의 마지막 계획 판으로 | 복구 시험 |
| 승인 단계가 다시 생김 | 계획에 승인·관리자 확인 경로가 없다(3절 8) | 문서 검토 |

### 8.2 시험 계획(구현 줄이 지킬 것)

- **경계 시험**(`AGENTS.md` "Required change discipline"): 말 고침은 `server.run_turn` 경계에서, 화면 고침은 HTTP 경로에서, 시작은 `session.start` 에서 잰다.
  도움 함수 시험만으로 끝내지 않는다. 바꾸기 전에 실패하는 시험을 먼저 쓴다.
- 공급자(STT·TTS·라우터·공개 자료)는 가짜다(contract-tested). 실제 호출은 각 구현 줄 지시서의 한도 안에서만.
- 저장: 덧붙이기 트리거, 스키마 이전, 계정 지우기 범위, 옛 기록 읽기.
- 노트: 표·이유·뺀 단계 안전 주의·지난번 차이의 고정 예시(골든) 시험.

### 8.3 평가

- **평가 세트**(가칭 `plan_edit_eval.json`, `data/fixtures/evaluation/` 에 둠): 고치는 말(한국어 구어) → 기대하는 고침(또는 되묻기·거절). 줄 HELP 처럼
  개발용·남겨 둔 세트 둘로 나누고, 남겨 둔 세트는 규칙을 만들지 않은 사람이 실제 논문 Methods 를 보고 쓴다. 잘못 들은 말 변형을 자동으로 만든다.
  `server.run_turn` 으로 가짜 공급자를 거쳐 돌린다.
- **목표(구현 줄의 출시 기준, 측정 아님)**: 확인 없이 적용된 구조 고침 **0**, 잘못 바뀐 상태 **0**, 질문·가정에서 고침 **0**, 큰 값 묻기 **100 %**,
  고침 읽기 정확 일치 개발 세트 ≥ 90 %·남겨 둔 세트 ≥ 80 %(못 읽으면 되묻기여야 하고 다른 고침이면 안 됨).
- **누름·말 세기**: 2.3절 목표를 걷기 시험(가짜 서버 + 태블릿 크기 브라우저, CI)이 실제로 센다.
- **손글씨**: 동의받은(또는 합성) 노트 사진 몇 장으로 OCR·카드 수를 잰다. 연구실의 비공개 자료는 쓰지 않는다.
- **파일럿 지표**(숫자·코드·시각만): 실행 전·중 고침 수(종류·화면/말), 올리기에서 시작까지 시간, "지난번 계획에서 시작" 비율, 노트 내려받기 비율.
  파일럿 뒤 인터뷰에서 "기존 실험 기록을 따로 썼나요?"를 묻는다(성공 = 따로 쓰지 않음).

## 11. 이 설계가 하지 않는 것

- 승인·검토자 승인·회수·연구실 변형을 되살리지 않는다. 계획이 연구실 전체의 실행본이 되지 않는다.
- 모델이 계획을 쓰지 않는다: 논문에서 단계를 뽑는 것은 지금의 분석(원문 인용·근거 검사)이고, 고침은 연구자의 것이다. "원문 없이 AI 가 계획 만들기"는 없다.
- 모델이 안전 문장·완료 기준·값을 쓰지 않는다. 공개 자료는 일반 참고일 뿐 안전 판단이 아니다.
- 고친 순서·넣은 단계·바꾼 시약이 과학적으로 맞는지 판단하지 않는다. 판단은 연구자의 몫이고, 화면·말·노트는 원문과 다른 점을 보일 뿐이다.
- 프로토콜 없이 타이머·기록만 하는 모드는 만들지 않는다(2026-10-24 결정 그대로, 파일럿 뒤 결정).
- ELN·LIMS 연결, GLP·GMP 등 규제 준수 주장, 현장 검증 주장은 없다.
