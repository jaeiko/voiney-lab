# 화면 설계 — 사용자가 쓰기 쉬운 새 화면

새 화면(`web/`, 서버의 `/app/`)이 따르는 설계다. 지금 화면(`src/voiney_lab/static/index.html`)은 그대로 두고, 화면을
하나씩 이 설계대로 옮긴 뒤 시험을 통과하면 설정(`VOINEY_LAB_NEW_UI`)으로 바꿔 끼운다. 결정과 날짜는
`docs/DECISIONS.md`, 문구는 `docs/COPY_DECK.md`, 문구 규칙은 `docs/VOICE_AND_TONE.md`, 기능의 동작은
`docs/FEATURES.md` 다. 이 문서는 "어떻게 보이고 무엇을 먼저 보여 주나"만 적는다. 서버 계약(API·`/ws` 사건)은 바꾸지 않는다.

## 1. 사용자와 상황

| 사용자 | 상황 | 화면이 해 줄 일 |
|---|---|---|
| 장갑 낀 연구자 | 태블릿·노트북을 실험대 옆에 두고 1 m 안팎에서 곁눈으로 본다. 손을 쓰지 못한다 | 지금 단계·타이머·듣는 중인지가 멀리서 보인다. 누를 것은 크고 드물다. 말로 되는 일은 화면이 요구하지 않는다 |
| 처음 쓰는 학부생 | 초대 링크로 들어왔다. 서비스가 무엇인지 모른다 | 첫 화면에 이름과 한 줄 소개가 있다. 빈 화면에 첫 행동 하나가 있다. 내부 말이 없다 |
| 바쁜 숙련자 | 같은 프로토콜을 자주 한다. 확인은 최소로 | 홈에서 한 번에 "실험 시작"·"이어서 하기". 확인은 남은 개수와 진행률이 보이고, 끝나면 바로 시작 |
| 연구실 관리자 | 참여자 초대·지표·"확인함" 기록 | 연구자 화면과 같은 틀에서 관리자에게만 보이는 자리(지표·확인함). 개발 정보는 개발 모드에서만 |

## 2. 원칙

1. **한 화면에 가장 중요한 행동 하나.** 그 행동은 큰 단추(또는 큰 카드) 하나이고, 나머지는 작은 보조 행동 2–3개다.
2. **상황에 따라 화면이 달라진다.** 처음 옴 · 확인할 것 있음 · 분석 중 · 진행 중 실험 있음 · 바로 시작 가능. 홈과 목록은 서버가 준 상태만으로 이 상황을 고른다. 글에서 상태를 추측하지 않는다.
3. **실험용 막대는 실험 중에만.** 실험이 없을 때 타이머·단계·일시정지·종료는 어디에도 없다.
4. **개발용 정보는 관리자·개발 모드에서만.** 리비전 id·해시·사유 코드·"개발 상세 정보"는 연구자 화면에서 뺀다(`docs/COPY_DECK.md`).
5. **모든 문장은 "무슨 일인가 + 무엇을 하면 되나".** 단추는 동사(`~기`). 해요체. 오류는 책임을 따지지 않는다.
6. **지금 상태가 한눈에.** 분석은 "분석 중 · N분 지남 (나눠 읽는 중 2/6)"처럼 서버가 아는 것만, 음성은 "듣는 중 / 생각하는 중 / 말하는 중" 셋 중 하나를 크게.
7. **글자 크기·간격 체계.** 정해진 크기 단계만 쓴다(6절). 본문 16 px 이상. 누를 것은 44 px, 장갑은 80 px.
8. **색은 상태에만, 늘 낱말과 함께.** 원문 근거 · AI 일반 지식 · 공개 자료는 색이 아니라 이름표(글자)와 테두리로 구분한다. 색이 있는 것은 정지·위험(danger), 주의(warning), 지금 사람 확인이 필요한 것(pending) 뿐이고 그마저 낱말·아이콘·테두리와 함께 간다(색약·흑백 인쇄). 초록·장식 색·그림자는 없다(6절).
9. **서버가 주지 않은 숫자는 보이지 않는다.** "약 1분"처럼 지어낸 예상 시간은 쓰지 않는다. 지난 시간과 진행 개수가 기본이고, 남은 시간은 **잰 진행에서만** 어림한다(나눠 읽는 조각이 하나 이상 끝났을 때 지금까지의 속도로 "이대로면 약 N분 더 걸려요 (지금까지 속도로 어림)"; 끝난 조각이 없으면 어림도 없다 — 사람 결정 10/25, 줄 RX1).

## 3. 핵심 흐름 5개 (화면 순서)

```text
① 초대 링크 가입 · 첫 로그인
   초대 링크 ─► 가입(이름·비밀번호) ─► 홈(처음 옴: "첫 프로토콜 올리기")
   로그인 화면 ─► 홈
② 프로토콜 올리기 → 분석 기다리기 → 확인할 것 확인
   홈 "첫 프로토콜 올리기" ─► 올리기(파일·링크) ─► 분석 중(지난 시간·진행) ─► 목록 "확인 N개 남음"
   ─► 확인 화면(원문 쪽 그림 + 카드 하나씩 + 진행률) ─► "확인이 끝났어요 · 실험 시작"
①′ 첫 로그인 안내(로그인 직후 한 번)
   마이크 허용 ─► 목소리 맞추기(건너뛰기 가능) ─► 안내 목소리 고르기 ─► 홈
③ 실험 시작 (목소리 맞추기 없음)
   홈 "실험 시작" ─► ① 프로토콜 확인 ─► ② 원문 값 확인 2문항 ─► ③ 안전 주의 읽기 ─► ④ 오늘 바꿀 값 ─► ⑤ 시작(주변 소리 고르기)
④ 실험 중
   지금 단계(크게) · 그림(크게) · 타이머(있을 때만) · 듣는 중/생각하는 중/말하는 중/잘 안 들렸어요 · 질문 카드 · 기록 칸 · 자막 · [일시정지] [종료]
⑤ 실험 노트 보기 · 내려받기
   기록 목록 ─► 한 실험의 노트(단계별 기록·관찰·원문과 다른 점·[미확인]) ─► Word·PDF·Markdown 내려받기
```

줄 RX0 이 만든 화면은 **앱 틀, 로그인·초대 가입, 홈, 프로토콜 목록**, 줄 RX1 이 만든 화면은 **올리기(분석할 쪽 고르기), 분석 기다리기,
확인 화면, 오늘 원문과 다르게 할 값(부품)**, 줄 RX2 가 만든 화면은 **실험 시작 흐름, 실험 중, 설정, 첫 로그인 안내**다(7절). 기록과 노트도 새 화면에서 연다. 아직 옮기지 않은 전체 프로토콜 상세와 일부 기록 작업은 명시적 이전 화면(`/index.html?legacy=1#/…`)으로 연결한다. 화면마다 맨 위에 "왜 이걸 하는지" 한 문장을 둔다(사람 결정 10/25).

## 4. 화면마다

화면마다 **목적 한 문장 · 가장 중요한 행동 · 네 상태(불러오는 중·비어 있음·오류·정상)의 모습과 문장 · 와이어프레임**이다.
문장은 `docs/COPY_DECK.md` 의 새 글과 같다(그 문서가 기준이고, 코드는 `web/src/copy/ko.ts` 한 파일이다).

### 4.0 앱 틀

- **목적**: 어디에 있는지와 누구로 들어왔는지를 한 줄로 보여 주고, 다섯 곳(홈·프로토콜·실험·기록·설정)으로 간다.
- **행동**: 탐색. 머리에는 로고(가로형 확정 로고, 높이 32 px — 6절), 오른쪽에 계정 이름과 [로그아웃]. 실험용 막대는 없다(실험 중 화면만 자기 막대를 가진다).
- **배치**: 넓은 화면(≥ 900 px)은 왼쪽 세로 메뉴, 휴대폰은 아래 탭. 탭 하나의 높이는 64 px 이상.
- **네 상태**: 불러오는 중 — 머리와 메뉴는 바로, 본문만 "불러오는 중…". 오류 — 본문 자리에 오류 문장과 [다시 불러오기]. 비어 있음·정상은 본문의 몫.

```text
┌──────────────────────────────────────────────────────────────┐
│ [⚗ Voiney Lab]                       김재준 · 연구실 A  [로그아웃] │
├────────────┬─────────────────────────────────────────────────┤
│ ● 홈        │                                                 │
│   프로토콜   │   (본문: 그 화면의 큰 행동 하나 + 보조 2–3개)         │
│   실험      │                                                 │
│   기록      │                                                 │
│   설정      │                                                 │
└────────────┴─────────────────────────────────────────────────┘
휴대폰:  머리(로고·이름) / 본문 / 아래 탭(홈·프로토콜·실험·기록·설정)
```

### 4.1 로그인 · 초대 가입

- **목적**: 어떤 서비스인지 알고, 받은 이름과 비밀번호로 들어간다.
- **행동**: [로그인하기] 하나. 초대 링크(`?invite=…`)로 열었으면 [가입하고 시작하기] 하나. 단계 번호("1/6 · 계정")는 없다.
- **네 상태**:
  - 불러오는 중: "확인하는 중…"(로그인 방식을 묻는 동안; 로고(높이 48 px)와 소개는 바로 보인다).
  - 비어 있음(이름·비밀번호 없이 누름): "이름과 비밀번호를 적어 주세요."
  - 오류: 틀린 비밀번호 "이름이나 비밀번호가 맞지 않아요." · 잠금(429, `Retry-After`) "여러 번 틀려 잠시 막혔어요. N분 뒤에 다시 해 주세요." · 연결 끊김 "연결이 안 돼요. 인터넷을 확인한 뒤 다시 해 주세요." · 만료된 초대 "초대 링크가 만료되었거나 이미 쓰였어요. 연구실 담당에게 새 링크를 받아 주세요."
  - 정상: 들어가면 홈.
- 개발 모드(서버의 `mode: "dev"`)에는 이 화면이 없다. 로그인 잠금은 서버 규칙 그대로(이름+기기 쿠키, `docs/FEATURES.md` F1).

```text
┌──────────────────────────────┐
│       [⚗ Voiney Lab]         │
│  장갑을 낀 채 말로 진행하는 실험 안내 │
│                              │
│  이름     [______________]   │
│  비밀번호  [______________]   │
│                              │
│  [       로그인하기        ]  │
│  처음이면 연구실 담당에게 받은     │
│  초대 링크를 열어 주세요.        │
└──────────────────────────────┘
```

### 4.2 홈

- **목적**: 지금 할 일 하나를 고른다.
- **행동**: 상황에 따라 큰 카드 하나.

| 상황(서버 상태로 고름) | 큰 카드 | 보조 행동 |
|---|---|---|
| 내가 하던 실험이 있다(`/api/workspace/experiments` 에 `ready·in_progress·paused·blocked`, 내 것) | **이어서 하기** · {프로토콜} · N단계 | 프로토콜 보기 · 지난 기록 |
| 확인을 기다리는 프로토콜이 있다(`review_pending.needs_review_count`) | **확인하기** · {프로토콜} · 확인할 것 N개 | 프로토콜 보기 · 올리기 |
| 프로토콜이 없다 | **첫 프로토콜 올리기** | 지난 기록 |
| 쓸 수 있는 것이 없고 분석 중인 것만 있다 | **분석 중** · {프로토콜} · N분 지남 (단추 아님) | 올리기 · 지난 기록 |
| 그 밖(바로 쓸 수 있는 것이 있다) | **실험 시작** | 프로토콜 보기 · 올리기 · 지난 기록 |

- **네 상태**: 불러오는 중 "불러오는 중…"(카드 자리) · 비어 있음 = "첫 프로토콜 올리기" 카드 · 오류 "프로토콜 목록을 불러오지 못했어요. [다시 불러오기]" · 정상 = 위 표.
- 실험 목록을 못 읽어도(작업공간 꺼짐 등) 홈은 프로토콜만으로 그린다.

```text
┌─────────────────────────────────────────┐
│ 안녕하세요, 재준 님.                        │
│ ┌─────────────────────────────────────┐ │
│ │ ▶ 실험 시작                          │ │   ← 큰 카드 하나
│ │   바로 쓸 수 있는 프로토콜 3개            │ │
│ └─────────────────────────────────────┘ │
│ [프로토콜 보기]  [올리기]  [지난 기록]        │   ← 보조 행동
└─────────────────────────────────────────┘
```

### 4.3 프로토콜 목록

- **목적**: 프로토콜마다 지금 상태와 다음 행동을 한 줄로 본다.
- **행동**: 줄마다 다음 행동 단추 하나 — 시작하기 / 확인하기 / 다시 시도하기. 위에 [올리기].
- **상태 칩**(글자로): 바로 쓸 수 있어요 · 확인 N개 남음 · 분석 중 · N분 지남(나눠 읽는 중 a/b) · 분석 실패 — 다시 시도 · 사진 글자 읽는 중 · 아직 시작할 수 없어요. "새로 분석하면 더 정확해요"는 서버 문장을 그대로 덧붙인다.
- **차례**: 바로 쓸 수 있는 것 먼저(줄 PRE 결정), 그 다음 올린 순서의 역순.
- **새로 받기**: 분석 중인 것이 있으면 5초, 평소 30초, 화면으로 돌아오면 즉시, 숨기면 멈춤(줄 PRE 와 같은 간격). 분석 중인 줄의 지난 시간·진행은 그 프로토콜의 상세(`GET /api/protocols/{id}` 의 `analysis_run`)에서 읽는다.
- **네 상태**: 불러오는 중 "불러오는 중…" · 비어 있음 "아직 올린 프로토콜이 없어요. [첫 프로토콜 올리기]" · 오류 "프로토콜 목록을 불러오지 못했어요. [다시 불러오기]" · 정상 = 줄 목록. 제목은 서버의 `title` 그대로다(표지 글이 제목이 된 문제는 분석의 몫, 8절).

```text
┌─────────────────────────────────────────────────────────┐
│ 프로토콜                                     [올리기]      │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ In-gel digestion            ● 바로 쓸 수 있어요       │ │
│ │ in-gel-digestion.pdf · 9단계 · 10월 19일 올림          │ │
│ │                                        [시작하기]    │ │
│ ├─────────────────────────────────────────────────────┤ │
│ │ Western blot                ● 확인 2개 남음           │ │
│ │ western.pdf · 10월 22일 올림              [확인하기]   │ │
│ ├─────────────────────────────────────────────────────┤ │
│ │ RNA extraction              ● 분석 중 · 3분 지남      │ │
│ │ rna.docx · 나눠 읽는 중 2/6                           │ │
│ └─────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────┘
```

### 4.4 올리기 (줄 RX1 이 만듦 — `#/upload`)

- **목적**: 파일 하나(PDF·Word·사진) 또는 공개 링크 하나를 올리고, **어느 쪽을 분석할지 같은 화면에서 정한다**(사람 시험 10/25: 쪽 칸이 있는지 몰라 바로 전체를 분석했다).
- **왜 한 문장**: "원문을 올리면 값과 안전 주의를 그 원문에서만 읽어 안내해요."
- **행동**: 큰 놓는 자리 하나 [파일 고르기](놓기도 됨). 아래에 공개 링크 칸과 [링크로 가져오기](로그인한 사람만).
  파일이 올라가면(등록만, 분석은 아직) 같은 화면이 **"어느 쪽을 분석할까요?"** 를 묻는다 — 큰 카드 둘: **[전체 분석]**(추천 · 문서 전체를 읽어요) · **[쪽 고르기]**(작은 그림을 눌러 시작 쪽과 끝 쪽을 골라요). 쪽 고르기는 서버의 쪽 작은 그림(`…/review-draft/source-pages/{n}/image?size=thumb`, 전체 쪽 수는 `…/review-draft/source-pages`)을 격자로 보이고, 첫 탭이 시작 쪽, 둘째 탭이 끝 쪽(같은 쪽을 두 번 누르면 한 쪽), 안내 줄이 "시작 쪽을 눌러 주세요 → 끝 쪽을 눌러 주세요 → 3–5쪽을 분석해요"로 바뀐다. [이 쪽만 분석하기]가 `POST …/analysis?first_page&last_page` 를 보내고 분석 기다리기로 간다.
- **네 상태**: 불러오는 중 "올리는 중… {파일}"(브라우저가 진행률을 주지 않으므로 숫자 없음) · 비어 있음 = 놓는 자리 · 오류 = 서버 코드의 쉬운 문장(`docs/COPY_DECK.md` 1.7; 링크 오류는 서버 문장 그대로) + 고르는 자리 그대로 · 정상 → 쪽 묻기 → 분석 기다리기.
- **바로 넘어가는 경우**: 같은 파일을 다시 올려 이미 분석됐거나 분석 중이면, 또는 사진 글자 읽기(OCR)가 올리기에서 시작돼 서버가 분석을 이어서 시작하면 쪽을 묻지 않고 분석 기다리기로 간다(OCR 문서는 전체를 읽는다 — 쪽 고르기는 다음 "다시 분석"에서; 이 줄의 한계).

### 4.5 분석 기다리기 (줄 RX1 이 만듦 — `#/protocols/<id>/analysis`)

- **목적**: 기다려도 되는지, 얼마나 지났는지, 끝나면 무엇이 되는지 안다.
- **왜 한 문장**: "분석이 끝나야 원문에서 읽은 값으로 안내할 수 있어요."
- **행동**: 없음(기다림). 보조: [목록으로]와 제목의 [이름 바꾸기] (4.11). 끝나면 "분석이 끝났어요 · 바로 쓸 수 있어요 [실험 시작]" 또는 "확인할 것 N개가 있어요 [확인하기]"로 바뀐다.
- **보이는 것**: 지난 시간(mm:ss, 서버의 요청 시각부터 1초마다), 나눠 읽는 진행 "나눠 읽는 중 a/b" 와 조각마다 쪽 범위와 상태("16–30쪽 · 읽는 중"), **남은 시간 어림은 잰 진행에서만**(원칙 9: 끝난 조각 ≥ 1 일 때 "이대로면 약 N분 더 걸려요 (지금까지 속도로 어림)"), "기다리는 동안 다른 화면을 봐도 돼요. 끝나면 목록과 홈에도 나와요." 사진 글자를 읽는 동안은 "사진 글자를 읽는 중이에요. 끝나면 분석이 이어서 시작돼요." 서버 상태는 `GET /api/protocols/{id}` 의 `analysis_run`(5초마다).
- **오류**: "분석하지 못했어요" + 실패 코드의 쉬운 문장(`docs/COPY_DECK.md` 1.7) + [다시 분석하기](문서 전체) · [다른 파일 올리기]. 없는 프로토콜은 "이 프로토콜을 찾지 못했어요."

### 4.6 확인 화면 (줄 RX1 이 만듦 — `#/protocols/<id>/review`; 지금 화면의 "검토 카드"를 대신한다)

- **목적**: 분석이 원문에서 확인하지 못한 값을 **원문 옆에서 하나씩** 정한다. 원문 전체 글 나열은 없다(원문 전체는 [원문 열기]로 쪽 그림을 따로 연다).
- **왜 한 문장**: "분석이 원문에서 확인하지 못한 값만 원문 옆에서 하나씩 정해요."
- **행동**: 카드 하나의 답 단추(서버가 준 선택지만 — 맞아요 / 고른 줄이 맞아요 / 직접 고칠게요 / 원문에 없어요 / 다시 분석 …; 글이나 분이 필요한 단추는 칸을 연다). 아래에 [이전]·(정한 카드면 [다음])·[나중에 하기] (목록으로). 다 마치면 확인한 값을 저장하고(`POST …/review-versions`, 계정 이름으로; 개발 모드는 이름을 한 번 묻는다) **"확인 끝 — 이제 실험할 수 있어요 [실험 시작]"**.
- **배치**: 왼쪽 원문 쪽 그림(`…/review-draft/source-pages/{n}/image`)에 카드가 가리키는 줄의 띠(주의 색 테두리), 사람이 고른 줄은 pending 색 띠. 줄을 골라야 하는 카드는 그림 아래에 번호 붙은 줄 목록(그 쪽의 줄만)을 두고 탭으로 고른다(옆 줄을 이어 누르면 여러 줄). [앞 쪽]·[다음 쪽]. 오른쪽(휴대폰·세로 태블릿은 아래) 카드 하나 + 위에 진행률 "확인할 것 3 / 8" 과 막대.
- **네 상태**: 불러오는 중 "확인할 것을 불러오는 중…" · 비어 있음 "확인할 것이 없어요. 바로 시작할 수 있어요. [실험 시작]"(분석이 아직 없으면 "아직 확인할 분석이 없어요.") · 오류 "확인할 것을 불러오지 못했어요. [다시 불러오기]" · 정상 = 카드.
- **줄 상자 API**(줄 RX0 의 "사람이 정할 것 ④", 10/25 승인): `GET …/review-draft/source-pages/{n}` 의 줄마다 `box`([x0, y0, x1, y1], PDF 포인트, 글 엔진의 블록에서 줄 수로 나눈 자리)와 `image_dpi`(쪽 그림의 해상도 120). 화면은 포인트 × dpi/72 를 그림의 자연 크기로 나눠 띠를 둔다. 상자가 없는 줄(블록이 없는 줄)은 줄 번호 ÷ 줄 수로 어림한 자리에 두고 "어림 위치"라고 쓴다.

```text
┌────────────────────────────┬──────────────────────────────┐
│ 원문 3쪽            [원문 열기] │ 확인할 것 3 / 8   ████████░░░░ │
│ ┌────────────────────────┐ │                              │
│ │ … Incubate for 10 min  │ │ 2단계의 시간                   │
│ │ ▌at 37 °C ▌ (형광)      │ │ 분석이 읽은 값: 10 min          │
│ │ …                      │ │ 원문 조각: "Incubate for 10 min" │
│ └────────────────────────┘ │ [맞아요] [원문에 없어요] [다른 값] │
└────────────────────────────┴──────────────────────────────┘
```

### 4.7 실험 시작 (줄 RX2 가 만듦 — `#/start`, `#/start/<id>`; 지금 시작 시트를 대신한다)

- **목적**: 한 화면에 한 가지씩 확인하고 시작한다(사람 결정 10/25 ①). **목소리 맞추기는 없다**(설정·첫 로그인 안내의 몫).
- **진행 표시와 뒤로 가기**: 맨 위에 ①–⑤ 와 이름(프로토콜 확인 · 원문 값 확인 · 안전 주의 읽기 · 오늘 바꿀 값 · 시작), 지금 단계는 먹색 칸, 지난 단계는 체크. 휴대폰은 번호만 보이고 지금 단계의 이름만 보인다. 화면마다 아래에 [뒤로 가기](①에서는 홈으로).
- **화면마다 맨 위 "왜" 한 문장**(굵은 띠): ① "어떤 원문으로 실험할지 확인해요." ② "원문에 적힌 값을 한 번 확인해요 — 잘못 분석된 값을 막으려고요." ③ "실험 전에 원문의 안전 주의를 읽어요. 읽었다고 기록돼요." ④ "오늘 원문과 다르게 할 값이 있으면 적어요. 없으면 그대로 넘어가요." ⑤ "시작하면 마이크가 켜지고 말로 단계를 안내해요."
- **① 프로토콜 확인**: 주소에 프로토콜이 있으면(`#/start/<id>`, 목록·확인 화면·분석 화면의 [실험 시작] = `startHref`) 그 카드 하나와 [다른 프로토콜 고르기], 없으면 목록(바로 쓸 수 있는 것 먼저; 아직 못 쓰는 것은 눌리지 않고 칩으로 이유). [이 프로토콜로 하기].
- **② 원문 값 확인**: `GET …/start-check` 의 문항을 하나씩 — "2개 중 1번째", 문항 글, 원문 조각(쪽·줄), 서버가 준 선택지 단추. `POST …/start-check/answers` 가 `proceed` 면 다음, 아니면 서버 문장과 후속 선택지(카드를 여는 것은 [프로토콜 화면에서 확인하기] — 지금 화면의 프로토콜 상세로).
- **③ 안전 주의 읽기**: `GET …/review` 의 원문 안전 주의를 카드로(주의 이름표 + 경고 계열 띠 + 한국어 먼저, 원문은 [원문 보기]로 접힘), 시작 전 알림은 따로. [읽었어요] → `POST …/start-check/safety`(②가 받은 `target`).
- **④ 오늘 바꿀 값**: 줄 RX1 의 부품(4.7.1)을 그대로 끼운다. 고른 결과의 `change_set_id` 를 시작이 이름 붙인다(`run_change_set_id`).
- **⑤ 시작**: 프로토콜 이름, 오늘 바꾼 값(없으면 "오늘 바꾼 값 없음"), 안내 목소리, **"주변 소리: [조용해요(기본)] [시끄러워요]"** 고르기 하나와 그 아래 한 줄 "시끄러우면 기록·단계 이동 전에 한 번 더 확인해요." 처음 골라진 값은 설정의 주변 소리 기본값이고, 바꾸면 시작 전에 서버 설정(`ambient_mode`)에 남긴다(설정이 하나뿐이라 다음 기본값도 그것이 된다 — 보고서의 사람이 정할 것). 마지막 단추는 `이 프로토콜로 시작`(이름 고정, `AGENTS.md` 규칙 5). 누르는 순간 소리와 화면 켜 두기를 그 터치 안에서 준비하고(`primeRunStart`), 실험 화면으로 간다.
- **이어서 하기**(홈의 큰 카드, `#/start/<id>?resume=<실험>`): ⑤만 — "하던 실험을 n단계부터 이어서 해요." · 주변 소리 · [이어서 하기]. 시작은 저장된 실험의 판(`experiment_session_version`)을 서버에서 다시 읽어 보낸다.
- **서버가 시작을 거절하면**(`start_check_required`·`safety_acknowledgement_required`·`run_changes_required` 등): 실험 화면이 서버 문장을 그대로 보이고 [실험 시작하기]가 그 단계로 연다(`#/start/<id>?step=n`).
- **네 상태**: 불러오는 중 "원문 값을 불러오는 중…"·"안전 주의를 불러오는 중…" · 비어 있음 "원문에 확인할 숫자가 없어요. 다음으로 가 주세요."(꺼져 있으면 "원문 값 확인은 꺼져 있어요. 다음으로 가 주세요.") · "원문에 적힌 안전 주의가 없어요. 안전 수칙은 연구실 규정을 따라 주세요." · 오류 "원문 값을 불러오지 못했어요."(서버 문장이 있으면 그대로) + [다시 불러오기] · 정상 = 그 단계.

#### 4.7.1 오늘 원문과 다르게 할 값 (부품 — 줄 RX1 이 만듦, `web/src/components/RunChangesStep.tsx`; 줄 RX2 의 시작 흐름이 쓴다. 이 줄에서는 `#/protocols/<id>/changes` 로 혼자 열린다)

- **목적**: 오늘 원문과 다르게 할 값이 있으면 미리 적는다(사람 시험 10/25: 값 칸 30개가 세로로 나열되고 문맥이 없어 "바꿀 값 없이 다음"으로 넘어갔다).
- **왜 한 문장**: "오늘 다르게 할 값을 미리 적어 두면 안내와 타이머가 그 값으로 가요."
- **행동**: 기본은 큰 단추 **[바꿀 값 없음 — 원문대로 할게요]**(빈 선택을 보낸다). 옆에 [바꿀 값이 있어요], 지난 기록이 있으면 [지난번처럼 (n개 · 날짜)].
  [바꿀 값이 있어요] → **단계 목록**(단계마다 "바꿀 수 있는 값 k개" 또는 "바꿀 값 없음", 한국어 문장 한 줄) → 단계를 누르면 **그 단계 문장**(한국어 번역이 있으면 먼저, 원문은 [원문 보기]로 접힘)에 바꿀 수 있는 값마다 형광 표시(원문 문장 위, 서버의 `start`·`end`) → 값을 누르면 **숫자 칸 + 같은 종류의 단위 단추**(서버의 `units_ko` — 초·분·시간 / °C / rpm / ×g / µL·mL·L / nM·µM·mM·M / % …) + 비교 "원문: 15분 → 오늘: 20분" + [이 값으로]. 숫자·단위로 쓸 수 없을 때만 [글로 쓰기] 칸. 고른 값 목록(빼기 가능)과 **[다 골랐어요]**.
- **서버가 정하는 것**: 값마다 단위 종류와 큰 변화(원문의 절반 미만·2배 초과)는 서버가 검사한다. 422 `run_change_large_unconfirmed` 가 오면 화면이 서버의 질문("2단계 시간을 10분에서 30분으로 바꿀까요? 원문 값과 많이 달라요.")을 한 번 더 보이고 [네, 이 값으로 할게요] 가 `confirm_large` 로 같은 선택을 다시 보낸다. 다른 거절은 서버 문장 그대로.
- **서버 필드**(이 줄이 더함): `GET …/start-check/changes` 의 `steps`(단계마다 `text`·`text_ko`·`value_ids`)와 값마다 `start`·`end`.
- **네 상태**: 불러오는 중 "값을 불러오는 중…" · 비어 있음(바꿀 값 없음) "원문에 바꿀 수 있는 값이 없어요. 원문대로 진행해요." · 오류 "값을 불러오지 못했어요. [다시 불러오기]"(서버 문장이 있으면 그대로) · 정상 = 위.

### 4.8 실험 중 (줄 RX2 가 만듦 — `#/experiment`)

- **목적**: 지금 단계·그림·타이머가 멀리서 읽히고, 듣는 중인지가 한눈에 보이며, 기록하는 곳이 스크롤 없이 늘 보인다(사람 시험 10/25의 다섯 지적, 사람 결정 ②).
- **실험이 없으면 실험용 막대는 없다**: 빈 상태 "지금 하는 실험이 없어요." + [실험 시작하기]. 실험이 도는 동안은 화면 전체(앱의 머리·메뉴 없음)를 실험이 쓰고, 홈은 큰 카드 "실험 중 · 돌아가기"로 돌아오게 한다.
- **배치**(가로 태블릿·데스크톱 = 넓은 화면 ≥ 900 px): 위 막대(프로토콜 이름 · 듣기 상태 크게 · 타이머 칩 · 마이크 · [일시정지] · [종료]) / 가운데 왼쪽 **지금 단계**(단계 번호 · 한국어 글 크게 · [원문 보기]로 원문 접힘 · 오늘 바꾼 값 · "다음 단계: …" · 질문 카드 · 타이머 알림) 아래 **그림**(크게, 화면 높이의 44 %까지) / 오른쪽 칸 **실험 기록**(머리 + [메모] [사진], 그 아래 목록) / 맨 아래 **자막**. 좁은 화면(세로 태블릿·휴대폰): 듣기 상태가 맨 위 한 줄 전체, 그 아래 타이머 칩과 단추, 가운데 단계와 그림(이 칸만 스크롤), 그 아래 **접히는 기록 판**(머리 · [메모] [사진] · 펼치기 단추가 늘 보이고, 접힌 동안 가장 최근 기록 한 줄), 맨 아래 자막. 화면 높이는 `100dvh` 로 고정해 기록 칸과 자막이 스크롤 없이 보인다.
- **듣기 상태**: 한 낱말을 크게 — 듣는 중 · 생각하는 중 · 말하는 중 · 연결하는 중 · 다시 연결하는 중 · 문제가 생겼어요 · **일시정지**(먹색 반전) · **잘 안 들렸어요**(서버가 들은 말을 버렸을 때 4초, 경고 계열 + "한 번 더 말해 주세요."). 버림 신호는 줄 HEAR 의 `speech.dropped`(일시정지 중의 버림과 크기로 거른 말은 빼고)와 줄 SP1 의 `speech.ignored`(옆 사람 말로 본 말) — `web/src/voice/runModel.ts` 의 `MISHEARD_EVENTS`. 서버의 `speaker.filter`(이번 실험이 거르는지와 그 까닭: 켜짐 · 맞추지 않음 · 2주 지남 · 마이크 바뀜, 거르기를 낮춤·끔)는 막대 아래 한 줄로 6초 보인다(꺼짐이 기본일 때는 말하지 않는다). [일시정지]를 누르면 서버의 `playback.stop` 으로 나오던 안내 소리가 멈춘다. 실험을 시작하면 `client.audio_ready` 에 마이크의 짧은 id(`mic_id`, `voice-core.js` 의 `micIdFor`)를 보낸다.
- **타이머**: 단계에 타이머가 있을 때만. 끝나기까지 1분보다 많이 남으면 위 막대의 작은 칩(이름 · 남은 시간 · 막대), 1분 전부터는 단계 위의 큰 칸(태블릿 128 px · 휴대폰 96 px 숫자 + "0:45 남음"), 끝나면 경고 계열 "끝남 · 0:20 지남". 시간은 서버의 마감 시각을 서버 시계로 읽는다(`connection.js` 의 시계, `voice-core.js` 의 `serverNowMs`).
- **그림**: 원문 그림(`screen.source_figures`, 없으면 단계의 원문 자산 하나)과 요청해서 AI 가 원문의 말로 그린 그림(`protocol.drawing.result`). 이름표로 출처를 쓴다(원문 그림 / 원문을 바탕으로 AI가 그린 그림 — 점선 테두리). 누르면 화면 전체에 크게, [닫기].
- **자막·대화**: 마지막으로 말한 것 또는 들은 것(들은 말은 따옴표)을 **두 줄까지, 잘리지 않게**. 두 줄을 넘는 말은 자막처럼 문장 단위 쪽으로 나눠 차례로 보이고(쪽마다 2.5–7초, 마지막 쪽이 남음), 한 문장이 혼자 두 줄을 넘을 때만 낱말 사이에서 나눈다. 누르면 오른쪽 **대화 기록 서랍**(이 실험에서 말하고 들은 것 전부, 최근 것 먼저).
- **기록 칸**: 서버의 실험 타임라인(`GET /api/workspace/experiments/{id}/timeline`)에서 관찰(말로 기록 · 메모, 고침·취소 표시)과 첨부(사진) — 최근 것 먼저. [메모] → 글 칸 → `POST …/observations`, [사진] → 카메라·사진 고르기(32 MB 까지) → `POST …/evidence`. 저장하면 "메모를 저장했어요."/"사진을 더했어요.", 실패는 서버 문장 또는 "저장하지 못했어요. 다시 해 주세요." 실험이 저장되지 않는 서버(작업공간 꺼짐)는 "이 실험에는 기록을 더할 수 없어요."
- **일시정지**: [일시정지] → 서버에 `workflow.pause`; 서버 상태가 일시정지면 **화면 전체 띠** "일시정지 중 — '다시 시작'이라고 말하거나 [다시 시작]을 누르세요"와 [다시 시작](`workflow.resume`), 그 옆에 **[종료]**(같은 묻기), 아래 한 줄 "끝내려면 [종료]를 누르세요. 지금까지의 기록은 실험 노트로 저장돼요." 듣기 상태는 "일시정지". 화면이 일시정지를 정하지 않는다 — 서버 상태대로 그린다. 서버가 일시정지·다시 시작을 거절하면 그 문장(`workflow.control.refused` 의 `message_ko`)을 띠 안에 보인다(사람 결정 10/26 ①, 줄 RX4). [다시 시작]이 듣지 않던 까닭: 서버가 다시 시작만 자기 generation 과 비교했는데 그 값은 이어 붙인 말(줄 HEAR)과 끼어든 말로 `session.ready` 때보다 앞서 가서, `session.ready` 값을 보내던 [다시 시작]이 "현재 연결의 설정으로 다시 요청해 주세요"로 거절됐다(사람 음성 시험 10/26). 이제 서버는 다시 시작도 일시정지처럼 **받아들인 설정(configuration_id)만** 본다(사람 결정 10/26 ③). 화면은 그래도 **서버가 이 연결에 보여 준 가장 새 generation** 을 들고 간다(`runModel.ts` `newestGeneration`; 지금 화면 `index.html` `latestServerGeneration`) — 탭으로 고른 되묻기 답(`client.clarify_choice`)은 서버가 여전히 generation 을 비교하므로.
- **지금 단계의 글(사람 결정 10/26 ②·⑤, 줄 KO2 의 필드)**: 한국어(상태의 `primary_summary` — 서버가 제 "N단계: "를 이미 뺀 검사 통과 번역; 화면은 다시 빼지 않는다)가 크고 굵게(`--run-step`, 긴 글은 `--run-step-min`), 원문은 그 아래 [원문 보기]로 접히고 열면 상태 크기(`--run-status`)의 흐린 글. 한국어가 없으면 원문을 다음 단계 크기(`--run-next`)로 — 원문을 큰 글자로 보이지 않는다 — 그리고 **서버가 번역 없음을 알릴 때만**(`translation_missing`) "번역 준비 중". 원문이 한국어인 단계(`source_language: "ko"`)는 원문이 곧 한국어다. 서버가 그 자리에서 번역하는 동안(`screen.translation_pending`) 단계 칸은 `aria-busy`, 번역이 오면 서버가 같은 상태를 다시 보낸다(`action: "translation_update"`). **다음 단계**는 작은 이름 "다음 단계" 아래에 서버의 문장을 그대로 — 한국어는 제 이름표 하나("5단계: …"), 원문이면 `screen.next_step_translation_missing` 일 때 이름이 "다음 단계 · 번역 준비 중". 답 상자와 자막은 답의 `translation_missing` 이 참이고 소리로 말한 글(`speech_text`)이 없을 때만 한 단계 작은 크기. 단계 번호가 없는 원문은 이름표 줄이 "전체 N단계"다. 화면은 글을 읽어 한국어인지 정하지 않는다(`runModel.ts` `stepWords`·`nextStepWords`).
- **[종료]**: 한 번 묻는다("실험을 끝낼까요? 끝내면 지금까지의 기록이 실험 노트로 저장돼요." [계속하기] [끝내기]). 서버는 `session.stop` 뒤에 `experiment.ended` 를 보내지 않으므로(그 사건은 말로 실험을 끝낸 턴에만 온다) 화면은 멈춤을 누른 그 자리에서 끝 화면(4.8.1)으로 간다.

#### 4.8.1 실험 끝 화면 (줄 RX4 가 만듦 — 실험이 끝난 `#/experiment`; 사람의 시안 "실험 끝 · 피드백", 사람 결정 10/26 ③)

- **목적**: 무엇을 했는지 한눈에 보고, 안내가 어땠는지 한 번 누르는 것으로 남긴다. 앱 틀(메뉴) 안의 보통 화면이다.
- **위**: 체크 원 아이콘 + "실험을 마쳤어요"(끝까지 간 실험) / "실험을 멈췄어요"(중간에 끝냄) — `--text-display`(30/38, 700); 아래 흐린 한 줄 "{프로토콜} · {N}단계 중 {k}단계까지(끝까지면 "N단계 모두") · {걸린 시간} 걸림"(걸린 시간은 서버 실험 시계 `timers.experiment` 의 시작·끝 시각으로, 끝 시각이 없으면 화면이 끝난 때까지); 기록 저장 여부가 왔으면 그 문장. 오른쪽 [실험 노트 보기](지금 화면의 그 기록).
- **숫자 세 칸**(bench 면, 모서리 4 px, 숫자 `--text-display`): **말로 남긴 기록**(저장된 실험 타임라인의 `capture_source: voice` 관찰 수; 저장된 실험이 없으면 "—") · **오늘 바꾼 값**(마지막 상태의 `run_changes` 수) · **문제 도움**(`turn.route_decision` 의 `action: problem_help` 턴 수).
- **"오늘 안내는 어땠나요?"**(`--text-heading` 22/30, 700) + "하나만 골라도 돼요. 다음 안내를 고치는 데 써요." 아래 큰 단추 다섯 칸(높이 108, 표정 아이콘(lucide 24 격자·2 px 선, 28 px로 그림) + 낱말: 많이 불편했어요 · 불편했어요 · 보통이에요 · 편했어요 · 아주 편했어요 = 평점 1–5; 고르면 먹색 채움·흰 글자; `radiogroup`). 휴대폰은 다섯 줄(높이 56, 아이콘 왼쪽).
- **칩**("어땠는지 골라 주세요 · 여러 개 골라도 돼요", 높이 44, 모서리 4 px, 고르면 2 px 먹색 테두리 + 체크): 말을 잘 알아들었어요 · 말을 자주 놓쳤어요 · 번역이 어색했어요 · 화면이 보기 편했어요 · 타이머가 편했어요 · 그림이 도움 됐어요 — 코드 `heard_well` · `missed_often` · `translation_awkward` · `screen_easy` · `timer_easy` · `figure_helped`(`pilot_metrics.FEEDBACK_TAGS`).
- **"더 하고 싶은 말 (선택)"** 한 줄(200자). [말로 남기기]는 **만들지 않았다** — 실험이 끝나 음성 세션이 닫힌 뒤 말을 글로 바꾸는 서버 길이 없다(보고서의 사람이 정할 것).
- **아래**: 왼쪽 [건너뛰기](글자 단추, ink-muted), 오른쪽 [보내기](먹색 채움, 220×56; 평점을 고르기 전에는 눌리지 않음). 보내면 "고마워요. 다음 안내를 고치는 데 쓸게요."와 [홈으로 가기]; 건너뛰면 [홈으로 가기]. 둘 다 줄 LOG 의 `POST /api/pilot/feedback` 로 `{report_id, rating, skipped, note, tags}` — `report_id` 는 실험 중 받은 `experiment.report.state` 의 것이고, 그것이 없으면(기록 저장소 없음) 질문 없이 숫자와 [홈으로 가기]만. 답하거나 건너뛴 실험은 이 기기에서 다시 묻지 않는다(지금 화면과 같은 저장소 키). 못 보내면 "보내지 못했어요. 다시 눌러 주세요."와 고른 것 그대로.
- **네 상태**: 불러오는 중(숫자 칸 "—") · 비어 있음(기록 저장소 없음 → 질문 없음) · 오류(보내기 실패 문장) · 정상 = 위.
- **소리·마이크**: 브라우저가 소리를 막으면 "소리를 켜려면 화면을 한 번 눌러 주세요." + [소리 켜기], 마이크가 끊겨 다시 열지 못하면 `voice-core.js` 의 문장 + [마이크 다시 연결하기]. 연결이 끊기면 `connection.js` 의 띠(이 화면에서는 위험 색, 돌아오면 먹색 — 초록·그림자 없음).
- **네 상태**: 불러오는 중 "연결하는 중…" · 비어 있음 "지금 하는 실험이 없어요." · 오류 "연결에 문제가 생겼어요."(서버 문장이 있으면 그대로) · 정상 = 위.
- **코드**: 음성·소켓·타이머 시계·화면 켜 두기·다시 연결은 지금 화면의 검증된 코드를 공용 파일로 옮겨 쓴다(사람 결정 ④) — `src/voiney_lab/static/voice-core.js`(지금 화면이 먼저 읽는 고전 스크립트, 바꾸지 않고 옮긴 함수 66개)와 `connection.js`. 새 화면의 `web/src/voice/engine.ts` 가 두 파일을 그대로 불러 그 파일들이 부르는 이름(`VOICE_CORE_HOST_NAMES` 와 `connection.js` 의 이름)을 정의하고, 사건을 읽어 `runModel.ts` 로 그린다. 서버 계약은 그대로다.

### 4.9 기록·실험 노트 보기 · 내려받기

- **목적**: 지난 실험의 기록을 단계별로 읽고 내려받는다. 목록 `#/records` → 상세 `#/records/<id>` → 노트 `#/records/<id>/notebook/<report>`.
- **왜 한 문장**: 목록 “지난 실험에서 한 일과 남긴 기록을 찾아봐요.”, 상세 “단계마다 남긴 기록과 원문에서 바꾼 값을 함께 확인해요.”, 노트 “기록과 원문으로 만든 노트를 읽고 연구실에 보관할 수 있어요.”
- **목록**: 제목·UTC 날짜·상태·끝낸 단계·저장 평점. 위쪽에 찾기와 프로토콜·상태·날짜·평점 필터. 넓은 화면 세 칸, 휴대폰 두 칸(찾기는 전체 폭). 완료 수·평점을 추정하지 않는다.
- **상세**: 노트 보기를 먼저, 아래 단계별 기록. 고친 말과 처음 말·취소 표식을 함께 보이고 사진은 원본 링크와 작은 미리 보기. 타이머 수치는 단위와 낱말을 붙인다.
- **노트**: 기존 서버 노트의 표를 읽는다. Word 단추를 먼저, 보조 형식은 줄 바꿈한다. 표 본문은 Desk 16/26, 묶음 제목은 22/30, 누르는 크기 48 이상. 긴 부록은 접는다. 미확인 값의 제어는 소유자에게만, 관리자 확인은 별도 묶음이다.
- **행동**: [Word 내려받기] 하나 크게. 보조: PDF · Markdown · JSON · CSV. 미확인 값은 [미확인] 이름표와 [확인하기].
- **네 상태**: 불러오는 중 "기록을 불러오는 중…" · 비어 있음 "아직 기록이 없어요. 실험을 하면 여기에 남아요." · 오류 "기록을 불러오지 못했어요. [다시 불러오기]" · 정상 = 노트.

### 4.10 설정 (줄 RX2 가 만듦 — `#/settings`)

- 쉬운 말(`docs/COPY_DECK.md` 3절·6절), **실행할 프로토콜 고르기는 없다**(시작 흐름의 몫). 묶음 차례:
  1. **목소리 맞추기**(여기와 첫 로그인 안내에만; 실험 중에는 묻지 않는다) — [지금 맞추기] → "오늘 실험도 차근차근 안전하게 시작해 볼게요."를 읽는 5초를 실험과 같은 마이크·처리로 녹음해(`voice-core.js` 의 `recordCalibrationPcm` — 줄 HEAR 의 것을 옮김) `POST /api/voice/calibration` 에 마이크의 짧은 id 와 함께 보낸다. 서버가 말소리 부분의 크기만 재고 크기·잰 때·마이크 id 를 실험자 설정 `voice_reference` 로 남긴다(소리는 버린다; 줄 HEAR 결정 1, `docs/FEATURES.md` F8). "목소리를 맞췄어요. 이제 옆 사람 말 거르기를 켤 수 있어요." / 서버의 `too_little_voice` 는 "목소리가 잘 안 들렸어요. 다시 맞춰 주세요."
  2. **안내 목소리** — 고르면 바로 서버에 저장하고 "저장했어요"와 그 목소리로 미리 듣기. [들어 보기]는 한 번에 하나.
  3. **숫자를 말했을 때** — 다시 읽어 주기(추천) · 먼저 물어보기 · 조용히 기록하기(`confirm_mode`).
  4. **옆 사람 말 거르기** — [끄기] [켜기], 실험자 설정 `speaker_filter`(기본 꺼짐). 맞춘 값(`voice_reference`)이 없으면 [켜기]가 눌리지 않고 "목소리를 맞춘 뒤에 켤 수 있어요." 맞춘 뒤에는 "{날}에 맞췄어요. 마이크를 바꾸면 그 마이크로 다시 맞춰 주세요.", 14일이 지나면 "맞춘 지 2주가 지났어요. 다시 맞춰 주세요 — 그동안은 모든 말을 들어요." 마이크가 바뀐 것은 실험을 시작할 때 서버의 `speaker.filter` 로 실험 화면에 알린다.
  5. **주변 소리 기본값** — 조용해요 · 시끄러워요(`ambient_mode`)와 "시끄러우면 기록·단계 이동 전에 한 번 더 확인해요."
  6. **계정** — 이름 · 연구실, [비밀번호 바꾸기](지금·새 비밀번호), [로그아웃하기](한 번 묻는다), [계정 지우기](되돌릴 수 없다는 말과 비밀번호를 한 번 더). 개발 모드는 "개발 모드에는 계정이 없어요."
- 고른 값은 서버가 받으면 그 묶음 아래 "저장했어요", 못 받으면 "저장하지 못했어요. 다시 골라 주세요."

## 6. 디자인 토큰 (`web/src/styles/tokens.css`)

사람의 "Voiney Lab 디자인 체계"(10/25)를 따른다. 흰 종이 위 먹색 글자가 기본이고 **색은 상태에만** 쓴다 — 장식·브랜드 색 없음, 초록 없음(완료는 먹색 체크와 흐림), 그림자 없음. 색이 있는 면(soft)은 혼자 쓰지 않고 같은 계열의 테두리·아이콘·낱말과 함께 쓴다. `tests/test_lane_rx0_new_ui.py` 가 이 규칙(팔레트 밖의 색·초록·그림자·4 px 넘는 모서리·400/600/700 밖의 굵기)을 스타일 파일에서 검사한다.

| 토큰 | 값 | 쓰는 곳 | 대비(흰 바탕) |
|---|---|---|---|
| `--ink` / `--paper` | `#1c1c1a` / `#ffffff` | 글자 / 바탕 | 16.4:1 |
| `--ink-muted` | `#55554f` | 보조 글자, 흐린 상태(분석 중, 개발용 예시) | 7.0:1 |
| `--on-ink` | `#ffffff` | 먹색 단추의 글자 | 16.4:1(먹색 위) |
| `--bench` / `--line` / `--line-strong` | `#efefec` / `#d4d4cf` / `#76766f` | 바탕 2 / 선 / 테두리 | — |
| `--danger` / `--danger-soft` | `#bf2229` / `#fbeaea` | **정지·위험에만**(실험 중 화면의 멈추기, 위험 주의 — 다음 줄). 일반 오류·거절에는 쓰지 않는다; 이 줄의 화면에는 쓰이는 곳이 없다 | 5.9:1 |

이 줄의 상태 칩(4.3)은 낱말이 기본이고 상태마다 아이콘이 붙는다: 바로 쓸 수 있어요 = 먹색 체크 + 먹색 1 px 테두리 · 확인 N개 남음 = pending 2 px 테두리·아이콘·글자·soft 면 · 분석 중 = 흐린 글자 + 모래시계 · 분석 실패 — 다시 시도 = 먹색 2 px 테두리 + 알림 아이콘(위험이 아니므로 danger 가 아니다) · 그 밖(개발용 예시, 서버 문장) = 흐린 글자, 아이콘 없음. 오류 상자와 로그인의 오류 문장도 먹색 2 px 테두리 + 알림 아이콘이다.
근거의 종류(원문 · AI 일반 지식 · 공개 자료)는 색이 아니라 **이름표와 테두리**로 구분한다(2절 원칙 8; 다음 줄의 확인·실험 중 화면).

**글자** — Pretendard(OFL 1.1, npm `pretendard` 1.3.9)를 빌드에 넣어 **서버가 직접 제공**한다(바깥 CDN 금지). 굵기는 400·600·700 만. 실험 전후 화면(Desk)의 단계:

| 토큰 | 크기 / 줄 / 굵기 | 쓰는 곳 |
|---|---|---|
| `--text-display` | 30 / 38 / 700 | 끝 화면의 제목과 숫자 세 칸, 홈 인사(줄 RX4, 사람 결정 10/26 ④) |
| `--text-title` | 24 / 32 / 700 | 화면 제목, 큰 카드 제목 |

| 토큰 | 휴대폰·데스크톱(디자인 체계 Run) | 태블릿(줄 TAB 1.5 m 실측; 터치 · 721×600 이상) |

사람이 정한 값은 단계 글·최소·타이머·장갑(태블릿)과 Run 척도(휴대폰)이고, 태블릿의 다음 단계·자막·상태·듣기 상태 크기와 양쪽의 듣기 상태 크기는 이 줄이 같은 비율로 맞춘 값이다(보고서). 굵기는 디자인 체계대로 400·600·700 만 쓴다 — Run 척도의 자막 500 은 400 으로 둔다. 데스크톱은 휴대폰과 같은 Run 척도다.

**간격** `--space-1…12` = 4·8·12·16·24·32·48 px.
**모서리** 최대 4 px: `--radius` 4 px(카드·단추·대화·상자), `--radius-small` 2 px(칩·입력). 알약 모양 없음.
**테두리** 1 px(`--border`), 상태 2 px(`--border-state`: pending 칩·카드, 실패 칩, 오류 상자·문장, 메뉴의 현재 표시), 초점 3 px(`--border-focus`, 먹색, 바깥쪽 2 px 띄움). 그림자 없음(메뉴의 현재 표시는 2 px 테두리).
**누르는 크기** Desk 40 px 이상 — 이 화면은 `--target` 48 px(단추·탭·입력; 줄 RX4 전 44 px), 휴대폰 아래 탭 64 px, 넓은 로그인 단추와 시작 흐름의 큰 단추 56 px, 끝 화면의 [보내기] 220×56.
**아이콘** lucide(24 px 격자, 2 px 선, 둥근 끝), 늘 낱말과 함께, 이모지 없음. 단추·메뉴·큰 카드·오류 문장 24 px, 칩 안 16 px(격자대로 줄여 그림). 홈의 보조 행동, 목록의 다음 행동 단추, 시작 흐름의 큰 단추에도 아이콘이 붙는다(줄 RX4, 사람 결정 10/26 ④ "아이콘과 낱말 함께").

## 8. 서버 쪽에 남는 것

- 제목이 표지 글("표지 최종 하리")로 나오는 것: 분석이 `title` 을 정하는 것은 그대로다. 화면이 이상한 제목을 파일 이름으로 바꿔 보이고 사람이 이름을 바꿀 수 있다(4.11, 줄 RX1). 분석이 제목을 더 잘 읽게 하는 것은 분석의 몫으로 남는다.
- 예상 시간: 서버는 주지 않는다. 화면은 잰 진행에서만 어림한다(원칙 9).
- 확인 화면의 줄 상자: 줄 RX1 이 더했다(4.6). 블록이 없는 줄(합쳐진 줄, 빈 줄)은 어림 위치다.
- 사진 글자 읽기(OCR)가 올리기에서 시작되는 문서는 쪽 고르기 없이 전체를 분석한다(4.4).
- 목소리 맞추기를 실험 밖에서 하고 실험에서 쓰는 서버 기능은 줄 HEAR 가 더했다(`POST /api/voice/calibration`, `speaker_filter`, `voice_reference`, `speaker.filter`; `docs/FEATURES.md` F8). 새 화면은 그대로 잇는다(4.10).
- 주변 소리는 서버 설정이 하나(`ambient_mode`)라 시작에서 고른 값이 다음 기본값도 된다(4.7).
- 서버가 보내는 문구(오류·카드 질문·음성 문장)는 `docs/COPY_DECK.md` 4절의 "바꿀 목록"으로만 남긴다.
