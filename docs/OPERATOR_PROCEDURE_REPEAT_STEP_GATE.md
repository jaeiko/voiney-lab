# 반복 단계 게이트 · 사용자 절차 1장

이 문서는 **서버 기동 → 검토자 해결 → 연구자 선택 → 음성 진행 → 7단계 게이트
→ 관찰 발화 → 전진**까지를 한 장으로 정리한다. 발화와 화면 문구는 코드에서
측정한 실제 문자열이며, 추정한 문구는 넣지 않았다.

> **먼저 알아야 하는 전제 (2026-09-07 기준).**
> in-gel 문서는 지금 **연구자 화면에서 선택할 수 없다.** readiness 이유 5개 중
> 3개가 `unsupported_repeat_until` 이고, 이 이유는 어떤 검토자 조작으로도
> 해제되지 않는다(`ProtocolCatalog._BLOCKER_RESOLUTION` 에 없다). 4·5단계
> (음성 진행 이후)는 그래서 **게이트 뒤쪽 동작을 진단하는 경로**로만 실행할 수
> 있다 — `tests/development_activation.py` 가 그 우회를 공개적으로 한다.
> `REPEAT_UNTIL` 을 지원 기능으로 선언하면 이 3개가 사라지고 남는 2개는 모두
> 검토자가 해결할 수 있어 in-gel 이 선택 가능해진다. 그 선언은 기존 테스트 5개의
> 전제를 무효화하므로 사용자 결정을 기다린다 — `docs/FINISH_LINE_A_CLOSEOUT_REPORT.md`
> 의 "작업 3" 항목을 볼 것.

## 1. 서버 기동

```bash
source .venv/bin/activate
uvicorn voice_workflow_agent.server:app --host 127.0.0.1 --port 8000
```

**이때 보여야 하는 것** — 브라우저에서 `http://127.0.0.1:8000` 을 열면 상단에
`프로토콜을 확인하고, 손을 쓰지 않고 진행하세요.`, 실험 컨텍스트 칩에
`프로토콜 선택 필요` / `승인된 프로토콜 선택` 이 보인다.

## 2. 검토자 해결 (검토자 화면)

1. 검토 화면(`프로토콜 검토`)에서 `검토 목록 새로고침` → `검토 필요` 목록에서
   대상 프로토콜을 누른다.
2. `아직 해결되지 않은 위험` 블록에 이유가 코드와 함께 줄단위로 나온다. in-gel은
   다섯 줄이다.
   - `no_declared_safety_warnings` → 버튼 **`안전 경고 확인 처리`**
   - `unresolved_ambiguity` (20단계) → 정본 판단 select 에서
     **`이 판단이 사유를 해제합니다`** 라고 표시된 항목을 고르고, 근거가 된 원문
     세그먼트 체크박스를 최소 1개 선택한 뒤 버튼 **`이 모호성을 해소`**.
     근거 없이 누르면 서버가 거절한다.
   - `unsupported_repeat_until` (7·9·20단계) → **버튼이 나타나지 않는다.**
     검토자가 해결할 항목이 아니다. 위 전제 참조.
3. 데모/연구용으로만: 검토 패널의 **`데모·연구용 초안 활성화`** 버튼
   (`POST /api/protocols/{id}/activate-development`). 성공 시
   `개발용 초안 활성화 완료 · 최종 승인 리비전은 아닙니다.` 가 표시된다.
   이 버튼은 readiness 를 해제하지 않는다.

**이때 보여야 하는 것** — 해결한 이유 줄 끝에 `· 확인됨` 이 붙고,
`처리된 요청` 아래로 기록이 남는다. 남은 이유가 0이 아니면 3단계에서 선택되지
않는다.

## 3. 연구자 선택

`실행할 프로토콜` 드롭다운(`#protocol-id`)에서 대상을 고른다.

**이때 보여야 하는 것** — 실험 컨텍스트에 프로토콜 이름과 정확한 리비전이 뜨고,
세션 칩(`#session-configuration-status`)이 서버 확인을 마친 상태로 바뀐다.
readiness 가 남아 있으면 목록에 아예 나타나지 않는다(빈 목록이 정상 동작이다).

## 4. 음성 진행

| 사용자 발화 | 에이전트 |
| --- | --- |
| “프로토콜을 시작해 줘.” | 1단계를 읽어 준다 |
| “현재 단계를 알려 줘.” | 현재 단계 재안내 (상태 불변) |
| “다시 말해 줘.” | 마지막 안내 1회 반복 |
| “다음 단계로 넘어가 줘.” | 완료 확인을 되묻는다 (그 자체로는 이동 없음) |

## 5. 7단계에서 게이트를 만난다

7단계에 도달해 완료를 말하면 에이전트는 **원문을 인용해** 되묻는다.

- 사용자: “현재 단계를 완료했어요”
- 에이전트:
  > 원문은 이 단계의 종점을 이렇게 적고 있습니다: “7 Repeat steps 2-7 until the
  > gel band is fully destained” 그 관찰 결과를 말씀해 주셔야 완료를 기록할 수
  > 있어요.
- 화면 상태: `clarify_completion`, `current_step_label` 은 그대로 `7`,
  `revision` 증가 없음.

게이트가 서는 자리는 라벨이 아니라 **문서가 반복을 진술한 자리**다. 분석이
반복 construct 를 붙인 단계에만 선다(in-gel 3곳, headspace 5곳,
intracellular·ANKOM 0곳).

## 6. 관찰을 말하고 전진한다

**종점에 도달했을 때**

- 사용자: “젤이 완전히 탈색되어 투명해요” (또는 되묻기에 “네”)
- 에이전트: “8단계로 이동했습니다. 안내를 화면에 표시했습니다. 타이머를
  시작하려면 말씀해주세요.”
- 기록되는 것: 프로토콜 id, 리비전 id, step id/라벨, **발화 원문**, UTC 시각,
  선언자(principal id·역할), predicate `positive`. **반복 횟수는 기록하지
  않는다** — 원문에 횟수가 없다.
- 실험 세션 기록이 열려 있으면 같은 턴에 append-only `experiment_observations`
  행으로도 남는다. 그 쓰기가 실패하거나 기록이 열려 있지 않으면 턴이 차단되고
  단계 이동이 되돌려진다.

**아직 도달하지 않았을 때**

- 사용자: “아직 색이 남아 있어요” (또는 “아니요”)
- 에이전트:
  > 말씀한 결과는 7단계의 원문 관찰 기준이 아직 충족되지 않았다는 뜻입니다.
  > 현재 단계를 유지하며 다음 단계로 이동하지 않습니다. 원문이 지시한
  > 2–7단계 반복 주기를 계속한 뒤 관찰 결과를 다시 말씀해 주세요.
- 단계는 그대로. 반복 범위(`2–7`)는 문서에서 읽은 값이다.

## 실패하면 확인할 3가지

1. **드롭다운에 프로토콜이 없다** → readiness 이유가 남아 있다.
   `GET /api/protocols/{id}/review` 의 `readiness` 블록을 보고, 이유마다
   검토자 조작이 있는지 확인한다. `unsupported_repeat_until` 이면 검토자
   조작은 없다 — 위 전제의 사유다.
2. **7단계에서 “네”라고 했는데 이동하지 않는다** → 되묻기는 **직전 턴 1회만**
   유효하다(turn_id, generation, configuration_id, workflow revision 이 모두
   일치해야 한다). 중간에 다른 발화가 끼면 무효가 되고 다시 완료를 말해야 한다.
   그리고 실험 세션 기록이 열려 있지 않으면
   `실험 세션 기록이 활성화되지 않아 관찰 내용을 저장하지 못했습니다.` 가 나오고
   이동이 되돌려진다.
3. **에이전트가 원문 대신 일반 문장으로 되묻는다**
   (`이 단계는 관찰 결과가 충족될 때까지 반복하는 단계입니다`) → 그 단계에 붙은
   반복 construct 를 찾지 못했다는 뜻이다. 분석이 반복을 포착하지 못한
   경우이며, `source_states_an_uncaptured_repetition` 이 함께 떠 있는지
   확인한다. 문구를 지어내지 않고 일반 문장으로 내려가는 것이 정상 동작이다.
